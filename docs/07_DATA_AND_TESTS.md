# 07 データ契約・検証・テスト

## 必要な安定ID
`chapterId`、`dateId`、`storyId`、`rewardSourceId`、`memoryId`、`quizId`、`factId`、`choiceEffectId` は文字列で永続的に一意。画面に出す日本語名は後から変えられるがIDは変えない。

## シナリオ編集
- Inkは文章と選択肢を担当。`# speaker: heroine`、`# speaker: narrator`、`# background: milano_cafe`、`# effect: memory_milano_promise` のようなタグを採用する。
- `effect:` タグは許可済みイベントの識別子。任意の式やJavaScriptを埋め込まない。
- `#` タグの取り扱いはInk公式の`currentTags`/choice tags仕様に従い、本文の行に一度だけ適用する。
- 選択が決まった直後に状態を保存。再開時にinkjsのstate JSONを復元し、選択前か選択後かの境界を失わない。
- 同一effectの再適用を避けるため、適用済みイベントIDとシナリオ実行位置を正しく扱う。全memoryイベントを世界で一度しか起こせない仕様とは混同しない。
- プレイヤー名等はInk変数で表示し、HTMLとして解釈しない。
- 開発中はシナリオ改稿後の旧版途中セーブの再開を必須としない。異なる脚本を無理に復元せず、読み込めないデータを保護して利用者が明示的に消去できるようにする。

## APの操作契約
- 報酬は `earnRewards`（`src/domain/rewards.ts`）で報酬IDごとに一度だけ付与する。付与済みのIDは同じIDの連打/再表示でも重複加算しない。
- `startDate(state, dateId)`: 定義存在・章解放・関係段階・AP残高・未完了状態を検証し、成功時のみ費用を1回減算、アクティブデートを登録。
- 選択前に保存済みチケットと直前の関係から確率・変化量を確定し、その結果をInkへ渡す。結果と効果・`finishDate` の履歴・告白結果はそれぞれ一度だけ適用する。同一バージョン内の途中デートは保存時の方式で継続する。親しさ・信頼・恋愛の意識には正・ゼロ・負の効果があり、途中で失敗しても重複適用しない。
- 未完了状態のまま再開するなら`startDate`を再度呼ばない。開始をリトライしても重複減算しない。
- APは0以上、設定の上限以下で常に整合。

## 受け入れテストの最低限
1. 空のセーブで開始し、デフォルト名/変更名の両方が表示できる。
2. 初回章クリアでAP4（仮）。同じ章の再クリア・画面再表示・再起動でもAPが増えない。
3. デート開始でAPを1回だけ消費。AP不足/未解放なら消費しない。
4. デート1本で3択×2回が完走し、各反応・思い出の記録が異なる。
5. ページリロード後も選択途中から再開でき、APと好感度の二重加算・二重減算なし。
6. 完了済み通常デートは再開始できずAPも減らない。同一バージョン内で進行中のイベントは保存・再開でき、効果を二重に適用しない。
7. `content/stories/*.ink` を改稿して再ビルドすると、コードを変更せず台詞が変わる。
8. 存在しないstoryId、重複dateId、未定義effect、壊れたInk、形式違反JSONで検証に失敗する。

9. 狭い画面で文字が切れない。長文の名前を入力してもレイアウトが大きく壊れない。
10. セーブデータ破損時は明確に案内し、利用者の他データを勝手に消さない。
11. ビルド/型チェック/テストの実行手順をREADMEに記載し、変更内容と影響範囲に応じて必要な確認を選ぶ。公開前や大きな変更では[開発時の確認](10_DEVELOPMENT_CHECKS.md)の全体確認を行う。

恋愛に影響する変更では、保存済みチケットとプロフィールの再現性、各軸の確率補正・上下限・変化幅、正負両経路の会話、二重操作・別タブ競合、無作為化しない告白、APが尽きたときの再交流を必要に応じて検証する。

通常デートを順不同で選べること、特定デートIDなしのStage進行、3軸の負値と保存、告白の成立・保留・拒否、拒否後の再挑戦制限、交際後の未体験デート、現在のバージョン内での保存・途中再開を必要な範囲で検証する。旅行・都市の進行に告白を要求しない。開発中は旧開発版セーブの更新後の再開や自動移行を保証せず、新機能ごとに旧互換テストを追加することは必須としない。

旅行の変更では、地点・イベント・片道経路の参照と出典、徒歩時間順の候補、帰路・宿泊・待機、時間と予算の境界、APと交通費の二重消費防止、ロード・別タブ競合を検証する。4観光と2特殊戦の順序を入れ替えた都市フィナーレまでの進行も確認する。実際の営業時間とゲーム内時間枠、実運賃と推計・調整値の区別は [ミラノの旅行データ](../content/travel/README.md) を参照する。

## 英語学習データと保存の方針
- 翻訳・学習補足は問題本文から分離し、安定したquestionIdと原文・選択肢・正解の版を照合する。問題を改稿した際は対応する翻訳・補足の再確認を検出する。
- 翻訳と復習は任意で、回答・戦績・報酬・恋愛進行を変更しない。未回答の解説を先に見せず、記録されていない個別回答を推測しない。
- バトルの途中保存は内容指紋を検証し、異なる問題を再開しない。学習設定・記録を別保存にする場合も破損・未知バージョン・古いタブを安全に扱う。
