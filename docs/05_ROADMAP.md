# 05 Codex実装フェーズと受け入れ条件

## 優先方針
恋愛を「クイズのおまけ」にしない。**恋愛縦切り体験を先に完了**し、単独で面白いか評価する。その後、文章の質が高いレイトン型バトル、観光・観察、システム統合、特殊戦、都市量産の順。

| Phase | 対象 | 完了条件 |
|---|---|---|
| 0 | リポジトリ調査・技術土台・Ink/JSONデータ設計 | シナリオのビルドと最低限のゲーム画面が動き、コード/データの責務が分かれている |
| 1 | **APと章末恋愛モード** | 開発用章クリア→AP獲得→デート選択→3択を2回→結果→保存・再開できる |
| 2 | 4段階好感度・思い出・特別デート・告白 | クイズ無しで恋愛ゲーム単独の開始〜告白成功を試遊可能 |
| 3 | A型バトル（面白い日本語敵台詞+英語3択） | 『最後の晩餐』の3問バトル1本が文章と演出込みで面白い |
| 4 | 観光・観察 | ヒロイン案内・画像タップ・発見帳ができ、バトルと結びつく |
| 5 | 全ループ統合 | 都市→観光→バトル→章クリア→AP→デート→次章が一気通貫 |
| 6 | B/C特殊戦 | 証拠確認UIあり、矛盾追及と証拠連結が稀な変化球として成立 |
| 7 | ミラノ編完成 | 4観光地・個性的な敵・都市ボス・複数デート・アルバムと演出 |
| 8 | AI量産・検証パイプライン | 史実・英文・選択肢・文章を検証しながらデータ追加可能 |
| 9 | 世界規模へ | 複数都市、単語復習、隠し観光地などを追加 |

## 初回のCodexタスクの正確な範囲
**Phase0+Phase1のみ**。以下を順番に実装する。

1. 既存README/コード/パッケージを調査。既存の構造があれば継承。
2. Vite+React+TS（既存構造がなければ）を構築し、スマホで動く起動UIを設置。
3. Inkのコンパイル・読み込みを実装し、`.ink`の台詞・タグ・3択をReactで表示。
4. `content/romance/date_catalog.json`を読んでデートメニューを表示。ミラノのカフェ1件の本物のシナリオを動かす。未実装のデートは未実装と明示し、空ボタンを設置しない。
5. 開発用の「ミラノ章初回クリア」操作で4AP（仮）を一度だけ付与。再クリック/リロードで二重付与しない。
6. カフェデート費用2AP（仮）を1回消費し、3択×2回の日本語会話を進める。
7. 好感度を非表示の形で変更し、イベント記憶とデート履歴を保存。関係段階の発展演出はPhase2に残してもよい。
8. 戻る/中断/再開で二重消費せず、進行と選択を保存・復元。ローカルセーブにschemaVersionを付ける。
9. JSON構文/Inkコンパイル/データ参照/型チェック/最低限の単体テストを行う。
10. READMEに起動・テスト・シナリオ編集の手順を追記し、試遊まで確認する。

## 明示的に初回では作らないもの
実際の観光・クイズ・英語難易度・特殊戦・全世界地図・複数都市・複雑な親密度計算・告白エンディング・AI自動生成・アカウント・クラウド保存・3Dモデル。

## Phase1を試遊する最小ケース
- まっさらなセーブ→章初回クリア→AP4→カフェ費用2→2回の選択→AP2→イベント履歴の保存。
- 初回クリアを連打してもAPは増えない。
- デートを中断して復帰してもAP2を二度減算しない。
- ページ更新しても主人公/ヒロインの名前、AP、選択分岐状態が残る。
- 選択肢・会話・背景名を`.ink`で変更した場合、TypeScriptのUIを編集せず内容に反映できる。
- iPhone幅で文字が切れずタップ操作ができる。

## 次のCodex指示を出す条件
Phase1の操作性と**デートの文章そのものの面白さ**を人間が試遊。合格したらPhase2に進む。機能が揃っただけで量産へ移らない。
