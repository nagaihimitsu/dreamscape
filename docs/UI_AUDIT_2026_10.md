# UI監査記録

添付された `UI_RULES.md` とリポジトリ内の同名ファイルが一致することを確認し、320〜390px幅を中心に画面と実際の操作を点検した。数値は代表的な状態の確認結果であり、すべての文字量・端末でスクロールが不要であることを意味しない。

| 確認した流れ | 発見した問題と対応 |
| --- | --- |
| 自由時間・デート | 大きなカードと重複するボタンで一覧が長くなっていた。名称・AP・操作を行にまとめ、選べない理由は残した。旧セーブ向け補助APも整理した。 |
| 再訪 | 観光地とバトルごとに大きなカードが続いていた。種類ごとの一覧に変更し、対象・戦績・操作を残した。 |
| エピソード開始 | 開始ボタンが360×640の画面外だった。ボタンを説明の前に移し、画像と余白を調整した。 |
| 観察・資料 | 発見一覧が縦に長く、非表示部分にキーボードフォーカスが移り得た。余白を調整し、覆われた操作へのフォーカスを防いだ。 |
| 会話ログ・設定 | 会話ログの白文字が明るい背景と重なっていた。色を修正し、設定のチェック項目を独立した行にした。 |
| 通常戦・特殊戦 | 長めの英語問題で3択が切れ、B/C戦の主操作も画面外になっていた。操作の重複と余白を整理し、訳・回答・証拠選択を維持した。 |
| 英語ノート | 回答済み問題が大きなボタンで縦に並んでいた。問題を一覧または前後操作で選び、復習登録を問題文の近くに配置した。 |

確認には Playwright の Chromium と実際のセーブ状態を使用し、一覧の全項目、利用不可の理由、進行後の解放、AP、特殊戦、設定、会話ログ、キーボード操作と保存復元を対象にした。Linux上の WebKit（390×844）でも、自由時間の確認・設定・観察資料の保存と再読込を確認した。継続的な回帰確認は `tests/e2e/ui-audit-regression.spec.ts` と既存E2Eで行う。

長文・対訳を広げた場合や英語ノートの全文を読む場合は内容領域のスクロールが必要。横向きの観察画面は従来のスクロール構成で、実機Safariやスクリーンリーダーによる検証は今回行っていない。
