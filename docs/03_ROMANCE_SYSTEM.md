# 03 恋愛システム仕様

## 目的

恋愛は観光の報酬ではなく、相手の言葉や反応を読んで二人の時間を選ぶゲーム。旅行を進めると複数の行き先が自由時間に現れ、プレイヤーはAPを使って好きなデートを選ぶ。通常デートの間に特定のデートIDによる一本道を作らない。通常デートは順不同で、最初に選んでも成立する。

デート中の選択と積み重ねで関係が変わり、誘いや任意の告白につながる。交際成立は恋愛上の大きな到達点だが、告白も交際も旅の進行には必須でない。告白せず友達に近い関係のまま旅を続けることもできる。交際後の長編や結婚・家族編は扱わない。

## 自由時間とAP

- 旅行エピソードの進行や最低限の関係条件に応じ、観光地・街角などの行き先を増やす。同じ場所を将来メイン観光の後にデートで再訪することもできる。
- APは限られた時間をどこに使うかを選ぶ資源であり、全デートを体験することは必須ではない。好感度を直接購入する通貨ではない。
- 上限は12。未使用・保留中のAPと報酬IDを維持し、再訪・再読込・連打で二重に増減しない。AP不足では開始・消費しない。
- 通常デートは原則3択を2回、一度完了した通常デートは再開始しない。未体験のデートは交際後も選べる。
- りえ自身からの誘いと期間限定の小さな出来事は、既存の特別イベントとして通常の行き先と区別する。参加は任意で、Stageや告白の必須イベントにはしない。

## 関係状態

内部には親しさ `affection`、本音を話せる安心や尊重を表す `trust`、恋愛を意識する気持ちを表す `spark` を持つ。これらの値や告白の確率は表示しない。選択肢の効果は正・ゼロ・負を取れ、複数の軸に異なる影響を与えられる。結果は会話や態度の変化として示す。

`romanceStage` は親しさの雰囲気や呼称を示す4段階であり、特定のデートIDでは決めない。一度親しくなった事実は原則戻さず、信頼などの現在の値は下がることがある。Stage、告白条件、選択の効果はデータで管理し、特定の言い方が常に最良にならないよう脚本と一緒に検討する。

名前は自由に変更できる。Inkには名前・呼称と、必要に応じ関係段階や交際状態を渡す。既存のセーブにある `affection`、`playedDateIds`、`memories`、Stageや進行中の会話は保護する。

## 選択肢と思い出

- 3択はその場の会話と相手の考えに根ざしたものにし、冗談・共感・率直な好意を毎回同じ序列で並べない。選択の結果は会話から推測でき、失敗時の返答にも人物らしさを持たせる。
- 同程度に距離の近い言葉でも、関係段階や交際状態によって異なる反応にできる。甘い言葉を常に最高評価としない。
- 思い出は二人が経験したことの記録で、後の会話や告白で参照する。通常デートやStageの進行鍵として特定の思い出を要求しない。未経験の会話を既成事実として語らない。

## 告白

告白はある程度一緒に過ごした後の任意の選択。結果は親しさ・信頼・恋愛の意識や一緒に過ごした経験に応じ、成立 `accepted`、答えを待つ `deferred`、現在は恋人になれない `rejected` を区別する。親しさだけで必ず成立することはない。

保留・拒否はゲームオーバーにせず、観光やデートを続けられる。再告白には新しい時間や経験を挟み、結果直後に同じ告白を繰り返せない。交際後も未体験の通常デートを遊べる。既存途中セーブは、保存時の脚本・効果と整合性を検証したうえで再開する。
