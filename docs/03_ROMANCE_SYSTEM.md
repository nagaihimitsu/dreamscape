# 03 恋愛システム仕様 Ver.3.0

## 企画上の目的
クイズの「おまけ」ではなく、独立した短い攻略ゲーム。長い会話の分岐を大量に作るのではなく、**章クリア→APでデート→3択で口説く→好感度・呼称の変化→告白成功**を繰り返す。恋人になることがエンディング。恋人後の追加長編は範囲外。

## AP（行動ポイント）
APはデートの機会を購入する資源。**好感度を直接購入する通貨ではない**。
- 初期バランス案: 章初回クリア +4AP、日常会話初参加 +1、クイズバトル初回完了 +1、好成績 +1。最初の章ではモックの開発ボタンで「章初回クリア+4」を試す。
- デート費用例: カフェ 2AP、散歩 4AP、特別イベント 6AP。
- AP上限: 初期案 12、未使用は持ち越し、既獲得報酬IDは二度と付与しない。
- 最安デートに必要なAPは章クリアだけでも獲得できる。英語が苦手でも恋愛進行を妨げない。
- AP不足時はボタン無効・減算しない。開始中断と再開で二重消費しない。デートの開始を「確認→消費→開始」の一貫したトランザクションにする。
- クイズの再戦・同じ日常会話の再表示で報酬を重複獲得しない。
- 全数値は設定データで変更可能。ここにある値はプレイテスト用で確定値ではない。

## 章末の恋愛モード
- 章クリア画面→「自由時間」を解放。観光と切り分けた専用画面。
- デートは費用、タイトル、短い紹介、必要関係段階、未体験かどうかを表示。選択してAP消費後にシナリオ開始。
- 通常デートは3〜5分程度を目標、**重要な3択選択を2回**。テキストで笑わせ、意外な反応、距離の変化を見せる。
- 通常デートは一度完了すると再選択できない。旧版で再鑑賞を開始済みのセーブは、途中の会話を維持して最後まで再開できる。告白の保留後は再挑戦できる。
- 好感度/関係状態は非表示、APのみ数値を表示。好感度が十分高いと自動的にりえから誘う「無料の特別イベント」を後で追加できる。

## 好感度と関係段階（シンプル設計）
初期実装は `affection`（非公開整数）・`romanceStage`・`memories[]`・`playedDateIds[]` のみ。Trust/Tuning/Spark/ELPの詳細な多変数モデルは**現フェーズでは導入しない**。後から導入できるようストーリーと状態の結合を浅くする。
- Stage1: 知り合い。「お兄さん」等、丁寧で距離がある。
- Stage2: 親しい友達。冗談や個人的な話が増える。
- Stage3: 恋愛の予感。視線や戸惑いが変わる。
- Stage4: 両想いの手前。デートや告白の条件を満たせる。
- GOAL: 告白成功→恋愛エンディング。
- 段階は好感度閾値と必要イベント履歴の両方で進行。数値閾値はシステムではなく設定へ。告白の成否は誠実な意思表示と物語上の条件で判定し、不可逆なゲームオーバーにはしない。
- プレイヤーとヒロインの表示名は任意変更可能。呼び方は同じ名前に付く敬称が段階で変わる。名称変更で台詞が破綻しない。

## 3択会話の設計
- 各選択肢に違う意味: 冗談、共感、少し大胆な口説きなど。
- 一目で「正解」を読める上中下の序列にしない。距離感によって反応・効果が変わりうる。
- 毎回最低1つ、予想外のリアクションがある。誤答にも面白い返答があり、単なる失敗文で終わらせない。
- やり取りは短くても、笑える瞬間、ヒロインの新しい一面、ドキッとする瞬間、記憶に残る小さな言葉のうち複数を含む。
- 思い出フラグを少数、質の高い箇所に付けて後の街で自然に回収する。

## 章末エピソード例（サンプル）
「ミラノ／運河沿いのカフェ」。りえはガイドブックを閉じて、何もすることのない時間を楽しみ始める。主人公は冗談・共感・率直な言葉を選ぶ。短い返答と次の選択が続く。台詞サンプルは `content/stories/milano/cafe_01.ink`。これは仕様例で、本番文章はプレイテスト後に推敲する。

## 告白
- 初期Phase1では未実装。Phase2で4段階+専用告白シナリオ・成立/保留・エンディングを導入。
- 告白条件が揃ったら専用イベントを解放。過去の重要なデートから一つ記憶を引用し、成功時に専用ラストを表示。
- 成功後も観光・クイズを遊べるが、恋愛ルートはクリア扱いとする。

## 各章でのゲーム性
目的はAPを大量に稼ぐことではなく「次のデートの機会を選び、どんな言葉を伝えるか悩むこと」。章あたりの会話量を無制限に増やさず、完成度の高い短編イベントを増やす。
