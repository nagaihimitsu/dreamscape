# 04 観光・英語クイズ・人物との対決

## 観光
- ミラノの有名観光地（ドゥオモ、ガッレリア、『最後の晩餐』、スフォルツェスコ城など）を好きな順に巡る。場所と交通を選び、時刻・営業時間・帰路を確かめる。次の都市がある旅行編では、都市クリアの後に次の都市へ出発する（自分で選んで出発するか、エピローグの後に自動で出発するかは、`manifest.json` の `cityTransition` で旅行編ごとに決める。インド編は自動）。
- 都市フィナーレへ進める条件は、都市ごとに制作者が書ける（決めた観光地の対決を終える、いくつかの対決を終える、お金や品物を持つ、交際している など）。書かない都市は、前提に決めた観光地（`progression/journey.json` の `requiredEpisodeIds`）と、その都市の特殊戦の対決をすべて終えると進める（ミラノ編は4観光とスカラ座・ブレラの特殊戦）。失敗しても各対決の完了は記録され、旅を続けられる。
- ヒロインの短い日本語案内と会話、背景・イラスト/正確な写真。案内は、要る場所にだけ入れる。
- 観察・発見型: 画像を拡大・ドラッグ・タップし、場所に合った観察ポイントを自由に調査。制限時間・必須観察なし。観察も、要る場所にだけ入れる（対決が使う手がかりを、どの観察でも見つけられないと、`content:build` が注意する）。
- 発見情報は手がかり帳に保存し、バトル中でも見られる。画面遷移でなくオーバーレイ/下からのパネルを推奨。
- 絵画や建築の細部を問うなら、AIで生成した図が本物と異なるおそれがある。ライセンス確認済みの実物資料画像を使う。

## バトル
- 対戦相手や交流する人物には生活と目的を持たせる。親切な人、商売人、危うい人、対等な論客など多様でよく、全員を変人や出題者にしない。英語クイズへの入口は事件・仕事・会話など場面ごとに作る。
- 3問の3択英語クイズが通常バトルの核。クイズの本文・選択肢は英語。道中交流の返答・行動選択は基本的に英語。人物の台詞は基本的に日本語（制限はなく、制作者は台詞や選択肢に英語を自由に使ってよい）。語彙補足・ヒント・解説は日本語。道中の会話選択には正誤を付けない（正解・不正解を示さず、採点しない。選んだ言葉で関係や品物、その後の展開が変わるのはよい）。
- 問題の題材は、人の願い、失敗、信仰、権力争い、伝説や異文化とのつながり、人物や表現の意外な小話を優先する。建材・運搬・寸法・年号・人名・様式名だけの暗記は原則主題にしない。ただし人の選択・事件・意外な結末に不可欠な技術や材料は使える。
- 英文を書く前に、日本語で「話の入口」「問い」「種明かし」を作り、クイズにしなくても興味を引くかを確認する。史実・解釈・仮説・伝説は区別し、一次・公的資料の該当箇所を確認する。未確認のものは未確認と記録する。
- 観光で見つけた証拠は、問題の解答に役立つ場合があるが、覚えていなくても手がかり帳を開ける。
- 手がかりには、問題の答えや解説がその内容を使うものと、どの問題にも結び付かない「観察だけの手がかり」（その場所の見え方を変える発見・資料）がある。どちらも手がかり帳で同じように読め、手がかりを見つけていなくても、覚えていなくても問題に答えられる（手がかり帳はバトル中も開け、特殊戦B・Cの証拠は事件の手がかりとしていつでも選べる）。結び付けは本当にその内容を使う問題にだけ付ける（[データ契約](07_DATA_AND_TESTS.md#観察だけの手がかり)）。
- 成績：結果の見出しは、全問正解で PERFECT（全問正解）、6割以上で CLEAR（クリア）、それより少なければ NICE TRY（ナイストライ）（3問なら2問以上、5問の都市フィナーレなら3問以上で CLEAR。判定は `src/domain/battle.ts`）。どの成績でも対決は完了し、旅を続けられる。完了した観光・対決はもう一度は遊べない。画面と遊ぶ人に向けた文では、勝ち負けの言葉を使わない（2026-11-11のユーザー判断。[AGENTS.md](../AGENTS.md)）。
- 会話、問題、反応、結末の流れはその人物と事件に合わせる。正解しても相手が改心する必要はなく、正解が少なくても旅を続けられる。

## バトル形式の比率（仮）
A: レイトン式、B: 証言矛盾追及、C: 証拠組み合わせ。Aを中心に、B/Cは物語に合う稀な特殊戦として配置する。旧試験値80/15/5は参考であり、地点数や出現順を固定しない。
- B/C: 証拠をいつでも1タップで確認、解答状態は保持、記憶力テストにしない。
- 都市フィナーレでも複数観光地の知識や出会いを回収する。B・C・通常戦・フィナーレはそれぞれ実在する著名な観光地に結び付け、特に「最後の晩餐」・B・Cは異なる主舞台と固有の資料を使う。

## 英語難易度
- A2/B1/B2。知識の難易度と英語の難しさは別。難しい史実をシンプルな英語でも問える。
- 語彙の表示・ヒント・解説・復習可能な構造にする。
- ユーザーが実際に英作文していないので、選択式クイズに無理にCEFR添削コメントを表示しない。

## コンテンツの制作と検証
- 史実・有力説・伝説を区別。元資料の出典URL/確認日/知識根拠を持つ。
- AIに直接3択を大量生成させる前に、観光地を題材とした良質な事実リストを作る。
- 別工程で英語、事実、誤答選択肢、論理的な一意正解、語彙難易度、観光価値を検証。
- 敵の日本語台詞はAI一括量産のまま本採用しない。キャラクター設計→脚本の複数案→編集・推敲。

## 任意の英語学習支援の制作方針
- 問題・各選択肢の訳は原文に忠実にし、正答だけを詳しくしたり、根拠を付け足したりしない。意味が事実と異なる選択肢も、英語として誤りとは限らない。
- 語彙・文法・語法は実際の英文を対象にし、その文での意味を優先する。解説や短い確認会話は任意で開き、観光の正誤説明と区別する。
- 正答率から英語力やTOEICスコアを推測しない。学習操作は採点・報酬・恋愛進行を変化させない。
