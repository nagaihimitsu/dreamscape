# Dreamscape

恋愛 × 世界観光 × 英語学習の、モバイル優先ブラウザゲーム。現在は **Phase 4まで**を実装しています。恋愛ルートは名前設定から通常デート3本、ヒロインの誘い、告白、交際エンディングまで。ミラノ『最後の晩餐』では実物の資料画像を観察し、手がかりを持って日本語の掛け合いと英語3択3問のバトルへ進めます。仕様の優先順位は [AGENTS.md](AGENTS.md)、全体設計は [docs/](docs/) を参照してください。

## 起動

Node.js 22.12以上を推奨（開発・検証環境: Node.js 24.19.0 / npm 11.9.0）。

```sh
npm ci
npm run dev
```

表示されたURL（通常 `http://localhost:5173`）で遊べます。Viteは `0.0.0.0` にバインドします。同じネットワークのスマートフォンからは開発機のIPと表示ポートにアクセスしてください。外部のクラウド開発環境では環境側のポート公開URLを使用します。

```sh
npm run build
npm run preview
```

本番出力は `dist/`。静的ホスティングで配信でき、サブディレクトリ配信にも対応する相対パス設定です。HTMLファイルを直接開かず、HTTP経由でアクセスしてください。バックエンド・アカウント・クラウド保存はありません。

## GitHub Pages

公開先: https://nagaihimitsu.github.io/dreamscape/

`.github/workflows/pages.yml` が `main` へのpushで、コンテンツ検証・単体テスト・型チェック・本番ビルドを実行し、成功した `dist/` をGitHub Pagesへ公開します。初回のみリポジトリの **Settings → Pages → Build and deployment → Source: GitHub Actions** を選択してください。設定後はActionsの「Deploy to GitHub Pages」から手動実行もできます。公開設定とデプロイの権限はGitHub側で必要です。

## Phase 4の観光・観察を試す

1. 名前設定またはロード後、**「観光・観察を試す」** を押します。ヒロインの短い案内を読み、「観察を始める」へ。案内は途中保存され、閉じて観察を始めることもできます。交際エンディングからも訪問でき、恋愛会話の途中では開始できません。
2. 絵の番号をタップするか一覧から選びます。対象を拡大・中央へ寄せ、短い説明を手がかり帳へ記録します。4箇所は遠近法、使徒のまとまり、光輪に代わる光の表現、後世に広げられた扉。画像だけでは確認できない制作技法は、独立した資料カードです。
3. 拡大・縮小ボタン、ドラッグ、2本指のピンチで自由に観察できます。「全体を見る」で戻り、「印を隠す」で絵だけを眺められます。倍率は1〜5倍、移動は画像の端で止まります。キーボードでは観察領域にフォーカスして矢印キーで移動、`+` / `-` で拡大縮小、`0` で全体表示できます。
4. **「バトルを始める」** で既存の英語3択へ進みます。観察は任意で、発見ゼロでも開始できます。問題の正解や採点は観察の有無で変わりません。
5. バトル中は **「手がかり帳」** を1回押すと、発見した説明を読み返せます。閉じても同じ会話・問題・回答後の画面へ戻ります。「観光に戻って調べる」で追加の観察をし、「バトルに戻る」で中断した箇所から続けられます。

発見済みのIDは自動保存され、再読み込み後も残ります。手がかり帳の開閉と画像操作は採点や戦績を変更しません。拡大位置は画面を開き直すと全体表示に戻ります。**観光もAP・好感度・思い出・章クリアには影響しません。** 都市全体の進行との統合は後のフェーズです。

## Phase 3のクイズバトルを試す

1. 名前を設定するか、既存の旅をロードし、**「クイズバトルを試す」** を押します。章クリア・APは不要で、交際エンディングからも開始できます。恋愛会話の途中では開始できないため、会話を終えてから試してください。
2. 保存に取り憑かれたアルド・ヴェルニーチェとの日本語会話を読み、構図・遠近法・制作技法についての英語3択を3問解きます。英語はB1を基本とし、語彙の日本語補足と任意のヒントがあります。
3. 回答は確認画面を挟まず確定し、その問題の選択肢をロックします。正誤・日本語解説を読んで「敵の反応を見る」へ進みます。間違えても最後まで遊べます。
4. 正解数3で **PERFECT VICTORY**、2で **VICTORY**、0〜1で **DEFEAT**。敵の結末とヒロインの余韻が変わります。結果画面から再戦、または元の恋愛画面へ戻れます。

会話・問題・ヒントの開閉・回答後の解説・結果は自動保存され、リロード後も同じ状態から再開します。初回・最高・直近の正解数と完了した挑戦数を記録します。ヒント使用による進行制限はありません。**バトルはAP・好感度・思い出・章クリアを変更しません。** Phase 2の試遊用APは引き続き利用できます。バトル報酬との正式統合は後のフェーズです。

## Phase 2の恋愛を試す

1. 主人公名・ヒロイン名を設定して「旅をはじめる」。既定は「なお」「りえ」、最大24文字（UTF-16単位）。既存のPhase 1セーブがあれば、その場面から続けられます。
2. 開発用「ミラノ章初回クリア」で **4AP** を受け取り、「運河沿いのカフェ」に **2AP** で誘います。
3. 日本語の3択を2回選び、デート終了後「自由時間に戻る」。**旅をもう一歩／Phase 2 試遊用** の「翌日の自由時間」で一度だけ **4AP** を受け取れます。
4. 「夕暮れの散歩」（3AP）を完了。ヒロインから届いた「彼女の寄り道」の誘いに応えます。この特別イベントは **無料・一度限り** です。
5. 試遊用「夜の自由時間」で一度だけ **4AP** を受け取り、「灯りを数える夜」（3AP）を楽しみます。
6. 「旅の続きに、きみと」で気持ちを伝えます。告白に **APは不要**。過去のカフェの言葉を振り返り、交際開始か保留に分かれます。
7. 保留になったら、無料の「書きかけのポストカード」で話してから、もう一度告白できます。通常デートで低めの好感度の選択を重ねても、誠実に気持ちを伝えれば交際エンディングへ到達できます。

通常デートは3択2回、特別イベント・保留後の会話・告白は3択1回です。好感度の数値、段階名、解放閾値は表示せず、呼び方や会話で変化を伝えます。これらのシナリオはシステム検証用の短編で、本番脚本としての推敲は別途行う前提です。

一文ずつの文字送りは3速度・全文表示に対応し、選択は確認画面で言い直せます。「中断する」やリロード後も、表示中の一文・選択肢・選んだ後の反応から再開できます。「セーブ」「ロード」は自動保存と同じ保存枠なので、過去へ巻き戻す機能ではありません。名前は会話の外で「設定」から変更できます。

再鑑賞は元のAP費用を使い、好感度・思い出を再獲得しません。これから必要なデートのAPまで使い切る再鑑賞は無効になります。試遊用APは総量12（初回章4＋仮進行4＋4）、所持上限12で、報酬IDごとに一度だけです。上限を超える試遊報酬は空きができるまで受け取れません。特別イベントと保留後の会話は一度だけ、保留中の告白は無料で再挑戦できます。

開発者向けの最低経路確認: カフェ選択1→1、散歩1→2、誘い1、夜景1→2、告白1で保留、ポストカードは任意、再告白1で成功。ブラウザテストもこの経路を検証しています。交際エンディングの到達状態は保存され、再読み込み後も表示されます。恋人後の長編はありません。

## 文章・データの編集

会話の編集元は `content/stories/milano/` の各 `.ink` ファイルです。既存 [`cafe_01.ink`](content/stories/milano/cafe_01.ink) はPhase 1から変更していません。台詞と選択肢をReactに埋め込まず、Inkに置いています。

```ink
# speaker: heroine
「……{player_name}さん。明日の予定、一つだけ書いてもいい？」
```

名前は `player_name` / `heroine_name` をゲーム状態から渡します。新しい恋愛シナリオでは `player_address`（段階に応じた敬称つき呼称）、`romance_stage`、`memory_callback`（過去の思い出）、`confession_ready` も利用できます。AP・段階・告白条件の計算はTypeScript側で行い、Inkには結果だけを渡します。`* [選択肢]`、`->` の合流で短い分岐を編集します。タグは `speaker`（narrator/heroine/player/enemy）、`background`、`emotion`、`effect` に限定。背景・表情はpresentationに登録、effectはeffect_catalogのIDに限定し、文字列をコードとして実行しません。本文タグとInk公式choice tagsの両方を検証・処理します。

| ---------------------------------------- | -------------------------------------------------------------------- |
| `content/stories/**/*.ink`               | 会話、選択肢、リアクション、タグ                                     |

| `content/romance/presentation.json`      | 背景・表情・思い出・保留案内・エンディングの文章                     |

新しい通常デートは、InkとJSON定義・効果を追加するだけで既存のメニューと会話画面に表示されます。`kind` は `normal` / `special` / `confession` / `reassurance`。通常は `choiceCount: 2`、無料イベントは必要に応じて0〜2回の3択を設定できます。`effectCount` は各経路で期待する効果数です。`actionLabelJa` もJSONにあり、Reactにイベント固有の文言を追加する必要はありません。

`validationContexts` に関係段階、告白可能/保留、引用するmemoryIdを指定し、その文脈から全分岐を検証します。告白は成立条件の真偽を両方指定する必要があります。通常デートは各文脈9経路、選択機会1回のイベントは各文脈3経路です。現在は6シナリオを合計105経路・文脈で検証しています。

```sh
npm run content:check
```

`inkjs/compiler/Compiler`（公式inkjsのコンパイラ）でコンパイルし、`src/content/generated/stories.json` を生成します。独自Inkパーサー・外部コマンド・.NETの準備は不要です。生成JSONはGit管理せず、手動編集しません。ブラウザには `inkjs` のランタイムを使用します。

`dev` 起動前、`test` 前、`build` 内で必ずコンパイル・検証します。開発サーバー起動中にInkを改稿したら別ターミナルで `npm run content:build` を実行してください。生成JSON変更をViteが反映します。**Ink原稿そのものの自動監視はありません。**

検証はJSONスキーマ、重複ID、章・背景・シナリオ・思い出参照、許可タグ、前提イベントの循環、段階設定、報酬ID重複、シナリオごとの選択数・効果数・告白結果を確認します。壊れたInk・参照切れ・未定義effect・不正JSONはビルド失敗になります。旧 `last_supper_B1.sample.json` は参考サンプルの検証だけに使用し、出題しません。

### クイズ・敵シナリオの編集

新しい通常バトルは、3問入りクイズJSON・Inkを用意し、`content/battles/catalog.json` に登録します。既存の画面を直接編集する必要はありません。クイズの `englishLevel` は A2/B1/B2 を表現できますが、今回の実装コンテンツはB1の1セットのみです。各問の `difficulty` は easy/medium/hard。選択肢IDと正解IDを一致させ、正解位置に偏りがないか確認してください。

出典は `sources` に公式資料のURL・発行元・タイトル・確認日・根拠文を保存します。`claimType` は documented_fact / interpretation / legend で区別し、学説は断定せず根拠文に明記します。今回は美術館の公式解説 [A powerful theatrical machine](https://cenacolovinciano.org/en/story/a-powerful-theatrical-machine/) と [Backstage](https://cenacolovinciano.org/en/museum/backstage/) を参照しています。プレイヤーには解答後に根拠リンクを表示し、出題前に解説を見せません。

Inkには `battle_scene`（catalogのシーン名）、`answer_correct`（直前の正誤）、`battle_score`（正解数）、設定した名前と `player_address` を渡します。導入・第1問後・第2問後・決着をそれぞれ独立した短いシーンとして `-> END` で閉じます。最終問の反応と勝敗別の結末は決着シーン内で分岐します。クイズの選択・採点はTypeScriptが担当するため、バトルInkには選択肢や恋愛effectを置けません。既存の文字送り・speaker/background/emotionタグを使い、演出を後から加えられる形にしています。

バトル用検証は、全3問・各3択・正解参照・重複ID・語彙・出典・シーン参照に加え、到達可能な13通りのシーン入力でInkを最後まで実行します。日本語の導入やヒント以外の表示が次問の答えを漏らしていないか、史実が正しいかは脚本レビューでも確認してください。クイズも `src/content/generated/quizzes.json` に生成されます。生成物は手動編集しません。

### 観光地・発見ポイント・画像の編集

`content/tourism/catalog.json` の `landmarks` に観光地を、`assets` に画像を、`clues` に発見内容を登録します。観光地は都市ID、日本語・英語名、画像アセットID、案内InkのID、既存バトルID、手がかりID一覧を持ちます。追加には都市の `landmarkIdsPlanned` と対応するバトル定義も登録します。React画面の修正は不要です。

`clues[].region` は**画像全体に対する0〜1の相対座標**で、左上の `x` / `y` と `width` / `height` を指定します。画面のpx値は書きません。`kind: "hotspot"` は領域必須、`kind: "document"` は `region: null` とし、技法など画像から直接観察できない知識を資料カードにします。`factId` は安定ID、`relatedQuestionIds` は既存クイズの問題IDです。説明はJSON、人物の台詞はInkに分けます。出典の `claimType` は事実・解釈・学説・伝承を区別し、画面にも区分と根拠を表示します。

観光案内Inkには `player_name` / `heroine_name` / `player_address` を渡します。短い日本語の線形会話として書き、恋愛effectや選択肢を入れません。コンテンツ検証ではID・参照・座標範囲・資料カードとの区別・出典・画像ファイルの形式・案内の実行を確認します。

現在の画像は [Wikimedia Commons掲載のParis Orlando撮影写真（2019年）](https://commons.wikimedia.org/wiki/File:Last_Supper_by_Leonardo_da_Vinci.jpg)。CommonsのPD-Art / PD-old-100-expiredおよび [Public Domain Mark 1.0](https://creativecommons.org/publicdomain/mark/1.0/) 表示を確認した忠実な複製画像です。3840px版を全体の構図を保ったまま2560×1422pxのWebP（約1.53MB）へ縮小・圧縮しました。描き足し・左右反転・生成AIによる補完はしていません。クレジット・出典・権利表示・確認日・加工内容はアセットJSONと画面内に残しています。

画像は `public/assets/tourism/last-supper.webp` の差し替えで反映できます。同じ構図・縦横比を維持してください。構図やトリミングを変える場合はアセット寸法と発見領域を再確認・更新します。別の画像に替えた場合は出典・利用条件・加工情報も更新してください。資料として正確でない仮画像は `isPlaceholder: true` で明示します。

## 実装とセーブ

- `src/app/` / `src/components/`: 表示・操作・保存後の状態反映。APや好感度の計算はありません。
- `src/domain/`: 純粋関数で章報酬、デート可否、AP、効果、履歴を処理。`battle.ts` は採点、ラウンド、勝敗、戦績のみを担当。
- `src/domain/tourism.ts`: 案内・訪問・発見・バトルとの往復。`src/features/tourism/viewport.ts` は画像座標・拡大・移動範囲の計算。
- `src/story/`: 公式 `Continue` / `currentChoices` / `ChooseChoiceIndex` とstate JSONを包むアダプタ。
- `src/persistence/`: localStorageアダプタ・保存データ検証・バックアップ。
- `src/content/` / `scripts/`: データ契約・許可タグ・ビルド時検証。

保存キーは旧版と同じ `dreamscape.save.v1`、データ内の `schemaVersion` は **4**。名前・AP・非表示好感度・思い出・履歴と、進行中のInk state/表示フレーム/選択回数/適用済み効果をまとめて保存します。バトルには表示段階・ラウンド・回答履歴・正解数・ヒント状態・Ink stateと、初回/最高/直近成績・完了回数を保持します。観光は `activeTourism`（観光地・案内/観察状態・案内Ink）、`visitedLandmarkIds`、`discoveredClueIds` を追加しています。リビジョン付き操作で古い入力を無視し、同じ発見・問題の二重処理や結果の再加算を防ぎます。保存が成功してから画面を進め、保存失敗時はその場に留まって再試行できます。

Phase 1・2・3（schemaVersion 1・2・3）は検証後にメモリ上で4へ移行し、次の進行操作で保存します。AP、名前、好感度、思い出、報酬・デート履歴、進行中のInk JSON・表示フレーム・選択位置・バトル回答を保持します。既存の恋愛・バトルInkと問題データは変更していません。Phase 1の段階は既存の好感度と完了履歴から再評価します。実際の旧実装で作成した `tests/fixtures/phase1-saves.json`、`phase2-saves.json`、`phase3-saves.json` を検証に使っています。

バトルから観光へ戻った場合は、同じ観光地の `activeBattle` と `activeTourism` を同時に保持します。観光を開いている間は回答操作を止め、バトルへ戻ると同一の回答・スコア・ヒント・Ink位置を再開します。恋愛会話との同時実行はできません。

Phase 2では解放済みイベントID、告白の保留/成功、交際エンディングの到達を保持します。成立の思い出とエンディングは告白を読み終えた時点で一緒に確定するため、成功反応の途中で更新しても欠落・二重付与しません。古いタブからの上書きも検出してロードを案内します。

破損・未知バージョン・不整合な保存は自動上書きしません。案内画面から明示的に新しく始める場合に限り、元データを `dreamscape.save.v1.backup.<時刻>` に退避します。他アプリの保存データは削除しません。シナリオ更新で進行中のInkとの互換性が失われた場合も元データを保護します。バトルでは問題・正解・シナリオの定義を含む指紋を照合し、更新前の回答を新しい問題で勝手に採点し直しません。観光画像の交換だけでは案内の指紋は変わりません。Phase 1〜3の既存シナリオには対応していますが、任意に改稿したInkの実行位置を移す機能はありません。改稿確認には別ブラウザプロファイルを使うと既存の旅を残せます。保存は端末・ブラウザ・URLのオリジンごとです。

## 検証

```sh
npm run content:check
npm run typecheck
npm run test
npm run build
npx playwright install chromium
npm run test:e2e
```

空のcheckoutでは `npm ci` のあと、生成物を必要とする単独 `typecheck` より先に `content:check` を実行してください。`npm run build` はこの順序を含みます。

単体テストは通常デート各9通りの保存・復元、段階と履歴の判定、告白の成功/保留/再挑戦、特別イベントの一度限り実行、AP上限/不足/未解放/連打、再鑑賞による資金不足の防止、旧セーブ移行、破損/未知schema/保存失敗、コンテンツ検証エラーを対象とします。バトルは全27回答経路で各状態の保存・復元、正誤反応、3種の勝敗、ヒント、二重送信、再戦、恋愛状態の不変性を検証します。

PlaywrightはモバイルChromiumで既存カフェ、低好感度からの保留・回復・交際開始、高好感度での成功、過去の思い出・名前変更、旧セーブの途中再開を操作します。バトルは360px幅で0〜3問正解の通しプレイ、ヒント・語彙、回答ロック、反応中の再読込、再戦、Phase 2の交際エンディングからの出入りを操作します。実機Safariでの検証は別途必要です。

観光は拡大・移動・相対座標の単体検証に加え、360px幅のPlaywrightで画像読み込み、タッチ入力によるピンチ・ドラッグ、移動制限、発見と再読み込み、手がかり帳の開閉、観察をスキップしたバトル、途中回答を保持した観光への往復、旧Phase 3セーブを検証します。

恋愛の背景と敵の立ち絵は簡易SVGイラストです。観光画面のみ上記の実物資料画像を使用しています。フォントはNoto Sans JP / Noto Serif JP（Google Fonts、SIL OFL）を任意取得し、取得できなくてもシステムフォントで動作します。
