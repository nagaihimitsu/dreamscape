# Dreamscape

恋愛 × 世界観光 × 英語学習の、モバイル優先ブラウザゲーム。現在はミラノ編を実装しています。4観光地を巡り、各3問の通常戦と5問の都市ボスを経て、都市エピローグまで遊べます。自由時間には複数の行き先からデートを選び、ヒロインの誘いや任意の告白も楽しめます。矛盾追及・証拠連結の特別対決も各1本あります。仕様の優先順位は [AGENTS.md](AGENTS.md)、全体設計は [docs/](docs/) を参照してください。

## 起動

Node.js 22.12以上を推奨（開発・検証環境: Node.js 24.19.0 / npm 11.9.0）。

```sh
npm ci
npm run dev
```

表示されたURL（通常 `http://localhost:5173`）で遊べます。Viteは `0.0.0.0` にバインドします。同じネットワークのスマートフォンからは開発機のIPと表示ポートにアクセスしてください。外部のクラウド開発環境では環境側のポート公開URLを使用します。

```sh
npm run build
npm run preview
```

本番出力は `dist/`。静的ホスティングで配信でき、サブディレクトリ配信にも対応する相対パス設定です。HTMLファイルを直接開かず、HTTP経由でアクセスしてください。バックエンド・アカウント・クラウド保存はありません。

## GitHub Pages

公開先: https://nagaihimitsu.github.io/dreamscape/

`.github/workflows/pages.yml` が `main` へのpushで、コンテンツ検証・単体テスト・型チェック・本番ビルドを実行し、成功した `dist/` をGitHub Pagesへ公開します。初回のみリポジトリの **Settings → Pages → Build and deployment → Source: GitHub Actions** を選択してください。設定後はActionsの「Deploy to GitHub Pages」から手動実行もできます。公開設定とデプロイの権限はGitHub側で必要です。

## ミラノ編の遊び方

1. 主人公名・ヒロイン名を設定して「旅をはじめる」。既定は「なお」「りえ」、最大24文字（UTF-16単位）。新規プレイは**ドゥオモ**から始まります。
2. ヒロインの案内を読み、写真を自由に観察します。案内・観察は任意で、発見せずにバトルへ進めます。
3. 日本語の掛け合いと英語3択3問を最後まで読むと、エピソードと戦績・APが確定します。結果画面から「自由時間へ進む」または「次の観光地へ進む」を選びます。
   結果画面の「AP報酬の内訳」「今回の正誤と戦績」を開くと、詳しい記録を確認できます。保管中のAPがある場合は、その項目から受け取れます。
4. **ドゥオモ → ガッレリア → 最後の晩餐 → スフォルツェスコ城**の順に進みます。最後の晩餐の通常戦の後にはB型の矛盾追及、城の後には最後の晩餐へ戻ってC型の証拠連結が登場します。結果画面や自由時間から旅を続けられます。
5. 4箇所とその途中の対決を終えると都市ボス「マエストロ・ゼーロ」が解放されます。4観光地の知識を組み合わせる英語3択5問です。5問正解でPERFECT、3〜4問でVICTORY、0〜2問でDEFEATですが、**どの成績でもミラノ都市クリア**となり、旅は詰まりません。
6. ボス結果から「エピローグへ進む」。台詞は現在の関係段階・交際状態に応じて変わります。都市クリアと恋愛の交際開始は別の達成です。
7. 都市クリア後は2APの新デート「地図にない帰り道」に誘えます。交際済みでも遊べる短いひとときで、既存の恋愛エンディングを取り消しません。

自由時間では、次の目的地やデートを選び、各観光地のクリア状態、発見数、最高成績・挑戦回数を確認できます。クリア済みの場所や対決は「旅先を再訪する」から選べます。都市エピローグは未読のときに一度見ることができます。

旧版の『最後の晩餐』クリアは維持されます。未完了のドゥオモ、ガッレリアを巡った後は、クリア済みの通常戦をやり直す必要はありません。B型が未体験なら先に登場し、その後に城へ進めます。旧版の途中会話・バトルは、その場面から再開できます。

## AP報酬のルール

条件と数値は `content/progression/journey.json` の試験設定です。APの加算はTypeScriptのゲームルール層だけで行います。

| 対象                           | 案内初読了 | バトル初完了 |   初好成績 | エピソード／都市クリア |
| ------------------------------ | ---------: | -----------: | ---------: | ---------------------: |
| ドゥオモ・ガッレリア・城（各） |          1 |            1 | 2問以上で1 |                      1 |
| 最後の晩餐                     |          1 |            1 | 2問以上で1 |    4（旧報酬IDを維持） |
| 都市ボス                       |          ― |            1 | 3問以上で1 |            都市クリア3 |
| B/C特殊戦                      |          ― |            0 |          0 |                      0 |

新規プレイの総供給量は、案内スキップ・全問不正解でも**15AP**、全案内読了・全好成績で**24AP**です。ドゥオモの最低2APだけでも最初のカフェに誘えます。好成績ボーナスは、後の再戦で初めて条件を満たした時にも一度だけ獲得できます。クイズは好感度を直接変えません。

所持上限は**12AP**。上限を超える統合報酬は「保留中のAP」として保存し、空きができてから受け取れます。デートでAPを使った際も、保留分を自動で受け取ります。報酬IDと残額を別々に保存し、リロード・連打・再戦による重複や取りこぼしを防ぎます。

旧『最後の晩餐』の4APは `chapter_milano_first_clear` のままで、新しい3観光地や都市報酬へ複製しません。旧セーブですでに受領している場合、再度付与しません。新しい都市クリア報酬は別IDです。

`content/romance/trial_progression.json` の4AP×2の補助報酬は、Phase 1〜6から移行した旅だけに残します（`legacyTrialAvailable`）。新規ゲームは観光・バトル・都市報酬で進行します。旧補助報酬も一度限りで、上限を超える場合は空きができるまで受け取れません。

## 観察・バトルの操作

画像の番号または一覧を選ぶと、対象を拡大・中央へ寄せ、説明を手がかり帳へ記録します。大聖堂の大理石や尖塔、ガッレリアの屋根、城の壁や中庭など、写真で見える特徴を観察できます。『最後の晩餐』では遠近法、使徒のまとまり、光輪に代わる光の表現、後世に広げられた扉を扱います。写真で確認できない制作技法・歴史は独立した資料カードです。

発見した箇所の説明は画像のそばに表示され、見比べながら拡大・移動や別の発見ができます。「発見ポイント・資料を見る」から一覧と資料も選べます。長い説明や資料の一覧は、開いた欄の中でスクロールして読めます。

拡大・縮小ボタン、ドラッグ、2本指のピンチに対応します。「全体を見る」で戻り、「印を隠す」で画像だけを眺められます。倍率は1〜5倍で、移動は画像の端で止まります。キーボードでは観察領域にフォーカスして矢印キーで移動、`+` / `-` で拡大縮小、`0` で全体表示できます。拡大位置は画面を開き直すと全体表示に戻ります。

バトル中の **「手がかり帳」** は1回押すと開き、閉じても同じ会話・問題・回答後の画面に戻ります。「観光に戻って調べる」で追加の観察をしてから「バトルに戻る」で続けられます。発見の有無によって正解や採点は変わりません。スキップした案内や旧版で読了を確認できない案内は「観光案内をもう一度読む」で読み直せます。

手がかり帳は「前へ」「次へ」または一覧で1件ずつ切り替えます。特殊戦では敵の主張と選択ボタンを表示したまま比較でき、選んだ証拠は閉じても残ります。長い説明や画像・出典を開いた場合は、説明欄の中をスクロールして確認できます。

通常戦のクイズはB1を基本とした英語3択3問。語彙の日本語補足と任意ヒントがあり、回答後は選択肢をロックして正誤・日本語解説を表示します。3問正解で **PERFECT VICTORY**、2問で **VICTORY**、0〜1問で **DEFEAT**。敵の結末とヒロインの余韻が変わり、初回・最高・直近の正解数と完了回数を記録します。ヒントを使っても完走・報酬獲得が可能です。

## 保存データの消去

「設定」→「保存データの消去」で確認画面を開き、消去を確定できます。このブラウザにある旅の進行・名前・AP・恋愛やバトルの記録、英語ノートと対訳設定を消去し、開始画面へ戻ります。操作は取り消せません。以前に退避したバックアップ、他のサイト、別のブラウザや端末のデータは消去しません。読めないセーブがある場合も、開始画面の案内から明示的に消去できます。別のタブで更新されていた場合は消去せず、再読み込みを案内します。

## 英語の対訳と振り返り

問題文や選択肢の英単語を1回タップすると意味を表示し、同じ単語を続けて2回タップすると、その文の日本語訳を開閉します。単語を触っても解答は確定せず、各選択肢の左端にある A・B・C のボタンで回答します。既存の語彙補足にある文脈上の意味を優先し、それ以外は一般的な意味を表示します。キーボードでも単語を選べます。問題文と各選択肢の「訳を見る」でも原文の下に日本語を表示します。「すべての訳を見る」で一括表示でき、設定の「常に日本語訳を表示する」も選べます。訳を見る操作で回答は確定せず、点数や報酬も変わりません。語彙補足とヒントは従来どおり利用できます。

回答後の「英文を確認する」では、問題・全選択肢・自分の回答・正解・訳を見比べられます。『最後の晩餐』の通常戦3問には、文の組み立て、文法・表現、例文、ヒロインとの短い確認も用意しています。その他の問題は対訳・語彙・観光の正誤解説を利用できます。バトル中は回答済み問題、結果画面は全問を振り返れます。自由時間の「英語ノート」では過去の回答と「あとで復習する」の登録・解除を確認できます。再戦やAPは不要です。

対訳設定・開閉・復習マーク・各バトルの直近の回答は、ゲーム本体とは別の `dreamscape.learning.v1` に保存します。壊れたデータや未知の版は自動上書きせず、別タブで更新されたときは再読込を案内します。問題やバトル内容の指紋が変わった古い回答は現在の問題に重ねません。旧セーブに合計点しかない場合は「以前の回答内容は未記録」と表示し、回答を推測しません。ゲーム本体の途中バトル・恋愛・報酬の保存形式と検証は変更していません。

対訳は `content/learning/translations.json` に、安定した問題IDと原文・選択肢・正解の照合用スナップショット、日本語訳を置きます。問題を変更すると `npm run content:check` が不一致を報告するので、訳を確認して照合用の原文も更新します。詳しい文法・語法は `content/learning/details.json`、短い学習会話は `content/stories/learning/english.ink` で編集します。語句・質問の対象が英文中にあること、資料URL、会話の話者・行数・効果なしの契約をビルドで確認します。英語の自然さや訳の妥当性は人が確認してください。

## 特別対決：矛盾追及・証拠連結

通常の旅ではA型を中心に、最後の晩餐の通常戦の後にB型、城の後にC型が登場します。いずれも成績にかかわらず最後まで進め、対決の間に自由時間を取ることもできます。体験済みの対決は「旅先を再訪する」から再戦できます。旧セーブではこれまでの戦績を維持し、未体験の対決にも通常の進行から進めます。

再訪先は観光・通常戦・特別対決の一覧から選べます。英語ノートでは、回答した問題を一覧または「前へ」「次へ」で切り替えられます。

| 形式        | 対決の内容                                               | 推理するラウンド |
| ----------- | -------------------------------------------------------- | ---------------- |
| A：通常戦   | アルド・ヴェルニーチェとのテンポのよい英語3択            | 追加操作なし     |
| B：矛盾追及 | 原因を一つにまとめたがるニーノに、異なる損傷の証拠を示す | 第2問            |
| C：証拠連結 | 何でも切り離すエットレに、人物配置と遠近法の関係を示す   | 第3問            |

どれも英語3択3問です。Bでは敵の主張を読み、必要なら **「追及する」** で詳しく聞きます。「手がかり帳」で証拠を1枚選んで **「証拠を突きつける」**。Cでは2枚を選び **「組み合わせる」**。どちらも資料を示しただけでは得点にならず、続く英語3択で理由・結論を答えます。誤った資料には不足している観点を短く説明し、その場で選び直せます。推理操作に時間制限・AP消費・減点はありません。

手がかり帳は1タップで開けます。敵の主張と英文問題を上部に残したまま、証拠の詳しい説明・出典・観光画像を比較できます。画像の枠は観光画面と同じ相対座標で、拡大して確認できます。必須の証拠は **「ケース資料」** として未発見でも読め、事前に観察したものには「観察済み」と表示します。読んだだけで観光の発見履歴を変更しません。選択は即時保存され、帳面を閉じても再読み込みしても残ります。

Bの争点は、乾式技法による劣化と、後世の出入口拡張による損傷の区別です。Cの結論は、観察できる人物配置と遠近法を踏まえた構図の**解釈**であり、作者の意図が証明されたとは扱いません。

B/C戦の戦績と途中状態は保存しますが、追加のAP・章クリア報酬・好感度・告白条件は変更しません。終了後は旅を続けるか、自由時間へ戻るか選べます。A/B/Cの80/15/5という比率は将来の目安で、出現抽選や数合わせは実装していません。

## 自由時間とデート

観光エピソードを終えると、自由時間でAPを使って行き先を選べます。カフェ・散歩・夜景に決まった順番はありません。旅を進めると、スカラ座、ブレラ絵画館、ナヴィリオ地区、サン・サティロ教会、スターバックス・ロースタリー、プラダ財団、彫刻《L.O.V.E.》などが候補に加わります。候補が多い場合は「前の候補」「次の候補」で切り替えます。

通常デートは3択を2回。選んだ言葉によって親しさ、信頼、恋愛の意識がそれぞれ変化します。数値や告白の成功率は表示せず、会話や態度から伝えます。りえからの無料の誘いや、特定の旅の途中だけ現れる短い出来事も任意です。

告白も任意で、成立・保留・拒否があります。拒否後も旅を続けられ、再告白には新たなデートを挟みます。交際後も未体験の通常デートを楽しめます。現在遊べる都市はミラノのみで、告白しなくても都市の旅とエピローグまで進めます。

通常デートでは行き先にちなんだ実景と小話を会話で楽しめます。会話中の「会話の操作」→「背景画像を見る」で写真全体と作者・利用条件を確認できます。周辺の街並みを用いた画像は出典欄にその旨を記載し、画像を用意できない場合は中立色で表示します。行き先や出典の追加方法は[制作マニュアル](authoring/CONTENT_GUIDE.md)を参照してください。

脚本更新前に開始したデートは旧脚本をそのまま再開します。新しく開始するデートに新しい観光会話が適用され、旧セーブの進行・AP・恋愛状態は維持します。

文字送りは3速度・全文表示に対応します。台詞をタップすると、表示途中なら全文を表示し、次のタップで会話が進みます。恋愛会話の返答は選ぶとすぐに進みます。以前の確認設定が保存されている場合も同じ操作です。APを使うデートの開始時には確認画面が表示されます。会話ログは現在のイベントで表示済みの台詞を最大100件読み返せます。ログは画面を開いている間だけ保持し、再読み込み後は表示した台詞から記録します。旧セーブにない過去の台詞は補完しません。中断・リロード後も表示中の一文や選択後の反応から再開できます。名前は会話の外で「設定」から変更できます。セーブ・ロードは自動保存と同じ枠で、過去へ巻き戻す機能ではありません。

「自動送り」は任意で、選択肢や問題、ログ・設定、会話の操作メニュー、ウィンドウ非表示、中断時に停止します。狭い画面では「会話の操作」から文字速度やウィンドウ非表示を選べます。隠したウィンドウは画面を一度タップすると戻り、そのタップで台詞は進みません。

通常戦では英語や訳を読んでも回答は確定せず、各選択肢の左端にある A・B・C のボタンで答えます。回答の保存後に短い演出を表示します。「設定」の「演出を短縮する」または端末の動きを減らす設定で演出を抑えられます。表示設定はゲーム本体とは別の `dreamscape.presentation.v1` に保存され、破損・未知バージョンや別タブでの更新を検出した場合は勝手に上書きしません。設定や演出は得点・報酬・セーブのシナリオ指紋に影響しません。

人物素材は [`content/presentation/characters.json`](content/presentation/characters.json) で登録します。人物ID `heroine` はプレイヤーが設定する名前とは独立しています。地域に属さない基本衣装 `default_01` に、提供された11表情の透過画像を登録しています。

### 基本衣装・表情の画像を追加する

1. 背景を透過した全身PNGまたはWebPを用意します。白背景の参照画像は正式な立ち絵とは別に管理し、拡張子だけを変えて登録しないでください。基本衣装 `default_01` の `standing_01` は **1024×1536px** を共通キャンバスとして設定しています。同じ衣装・ポーズの差分は、人物の位置とキャンバスを揃え、画像ごとにトリミングしません。
2. 例えば `public/assets/characters/heroine/default_01/standing_01/neutral.png` に置き、`characters.json` の `heroine` → `costumes` → `default_01` → `poses` → `standing_01` の `expressions` に `"neutral": "assets/characters/heroine/default_01/standing_01/neutral.png"` と登録します。パスは `public/` からの相対パスです。
3. 表情IDは `neutral`、`smile`、`happy`、`shy`、`shy_deep`、`surprised`、`surprised_big`、`worried`、`serious`、`teasing`、`teasing_big` です。差分が届いたら `expressions` に一枚ずつ追加し、未納品のファイルは登録しません。`neutral` だけでもその衣装が使われ、未登録の表情は同じ衣装・ポーズの `neutral` が表示されます。表情の指定にはInkの既存の `emotion` タグを使います。
4. `npm run content:check` を実行します。登録済みファイルの存在、実際の形式・寸法・透過画素、表情や衣装の参照を検証します。これは背景が適切に切り抜かれたことや透過の縁の品質まで保証するものではないため、下記プレビューで目視確認してください。衣装が未納品の場合は基本素材を使い、画像の読み込みに失敗しても会話は続きます。

人物の配置は各人物の `placement`、衣装・ポーズごとの補正は同じポーズの `placement` で設定します。`x`・`bottom`・`width`・`height`・`scale`・`originX`・`originY` を差分間で共有し、画像を歪めずに表示します。既存の `imagePath`、`variants`、敵の `battleCharacters` の設定も使えます。観察用画像と座標は別管理です。

既存の台詞に表情を付ける場合は [`content/presentation/dialogue-expressions.json`](content/presentation/dialogue-expressions.json) に `storyId`・`speaker`・`text`・`emotion` を指定できます。名前などの変数を含まないInk原文の一行を完全一致で登録してください。台詞に既存の `emotion` タグがある場合はその指定を使い、同じ行への重複指定はしません。`npm run content:check` は登録された検証条件の分岐で、話者・台詞の存在や表情ID・タグとの競合を検証します。脚本を変更した際は、未検証の分岐も含めて編集者が表情とタグの対応を確認してください。表情指定は表示だけに使い、保存した会話位置や好感度を変更しません。Ink自体を編集する場合は、途中セーブの指紋に影響する点に注意してください。

`heroine` の `defaultCostume` と `defaultPose` が地域に属さない基本衣装とポーズです。`wardrobe` の `cities`・`countries`・`regions` では、将来の都市から国・地域・標準衣装を指定できます。既存の `milano` → `IT` → `south_europe` → `south_europe_01` 設定は維持していますが、南欧衣装は未納品のため、現在は基本衣装を表示します。個別指定の優先順位は `scenes`、都市、国、地域の標準衣装、基本衣装、仮素材の順です。`scenes` のキーには既存のデートID、バトルID、観光地ID、都市エピローグのエピソードIDを使い、例えば `"milano_cafe_01": { "costume": "south_europe_01", "pose": "standing_01" }` と登録します。未納品の衣装から別の表情だけ別衣装に切り替わることはありません。

現在のゲームはミラノ単独の都市データを読み込み、デートでは既存の章IDを都市IDとして扱います。将来ほかの都市を追加する際は、都市データの読み込み・検証と、デートの章と都市の対応も拡張する必要があります。

素材の確認は `npm run dev` を起動し、表示されたURLに `?character-preview` を付けて開きます。衣装・ポーズ・表情、明暗背景、台詞枠を切り替え、基準線と見比べながら差分の顔や足元、透過の縁を確認できます。「全体を確認」と「ゲーム中の配置」を切り替えて表示範囲を確認できます。未制作の差分と画像の読み込みエラーは区別して表示します。プレビューは開発サーバー専用で、ゲームのセーブやAPには触れません。

会話用の背景画像は [`content/romance/presentation.json`](content/romance/presentation.json) の各背景に任意の `imagePath`（`public/assets/` 以下のパス）を追加して差し替えます。未登録・読込失敗時は既存の仮背景を表示し、観察用画像には影響しません。会話窓の色・透明度・角丸・余白・文字サイズなどは [`romance-scene.css`](src/features/romance/romance-scene.css) 冒頭の `--vn-*` でまとめて調整できます。背景・人物・テーマ・ウィンドウ表示は進行中のInkやクイズの指紋を変更しません。

会話・選択肢・戦闘画面はPlaywrightのChromiumで360×780、430×932、1280×800、横向き780×360を確認しています。長い英文や対訳は縦にスクロールして読めます。実機Safariでは未確認です。

スマートフォンの縦画面では会話・戦闘を画面内に収め、長い台詞や対訳だけをその欄の中でスクロールできます。観察では画像の操作とバトルへの入口を近くに配置しています。横向きや高さの小さい画面では、内容を切らないよう必要に応じてページをスクロールします。

通常デートは一度完了すると再選択できず、終了後は自由時間に戻ります。思い出の一覧は表示しませんが、後の会話に使う記録は保存されます。旧版で再鑑賞を開始済みのセーブは途中の会話を再開でき、APや関係状態・思い出が重複しません。交際状態は保存され、到達後も観光・バトル・未読の都市エピローグ・未体験の通常デートを楽しめます。

現在の観光クイズの編集上の棚卸しは [編集メモ](authoring/quiz-editorial-review.md)、未採用の小話候補は [下書き](authoring/drafts/) にあります。候補はゲームに読み込まれず、史実の最終確認や公開承認を示すものではありません。

## コンテンツ制作の始め方（Phase 8）

[制作マニュアル](authoring/CONTENT_GUIDE.md) と [テンプレート](authoring/templates/) に、観光地・発見・クイズ・A/B/C戦・デート・案内・都市進行の正規JSONとInkの編集例があります。直接編集しても、AIが提案した文章を転記しても、同じ形式と検証を使います。`authoring/drafts/` は必要に応じて使える任意の下書き置き場で、ゲームに読み込まれません。採用は通常のGitレビューで行います。

```sh
npm run content:inspect -- content/quizzes/duomo_B1.json
npm run content:inspect -- --type quiz authoring/templates/quiz.json
npm run content:inspect -- --all
npm run content:compat
```

単体検証はJSON構文・型やInkコンパイルを確認します。ファイル間の参照、実行時タグ、画像、報酬条件は `--all` または `npm run content:check` で検証してください。`content:compat` は同梱の既存セーブ例を使う互換テストであり、すべてのプレイヤーの途中データの互換性を保証するものではありません。公開済みIDの変更や、進行中Ink・問題の改稿は保存データに影響し得ます。文章の面白さ、英文の自然さ、史実と画像使用権は人が確認します。

[将来の都市追加手順](authoring/FUTURE_CITIES.md) には、現在の単一都市前提と後続で必要なコード・セーブ対応を記しています。別の都市ファイルを置くだけで複数都市を遊べる状態にはなりません。

## 文章・データの編集

会話の編集元は `content/stories/milano/` の各 `.ink` ファイルです。既存 [`cafe_01.ink`](content/stories/milano/cafe_01.ink) はPhase 1から変更していません。台詞と選択肢をReactに埋め込まず、Inkに置いています。

```ink
# speaker: heroine
「……{player_name}さん。明日の予定、一つだけ書いてもいい？」
```

名前は `player_name` / `heroine_name` をゲーム状態から渡します。新しい恋愛シナリオでは `player_address`（段階に応じた敬称つき呼称）、`romance_stage`、`memory_callback`（過去の思い出）、`confession_ready` も利用できます。AP・段階・告白条件の計算はTypeScript側で行い、Inkには結果だけを渡します。`* [選択肢]`、`->` の合流で短い分岐を編集します。タグは `speaker`（narrator/heroine/player/enemy）、`background`、`emotion`、`effect` に限定。背景・表情はpresentationに登録、effectはeffect_catalogのIDに限定し、文字列をコードとして実行しません。本文タグとInk公式choice tagsの両方を検証・処理します。

新しい通常デートは、InkとJSON定義・効果を追加するだけで既存のメニューと会話画面に表示されます。`kind` は `normal` / `special` / `confession` / `reassurance`。通常は `choiceCount: 2`、無料イベントは必要に応じて0〜2回の3択を設定できます。`effectCount` は各経路で期待する効果数です。`actionLabelJa` もJSONにあり、Reactにイベント固有の文言を追加する必要はありません。

`validationContexts` に関係段階、告白結果、引用するmemoryId、交際状態を指定し、その文脈から全分岐を検証します。告白は成立・保留・拒否の文脈をすべて指定します。通常デートは各文脈9経路、選択機会1回のイベントは各文脈3経路です。

```sh
npm run content:check
```

`inkjs/compiler/Compiler`（公式inkjsのコンパイラ）でコンパイルし、`src/content/generated/stories.json` を生成します。独自Inkパーサー・外部コマンド・.NETの準備は不要です。生成JSONはGit管理せず、手動編集しません。ブラウザには `inkjs` のランタイムを使用します。

`dev` 起動前、`test` 前、`build` 内で必ずコンパイル・検証します。開発サーバー起動中にInkを改稿したら別ターミナルで `npm run content:build` を実行してください。生成JSON変更をViteが反映します。**Ink原稿そのものの自動監視はありません。**

検証はJSONスキーマ、重複ID、章・背景・シナリオ・思い出参照、許可タグ、前提イベントの循環、段階設定、報酬ID重複、シナリオごとの選択数・効果数・告白結果を確認します。壊れたInk・参照切れ・未定義effect・不正JSONはビルド失敗になります。旧 `last_supper_B1.sample.json` は参考サンプルの検証だけに使用し、出題しません。

### クイズ・敵シナリオの編集

新しい通常バトルは、3問入りクイズJSON・Inkを用意し、`content/battles/catalog.json` に登録します。既存の画面を直接編集する必要はありません。クイズの `englishLevel` は A2/B1/B2 を表現でき、現在はB1の7セット（通常4本、B/C各1本、都市ボス1本）です。各問の `difficulty` は easy/medium/hard。選択肢IDと正解IDを一致させ、正解位置に偏りがないか確認してください。

出典は `sources` に公式資料のURL・発行元・タイトル・確認日・根拠文を保存します。`claimType` は documented_fact / interpretation / legend で区別し、学説は断定せず根拠文に明記します。今回は美術館の公式解説 [A powerful theatrical machine](https://cenacolovinciano.org/en/story/a-powerful-theatrical-machine/) と [Backstage](https://cenacolovinciano.org/en/museum/backstage/) を参照しています。プレイヤーには解答後に根拠リンクを表示し、出題前に解説を見せません。

Inkには `battle_scene`（catalogのシーン名）、`answer_correct`（直前の正誤）、`battle_score`（正解数）、設定した名前と `player_address` を渡します。導入・各中間ラウンド後・決着をそれぞれ独立した短いシーンとして `-> END` で閉じます。最終問の反応と勝敗別の結末は決着シーン内で分岐します。クイズの選択・採点はTypeScriptが担当するため、バトルInkには選択肢や恋愛effectを置けません。既存の文字送り・speaker/background/emotionタグを使い、演出を後から加えられる形にしています。

バトル用検証は、通常3問／都市ボス5問・各3択・正解参照・重複ID・語彙・出典・シーン参照に加え、通常戦の13通り、都市ボスの31通りのシーン入力と、特殊戦の追加シーンをInkで最後まで実行します。日本語の導入や証拠提示成功時の台詞が、続く英語の答えを直接教えていないか、史実が正しいかは脚本レビューでも確認してください。クイズも `src/content/generated/quizzes.json` に生成されます。生成物は手動編集しません。

### 特殊戦の追加・編集

バトル定義の `format` は省略時Aです。既存Aのデータとシナリオはそのまま保持しています。Bは `format: "B"` と `reasoning.kind: "contradiction"`、Cは `format: "C"` と `reasoning.kind: "connection"` を設定します。`reasoning` は次の情報だけを持ちます。

- `roundIndex`: 推理を入れる1問の位置（0から数える）。残りは通常3択。
- `caseClueIds`: 手がかり帳へ常時提供する既存の証拠ID（3〜5枚）。観光の `clues` を再利用。
- `correctClueIds`: Bは1枚、Cは異なる2枚。Cは順不同で判定。
- `claimScene` / `successScene` / `failureScene`: 主張・証拠受付・不足点の説明を記したInkシーン。Bだけ `pressScene` も指定。

推理の結論は、同じ `roundIndex` のクイズの `correctOptionId` で指定します。証拠の選択と英語の採点は独立しており、証拠だけで3択に自動回答しません。追加シーンも既存の `battle_scene` で分岐し、`-> END` で閉じます。主張は帳面にも表示されるため、短い日本語にしてください。台詞はInk、証拠・条件はJSON、判定・保存はTypeScript、入力と描画はReactです。

ビルド時に形式と推理種別、証拠枚数・重複・正解の包含、証拠IDと観光地の一致、ラウンド範囲、シーンIDの重複と実行可能性を検証します。正解証拠と結論が論理的に一意かは出典と脚本も照合してください。本編への配置は `content/progression/journey.json` の `storyBattles` に、対決ID、前後のエピソードID、案内文とボタン名を指定します。B/C戦績を完了記録に使い、観光エピソードや報酬を重複登録しません。

### 観光地・発見ポイント・画像の編集

`content/tourism/catalog.json` の `landmarks` に観光地を、`assets` に画像を、`clues` に発見内容を登録します。観光地は都市ID、日本語・英語名、画像アセットID、案内InkのID、既存バトルID、手がかりID一覧を持ちます。追加には都市の `landmarkIdsPlanned` と対応するバトル定義も登録します。React画面の修正は不要です。

`clues[].region` は**画像全体に対する0〜1の相対座標**で、左上の `x` / `y` と `width` / `height` を指定します。画面のpx値は書きません。`kind: "hotspot"` は領域必須、`kind: "document"` は `region: null` とし、技法など画像から直接観察できない知識を資料カードにします。`factId` は安定ID、`relatedQuestionIds` は既存クイズの問題IDです。説明はJSON、人物の台詞はInkに分けます。出典の `claimType` は事実・解釈・学説・伝承を区別し、画面にも区分と根拠を表示します。

観光案内Inkには `player_name` / `heroine_name` / `player_address` を渡します。短い日本語の線形会話として書き、恋愛effectや選択肢を入れません。コンテンツ検証ではID・参照・座標範囲・資料カードとの区別・出典・画像ファイルの形式・案内の実行を確認します。

### エピソード・報酬の編集

`content/progression/journey.json` の `episodes` が順序・観光地・バトルを結び、`entryEpisodeId` が新規開始地点を指定します。`requiredEpisodeIds` で先行エピソードを指定し、循環や参照切れを検証します。通常観光は `kind: "episode"`。都市ボスは `kind: "city_finale"`、`landmarkId: null` で、4観光地を前提にする独立したフィナーレです。架空の5番目の観光地を作りません。

都市ボスのバトル・クイズも `scope: "city_finale"` と都市IDを指定し、`landmarkId: null` にします。クイズは5問、中間シーンは4つ。通常戦の3問・中間2つは維持します。得点上限・ラウンド・結果・保存の整合性は、登録された問題数に照らして判定します。

報酬の条件は `guide_read` / `battle_complete` / `battle_score` / `episode_clear` / `city_clear`。`minScore` は好成績報酬だけに指定します。IDは保存に使うため、公開後に変更しないでください。旧 `chapter_milano_first_clear` は『最後の晩餐』だけの互換報酬として保持し、都市クリアのIDは別にします。章末の短い地の文はこのJSON、人物の台詞はInkに置きます。

フィナーレの `epilogueStoryId` は `milano/city_epilogue`。Inkに名前・呼称・`romance_stage`・`ending_reached` を渡し、恋愛効果や選択肢は許可しません。デート間の固定順序はなく、実体験だけを思い出として参照します。都市クリアと交際状態は別々に記録します。

## 実装とセーブ

- `src/app/` / `src/components/`: 表示・操作・保存後の状態反映。APや好感度の計算はありません。
- `src/domain/game.ts`: デート可否・AP消費・恋愛の選択効果・思い出と告白の進行。
- `src/domain/battle.ts`: 採点・ラウンド・勝敗・戦績、証拠選択・追及・組み合わせ。通常戦の決着時に共通の章進行処理を呼ぶ。
- `src/domain/tourism.ts`: 案内・訪問・発見・バトルとの往復。案内読了時に共通の報酬処理へ通知する。
- `src/domain/chapter.ts`: エピソード順序・解放、都市完了、自由時間、既存章IDとの互換性。
- `src/domain/epilogue.ts`: 都市エピローグの開始・途中保存・読了。
- `src/domain/rewards.ts`: 一度限りのAP獲得、上限を超えた残額、結果画面の報酬記録。
- `src/features/tourism/viewport.ts`: 画像座標・拡大・移動範囲の計算。
- `src/story/`: 公式 `Continue` / `currentChoices` / `ChooseChoiceIndex` とstate JSONを包むアダプタ。
- `src/persistence/`: localStorageアダプタ・保存データ検証・バックアップ。
- `src/content/` / `scripts/`: データ契約・許可タグ・ビルド時検証。

保存キーは旧版と同じ `dreamscape.save.v1`、データ内の `schemaVersion` は **8**。名前・AP・関係状態・思い出・デート履歴・告白と交際状態、進行中のInk、バトル回答と戦績、観光と発見を保持します。旧版にない信頼と恋愛の意識は既存の進行に基づいて移行し、思い出を捏造しません。旧告白・誘いなどの途中データは旧脚本の指紋を検証して再開します。`completedEpisodeIds`、`completedCityIds`、`completedGuideIds`、`pendingApRewards`、`battleRewardReceipt` も維持します。

Phase 6では `activeBattle.reasoning` に主張のシーンID、選択中・提出済みの証拠、追及済みか、推理の状態を保存します。通常戦では `null`。推理中も同じInkの実行位置を保存し、誤った証拠への反応・追及の途中・英語回答の前後から再開できます。選択と提出はリビジョンを検証し、連打で二重採点しません。特殊戦の指紋には証拠データも含め、資料の意味が変わったセーブを勝手に再判定しません。

`completedChapters: ["milano"]` は、既存デートの解放に使う互換用の記録です。Phase 7では最初の観光エピソード完了でもこのトークンを記録しますが、旧4APの受給や都市全体のクリアを意味しません。各観光地・フィナーレは `completedEpisodeIds`、都市全体は `completedCityIds` に分けます。ミラノ都市クリアは4観光地とボスの完了からのみ確定します。

Phase 1〜7は検証してメモリ上で8へ移行し、次の保存操作で書き込みます。名前・APと未受取分・恋愛状態・観光発見・A/B/Cの途中Inkや証拠選択を保持し、旧フラグから残りの観光地や都市クリアを推測しません。旧『最後の晩餐』完了は同じIDのまま残り、新規の観光順序に差し込まれます。以前から訪問・バトル中だった『最後の晩餐』にも再開用の互換アクセスを維持します。

新しい保存項目は `activeEpilogue`、`viewedEpilogueCityIds`、`legacyTrialAvailable`。移行した旅の補助報酬は保持し、新規プレイでは無効です。Phase 1〜4の完了済みバトルに対する未受領の統合報酬は、従来どおりAP残高を変えず保留分へ移します。旧4APの報酬IDがあれば二重に付与しません。

旧恋愛・通常戦・特殊戦・観光のInkとクイズは変更していません。実際の旧実装で作った `tests/fixtures/phase1-saves.json` 〜 `phase6-saves.json` で互換性を検証します。Phase 6には途中の証拠選択・反応、交際済み、保留APを含む26例があります。操作はリビジョンを照合し、保存が成功した後で画面を進めます。

通常バトルから観光へ戻った場合は、同じ観光地の `activeBattle` と `activeTourism` を同時に保持します。観光を開いている間は回答操作を止め、バトルへ戻ると同一の回答・スコア・ヒント・Ink位置を再開します。特殊戦ではケース資料内で画像を確認でき、観光画面への移動は不要です。恋愛会話との同時実行はできません。

Phase 2では解放済みイベントID、告白の保留/成功、交際エンディングの到達を保持します。成立の思い出とエンディングは告白を読み終えた時点で一緒に確定するため、成功反応の途中で更新しても欠落・二重付与しません。古いタブからの上書きも検出してロードを案内します。

破損・未知バージョン・不整合な保存は自動上書きしません。案内画面から明示的に新しく始める場合に限り、元データを `dreamscape.save.v1.backup.<時刻>` に退避します。他アプリの保存データは削除しません。シナリオ更新で進行中のInkとの互換性が失われた場合も元データを保護します。バトルでは問題・正解・シナリオの定義を含む指紋を照合し、更新前の回答を新しい問題で勝手に採点し直しません。観光画像の交換だけでは案内の指紋は変わりません。Phase 1〜6の既存シナリオには対応していますが、任意に改稿したInkの実行位置を移す機能はありません。改稿確認には別ブラウザプロファイルを使うと既存の旅を残せます。保存は端末・ブラウザ・URLのオリジンごとです。

## 検証

```sh
npm run content:check
npm run typecheck
npm run test
npm run build
npx playwright install chromium
npm run test:e2e
```

空のcheckoutでは `npm ci` のあと、生成物を必要とする単独 `typecheck` より先に `content:check` を実行してください。`npm run build` はこの順序を含みます。

単体テストは通常デート各9通りの保存・復元、順不同の選択と3軸・段階の判定、告白の成功/保留/拒否/再挑戦、特別イベントの一度限り実行、AP上限/不足/未解放/連打、完了済み通常デートの再開始防止と旧再鑑賞セーブの継続、旧セーブ移行、破損/未知schema/保存失敗、コンテンツ検証エラーを対象とします。バトルは全27回答経路で各状態の保存・復元、正誤反応、3種の勝敗、ヒント、二重送信、再戦、恋愛状態の不変性を検証します。

PlaywrightはモバイルChromiumで既存カフェ、低好感度からの保留・回復・交際開始、高好感度での成功、過去の思い出・名前変更、旧セーブの途中再開を操作します。バトルは360px幅で0〜3問正解の通しプレイ、ヒント・語彙、回答ロック、反応中の再読込、再戦、Phase 2の交際エンディングからの出入りを操作します。実機Safariでの検証は別途必要です。

観光は拡大・移動・相対座標の単体検証に加え、360px幅のPlaywrightで画像読み込み、タッチ入力によるピンチ・ドラッグ、移動制限、発見と再読み込み、手がかり帳の開閉、観察をスキップしたバトル、途中回答を保持した観光への往復、旧Phase 3セーブを検証します。

統合テストでは、新規ゲームから案内・観察・バトル・章末・APを使うデートまでを仮クリア操作なしで進めます。0問正解から告白までの経路、再戦で初めて得る好成績報酬、初回報酬の再取得不可、上限で保留したAPの受取、観光・バトル・デート途中の再読み込み、旧Phase 1〜6セーブと交際済みセーブの再訪も確認します。

特殊戦のテストは、正しい証拠・無関係な証拠・順不同の組み合わせ、追及と再挑戦、未発見のケース資料、帳面の開閉・画像確認、選択中やInk途中の再読み込み、二重採点防止、AP・恋愛状態の不変性、Phase 5の実セーブ移行を確認します。証拠を揃えても英語3択は別に解答することを検証します。

ミラノ編の通しテストでは、新規ドゥオモ開始・正しい訪問順・4画像と発見・通常12問・ボス5問の勝敗・0問正解の都市クリア・エピローグと新デート・旧セーブでクリア済みの場所を飛ばす進行を確認します。新しい脚本とクイズは作者以外が出典・誤答の一意性・英語・人物の個性・答えの先出しをレビューしています。

恋愛の背景と敵の立ち絵は簡易SVGイラストです。観光画面と証拠帳は上記の実物資料画像を使用しています。フォントはNoto Sans JP / Noto Serif JP（Google Fonts、SIL OFL）を任意取得し、取得できなくてもシステムフォントで動作します。
