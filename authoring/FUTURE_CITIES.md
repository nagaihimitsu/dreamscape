# 都市の追加手順

この文書は、既存の旅行編に都市を加えるときの、都市のデータの登録と、都市の移り方・保存の決まりです。作業の順番（調査・脚本・絵・音・調整・公開）は [新しい都市を1つ足す手引き](NEW_CITY_GUIDE.md) を先に読んでください。旅行編そのものを加える場合は、`npm run journey:new` で見本の編から `content/journeys/<旅行編ID>/` を作る [新しい編を追加する手順](../docs/02_TECH_ARCHITECTURE.md#新しい編を追加する手順) から始め、都市ごとの登録は以下に従います。遊べる最小の旅行編フォルダの例は [見本の編](templates/sample_trip/README.md)（開発・テスト専用）です。

旅行編は独立した新規ゲームです。旅行編ごとのフォルダ `content/journeys/<旅行編ID>/`（フォルダ名は旅行編IDと一致）の `manifest.json` に、旅行編のID、一覧での並び順 `order`（旅行編間で重複不可）、都市の順序、通貨、公開状態と初期値を登録します。ゲームが読む旅行編一覧は `npm run content:build` がすべての `manifest.json` から生成します。ミラノ編とゴールデントライアングル編は別々に保存され、互いの進行や予算を引き継ぎません。インド編はデリー、アーグラ、ジャイプールの3都市に地点・背景・市内移動・観光・デート・シナリオ・クイズを登録済みです。各都市は `complete`、旅行編は `available` とし、ミラノ未クリアでも開始できます。これらはビルド対象の状態であり、サイトのデプロイとは別です。ウズベキスタン編とルアンパパーン編は、引き続き制作基盤のみの `preparing` です。

インド編の地点・交通・入場料・画像の制作調査には、[全調査統合版](journeys/golden_triangle/research/golden-triangle-all-research-20261103/README.md) と、そこに記載された出典の優先順位を参照してください。これは研究台帳であり、本番の経路・イベント・画像カタログではありません。

追加調査と、同じ都市・旅行・設定スキーマで整えた[インド編の制作ドラフト](journeys/golden_triangle/drafts/README.md)も参照できます。ドラフトの生成と追補資料の構造は `npm run india:check` で検証できます。実際に登録するデータは `content/journeys/golden_triangle/cities`・`content/journeys/golden_triangle/travel` を正とし、生成ドラフトを完成済みと見なして自動上書きしないでください。

次の都市への移り方は、旅行編の `manifest.json` の `cityTransition` で決めます。`manual`（書かないときも）はプレイヤーが出発を選びます。`after_epilogue`（インド編）は、次の都市が公開済みなら、各都市のクリア後にエピローグを読み終えると次の都市へ自動で移ります。デリー、アーグラ、ジャイプールはそれぞれ独立した市内マップで、マップ間の経路・交通手段・料金・所要時間は作りません。次都市が未公開の場合や最終都市では現在の都市に滞在します。

## データの登録

1. 該当する旅行編の `content/journeys/<旅行編ID>/manifest.json` の `cities` に一意な都市IDを順に登録します。次の手順で都市の作業用JSONを作成し、検証・反映すると旅行編フォルダに `content/journeys/<旅行編ID>/cities/<都市ID>.json` が作成されます。ファイル名と `id` は一致させ、正式公開時は `productionStatus` を `complete` とします。既存の `milano.json` は変更せず参考にできます。旅行編を公開するときは開始都市のデータと初期予算を確定し、`npm run journey:readiness -- --journey <旅行編ID>` で準備中であること以外の問題がないことを確かめてから、`npm run journey:release -- --check --journey <旅行編ID>`、続けて `--apply` で開始都市を `complete`、旅行編の `status` を `available` にします（[新しい編を追加する手順](../docs/02_TECH_ARCHITECTURE.md#新しい編を追加する手順) の手順9）。`status` を手で書き換えると、`journey:new` で作った旅行編に残る見本の画像・文章の確認（readiness・release）を通らずに公開されてしまいます（見本の出典 example.com が残っていれば `content:build` も止めます）。
2. 滞在先、地点、イベントと地点の対応、都市内の移動経路・費用・時間・営業時間を登録します。[都市別データの編集手順](CITY_BUNDLES.md) を使うと、地点・交通・背景などを都市ごとに１つの作業用JSONでまとめて編集し、検証してから `content/journeys/<旅行編ID>/travel/<都市ID>.json` などの正本に反映できます。地点やイベントのIDは都市をまたいでも重複させません。
3. 旅行編フォルダの `progression/journey.json` に都市ID付きの観光エピソードと都市フィナーレ、特殊戦、固有の報酬を追加します。その都市の最初のエピソードを先に、フィナーレを最後に置きます。フィナーレは同じ都市の観光を条件にし、特殊戦の完了もその都市内で判定します。ミラノの報酬IDを再利用しないでください。
4. 旅行編フォルダ `content/journeys/<旅行編ID>/` の `tourism/catalog.json`、`battles/catalog.json`、`quizzes/`、`romance/date_catalog.json` と `date_destinations.json`、`encounters/catalog.json` に必要な内容を追加します（`content/` 直下と同じ相対パス。ファイルが無ければ作成し、ビルド時に共通データと統合されます）。項目は自分の旅行編の都市だけを扱い、参照先は同じ旅行編か共通データに限ります。各観光地・バトル・クイズ・デート・交流・品物の所属と参照先を揃えます。会話のInk、対訳、演出や画像なども必要に応じて登録してください（その旅行編だけが使う画像は `content/journeys/<旅行編ID>/public/assets/` に、配信時と同じ相対パスで置きます）。
5. 移行元の都市に `nextCityId` を設定し、同じ旅行編で次の順序にある登録済み都市を参照させます。移行先は `complete` の都市か、`manifest.json` で次の順にある制作中（`prototype`）の都市に限り（制作中の都市へは、公開されるまで出発できません）、存在しない都市や循環、旅行編をまたぐ接続は検証で拒否されます。インド編では都市間の交通手段を作らず、`intercityModes` は空配列にします。各都市の `travel` の経路は、その都市のマップに属する地点間だけに登録します。
6. `npm run content:check`、`npm run typecheck`、`npm test`、`npm run build` を実行し、変更に応じた画面操作も確認します。`content:check` は差分だけでなく全コンテンツを検証・生成します。Debugでは登録済み都市を選んで観光・戦闘・交流・デートを確認できます。詳しくは [開発時の確認](../docs/10_DEVELOPMENT_CHECKS.md) を参照してください。

各地点に同じ場所の観光とデートを紐付けられます。ゲームの正本に保存される経路は、出発地・到着地・交通手段を区別した片道データです。都市別の作業用JSONでは、両方向の内容が同じと確認した経路を１回だけ記入することもできます。異なる場合はそれぞれの方向に登録し、片道を勝手に反転しないでください。座標は方角表示に利用し、直線距離から徒歩時間を実測値として生成しません。出典・調査日・推計値とゲーム内調整値を区別し、帰路も確認してください。

ゴールデントライアングル編はゲーム用暫定設定として、初期予算 ₹38,000（いちばん安い乗り物で回れば、本筋もデートも全部の費用を払える額）、宿泊無料、各都市のクリア報酬4APを `content/journeys/golden_triangle/manifest.json` に登録しています。正式な都市の宿泊設定はこの値と一致させ、`content/journeys/golden_triangle/progression/journey.json` のその都市のフィナーレに `city_clear` の4AP報酬を一つ登録してください。ビルド時に整合性を検査します。都市定義の `firstClearReward` は既存の観光エピソード用の旧互換報酬であり、都市クリア報酬ではありません。資料の同名フィールドを都市クリア報酬としてそのまま移さないでください。

インドの各都市にはメイン観光4件・デート8件（行き先のある6件と、宿の屋上の告白・「待って」の後の2件。ジャイプールには彼女の返事も）と、5問の都市フィナーレ・エピローグを実装しています。フィナーレは同都市の4観光の完了で解放し、デートや交際は条件にしません。今のインド編は、場所のファイル40本・クイズ15本（51問）です。下書きの構成と出典は [制作記録](journeys/golden_triangle/drafts/scenario/README.md) を参照してください。今後追加する都市でも、件数の設定だけで未執筆イベントを完成扱いにせず、実ファイルと参照を検証してから登録します。

営業時間の `openingWindows` は到着時の入場、イベントの `endWindows` は活動終了時刻を判定します。ゲーム内の行動・帰路は9:00〜21:00、夜は18:00からです。地点の `closedWeekdays` はゲーム内の休館曜日（0=月曜、6=日曜）を設定します。インド編の初日は仮の月曜日で、現実の日付とは対応しません。宿泊で曜日が進みます。都市間移動では次の都市が次の朝から始まり（2026-11-13のユーザー判断。時計が戻らないように）、旅の日と曜日が1つ進み、都市の日数は1日目に戻ります。曜日によって営業時間帯そのものが変わる場合や祝日などはまだ表せません。

イベントの `admissionCost` は旅行編の通貨による2人分のゲーム内入場料です。省略すると無料で、イベント開始時に交通費とともに支払い、帰路の費用は別途確保します。同一地点で別のイベントを行う場合も、それぞれのイベントに設定された金額を支払うゲーム仕様です。経路の `estimation: "game_model"` は直線距離モデルなどゲーム用推定を示し、画面にも推定と表示します。現実の運賃や入場料と混同せず、未調査の料金を実測値として登録しないでください。

## 都市の移行と保存

移行時は進行中の会話・観光・バトル・デート・交流を中断しません。共通基盤ではプレイヤーが出発を選び、インド編では次都市が公開済みなら都市クリア後のエピローグ読了時に自動移行します。名前、AP・保留AP、旅行予算、関係値、思い出、報酬とイベントの履歴を引き継ぎます。新都市で予算を再付与せず、現在地は新都市の滞在先、時刻は次の朝の9:00（都市の1日目。暦のある旅では旅の日と曜日が1つ進む）にします。

所持品は所属都市でのみ使えます。移行時に未使用品を置いていきますが、入手・使用などの履歴は保持します。旅の間持ち歩く品物（`"carry": "journey"`）だけは、持ったまま次の都市へ行き、後の都市でも渡せる・使えます（[CONTENT_GUIDE の「道中の交流」](CONTENT_GUIDE.md#道中の交流)）。任意出発の都市では、移行前に品物を使えます。新都市を追加する際は、他都市のイベントや品物を直接使用できないこと、移行前後の保存・再開と別タブ競合も確認してください。

どの旅行編も、同じ保存先を複数タブで同時編集しないよう、画面を開いている間 Web Locks を使います。対応していないブラウザでは編集できません。以前のバージョンのタブはこの排他に参加しないため、更新時には古いタブを閉じてください。Debug の仮都市・仮地点・仮経路は開発と試験だけに使用し、本番データには含めません。

ゲーム内の内容・位置・交通・営業時間・画像の利用条件は制作時に確認します。自動検証は文章の面白さ、英語の自然さ、史実や使用権の最終判断を代替しません。開発中は旧セーブの自動移行を保証せず、読み込めないデータは勝手に消去・上書きしません。

## 旅行編ごとのシナリオ取り込み

インド・ウズベキスタン・ルアンパパーンと、`journey:new` で作った旅行編は、共通の `journey:scaffold`・`journey:readiness`・`journey:release` を利用する（`manifest.json` に `authoring` がないミラノ編は対象外）。都市数はカタログから取得し、3都市には固定しない。具体的な入力手順は [JOURNEY_AUTHORING](JOURNEY_AUTHORING.md) を参照。都市間の移動方式は旅行編の `cityTransition`、料金の対象人数は `farePartySize` で指定する。未指定の移動方式は従来どおり任意出発。
