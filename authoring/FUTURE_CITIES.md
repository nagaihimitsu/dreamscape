# 都市の追加手順

旅行編は独立した新規ゲームです。`content/journeys/catalog.json` に旅行編のID、都市の順序、通貨、公開状態と初期値を登録します。ミラノ編とゴールデントライアングル編は別々に保存され、互いの進行や予算を引き継ぎません。インド編はデリー、アーグラ、ジャイプールの3都市に地点・背景・市内移動・観光・デート・シナリオ・クイズを登録済みです。各都市は `complete`、旅行編は `available` とし、ミラノ未クリアでも開始できます。これらはビルド対象の状態であり、サイトのデプロイとは別です。ウズベキスタン編は引き続き制作基盤のみの `preparing` です。

インド編の地点・交通・入場料・画像の制作調査には、[全調査統合版](research/golden-triangle-all-research-20261103/README.md) と、そこに記載された出典の優先順位を参照してください。これは研究台帳であり、本番の経路・イベント・画像カタログではありません。

追加調査と、同じ都市・旅行・設定スキーマで整えた[インド編の制作ドラフト](drafts/golden-triangle/README.md)も参照できます。ドラフトの生成と追補資料の構造は `npm run india:check` で検証できます。実際に登録するデータは `content/cities`・`content/travel` を正とし、生成ドラフトを完成済みと見なして自動上書きしないでください。

共通基盤では、本番に登録された次都市に任意で出発できます。インド編は別の方針で、次都市が公開済みの場合、各都市のクリア後にエピローグを読み終えると次都市へ自動移行します。デリー、アーグラ、ジャイプールはそれぞれ独立した市内マップで、マップ間の経路・交通手段・料金・所要時間は作りません。次都市が未公開の場合や最終都市では現在の都市に滞在します。

## データの登録

1. `content/journeys/catalog.json` の該当する旅行編に一意な都市IDを順に登録します。次の手順で都市の作業用JSONを作成し、検証・反映すると `content/cities/<都市ID>.json` が作成されます。ファイル名と `id` は一致させ、正式公開時は `productionStatus` を `complete` とします。既存の `milano.json` は変更せず参考にできます。旅行編を公開するときは開始都市のデータと初期予算を確定し、旅行編の `status` を `available` に変更します。
2. 滞在先、地点、イベントと地点の対応、都市内の移動経路・費用・時間・営業時間を登録します。[都市別データの編集手順](CITY_BUNDLES.md) を使うと、地点・交通・背景などを都市ごとに１つの作業用JSONでまとめて編集し、検証してから `content/travel/<都市ID>.json` などの正本に反映できます。地点やイベントのIDは都市をまたいでも重複させません。
3. `content/progression/journey.json` に都市ID付きの観光エピソードと都市フィナーレ、特殊戦、固有の報酬を追加します。その都市の最初のエピソードを先に、フィナーレを最後に置きます。フィナーレは同じ都市の観光を条件にし、特殊戦の完了もその都市内で判定します。ミラノの報酬IDを再利用しないでください。
4. 既存の `content/tourism/catalog.json`、`content/battles/catalog.json`、`content/quizzes/`、`content/romance/date_catalog.json` と `date_destinations.json`、`content/encounters/catalog.json` に必要な内容を追加します。各観光地・バトル・クイズ・デート・交流・品物の所属と参照先を揃えます。会話のInk、対訳、演出や画像なども必要に応じて登録してください。
5. 移行元の都市に `nextCityId` を設定し、同じ旅行編で次の順序にある登録済み都市を参照させます。移行先は `complete` の都市に限り、存在しない都市や循環、旅行編をまたぐ接続は検証で拒否されます。インド編では都市間の交通手段を作らず、`intercityModes` は空配列にします。各都市の `travel` の経路は、その都市のマップに属する地点間だけに登録します。
6. `npm run content:check`、`npm run typecheck`、`npm test`、`npm run build` を実行し、変更に応じた画面操作も確認します。`content:check` は差分だけでなく全コンテンツを検証・生成します。Debugでは登録済み都市を選んで観光・戦闘・交流・デートを確認できます。詳しくは [開発時の確認](../docs/10_DEVELOPMENT_CHECKS.md) を参照してください。

各地点に同じ場所の観光とデートを紐付けられます。ゲームの正本に保存される経路は、出発地・到着地・交通手段を区別した片道データです。都市別の作業用JSONでは、両方向の内容が同じと確認した経路を１回だけ記入することもできます。異なる場合はそれぞれの方向に登録し、片道を勝手に反転しないでください。座標は方角表示に利用し、直線距離から徒歩時間を実測値として生成しません。出典・調査日・推計値とゲーム内調整値を区別し、帰路も確認してください。

ゴールデントライアングル編はゲーム用暫定設定として、初期予算 ₹30,000、宿泊無料、各都市のクリア報酬4APを `content/journeys/catalog.json` に登録しています。正式な都市の宿泊設定はこの値と一致させ、`content/progression/journey.json` のその都市のフィナーレに `city_clear` の4AP報酬を一つ登録してください。ビルド時に整合性を検査します。都市定義の `firstClearReward` は既存の観光エピソード用の旧互換報酬であり、都市クリア報酬ではありません。資料の同名フィールドを都市クリア報酬としてそのまま移さないでください。

インドの各都市にはメイン観光4件・デート6件と、5問の都市フィナーレ・エピローグを実装しています。フィナーレは同都市の4観光の完了で解放し、デートや交際は条件にしません。脚本48本・クイズ51問の構成と出典は [制作記録](drafts/golden-triangle/scenario/README.md) を参照してください。今後追加する都市でも、件数の設定だけで未執筆イベントを完成扱いにせず、実ファイルと参照を検証してから登録します。

営業時間の `openingWindows` は到着時の入場、イベントの `endWindows` は活動終了時刻を判定します。ゲーム内の行動・帰路は9:00〜21:00、夜は18:00からです。地点の `closedWeekdays` はゲーム内の休館曜日（0=月曜、6=日曜）を設定します。インド編の初日は仮の月曜日で、現実の日付とは対応しません。宿泊で曜日が進み、都市間移動では都市の日数だけ1日目に戻ります。曜日によって営業時間帯そのものが変わる場合や祝日などはまだ表せません。

イベントの `admissionCost` は旅行編の通貨による2人分のゲーム内入場料です。省略すると無料で、イベント開始時に交通費とともに支払い、帰路の費用は別途確保します。同一地点で別のイベントを行う場合も、それぞれのイベントに設定された金額を支払うゲーム仕様です。経路の `estimation: "game_model"` は直線距離モデルなどゲーム用推定を示し、画面にも推定と表示します。現実の運賃や入場料と混同せず、未調査の料金を実測値として登録しないでください。

## 都市の移行と保存

移行時は進行中の会話・観光・バトル・デート・交流を中断しません。共通基盤ではプレイヤーが出発を選び、インド編では次都市が公開済みなら都市クリア後のエピローグ読了時に自動移行します。名前、AP・保留AP、旅行予算、関係値、思い出、報酬とイベントの履歴を引き継ぎます。新都市で予算を再付与せず、日数と現在地は新都市の滞在先の1日目9:00に戻します。

所持品は所属都市でのみ使えます。移行時に未使用品を置いていきますが、入手・使用などの履歴は保持します。任意出発の都市では、移行前に品物を使えます。新都市を追加する際は、他都市のイベントや品物を直接使用できないこと、移行前後の保存・再開と別タブ競合も確認してください。

インド編では同じ保存先を複数タブで同時編集しないよう、画面を開いている間 Web Locks を使います。対応していないブラウザでは編集できません。以前のバージョンのタブはこの排他に参加しないため、更新時には古いタブを閉じてください。Debug の仮都市・仮地点・仮経路は開発と試験だけに使用し、本番データには含めません。

ゲーム内の内容・位置・交通・営業時間・画像の利用条件は制作時に確認します。自動検証は文章の面白さ、英語の自然さ、史実や使用権の最終判断を代替しません。開発中は旧セーブの自動移行を保証せず、読み込めないデータは勝手に消去・上書きしません。

## 旅行編ごとのシナリオ取り込み

インドとウズベキスタンは共通の `journey:scaffold`・`journey:readiness`・`journey:release` を利用する。都市数はカタログから取得し、3都市には固定しない。具体的な入力手順は [JOURNEY_AUTHORING](JOURNEY_AUTHORING.md) を参照。都市間の移動方式は旅行編の `cityTransition`、料金の対象人数は `farePartySize` で指定する。未指定の移動方式は従来どおり任意出発。
