# 都市の追加手順

ミラノが最初の都市です。本番に登録された次都市がある場合、都市クリア後に任意で出発できます。都市クリアやエピローグの読了だけでは出発せず、残りのデートも楽しめます。出発後の都市間往復、航空券や都市間の交通費・所要時間は扱いません。

## データの登録

1. 一意な都市IDを決め、`content/cities/<都市ID>.json` を追加します。ファイル名と `id` は一致させ、正式公開時は `productionStatus` を `complete` とします。既存の `milano.json` は変更せず参考にできます。
2. `content/travel/<都市ID>.json` と `<都市ID>-settings.json` に、滞在先、地点、イベントと地点の対応、移動経路、費用、時間、営業時間を登録します。地点やイベントのIDは都市をまたいでも重複させません。各地点の背景は既存の `content/romance/presentation.json` に登録します。
3. `content/progression/journey.json` に都市ID付きの観光エピソードと都市フィナーレ、特殊戦、固有の報酬を追加します。その都市の最初のエピソードを先に、フィナーレを最後に置きます。フィナーレは同じ都市の観光を条件にし、特殊戦の完了もその都市内で判定します。ミラノの報酬IDを再利用しないでください。
4. 既存の `content/tourism/catalog.json`、`content/battles/catalog.json`、`content/quizzes/`、`content/romance/date_catalog.json` と `date_destinations.json`、`content/encounters/catalog.json` に必要な内容を追加します。各観光地・バトル・クイズ・デート・交流・品物の所属と参照先を揃えます。会話のInk、対訳、演出や画像なども必要に応じて登録してください。
5. 出発元の都市に `nextCityId` を設定し、登録済みの次都市を参照させます。移動先は `complete` の都市に限り、存在しない都市や循環は検証で拒否されます。次都市を登録しない間、本番画面に出発ボタンは出ません。
6. `npm run content:check`、`npm run typecheck`、`npm test`、`npm run build` を実行し、変更に応じた画面操作も確認します。`content:check` は差分だけでなく全コンテンツを検証・生成します。Debugでは登録済み都市を選んで観光・戦闘・交流・デートを確認できます。詳しくは [開発時の確認](../docs/10_DEVELOPMENT_CHECKS.md) を参照してください。

各地点に同じ場所の観光とデートを紐付けられます。経路は出発地・到着地・交通手段を区別した片道データです。逆方向は自動生成されないため、必要な方向をそれぞれ登録します。座標は方角表示に利用し、直線距離から徒歩時間を実測値として生成しません。出典・調査日・推計値とゲーム内調整値を区別し、帰路も確認してください。

営業時間の `openingWindows` は到着時の入場、イベントの `endWindows` は活動終了時刻を判定します。ゲーム内の行動・帰路は9:00〜21:00、夜は18:00からです。曜日別の営業時間には対応していません。費用は整数ユーロで管理し、現実の端数運賃とゲーム内採用額を区別します。

## 出発と保存

出発は進行中の会話・観光・バトル・デート・交流がないときに、プレイヤーが選択します。名前、AP・保留AP、旅行予算、関係値、思い出、報酬とイベントの履歴を引き継ぎます。新都市で予算を再付与せず、日数と現在地は新都市の滞在先の1日目9:00に戻します。

所持品は所属都市でのみ使えます。出発時に未使用品を置いていきますが、入手・使用などの履歴は保持します。都市クリア後も出発前なら品物を使えます。新都市を追加する際は、他都市のイベントや品物を直接使用できないこと、出発前後の保存・再開と別タブ競合も確認してください。

ゲーム内の内容・位置・交通・営業時間・画像の利用条件は制作時に確認します。自動検証は文章の面白さ、英語の自然さ、史実や使用権の最終判断を代替しません。開発中は旧セーブの自動移行を保証せず、読み込めないデータは勝手に消去・上書きしません。
