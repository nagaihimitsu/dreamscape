# インド編の公共交通調査

> 記録の注記：本文のパス・コマンドは作成当時の配置のままです。現在、この旅行編のデータは `content/journeys/golden_triangle/`、制作資料は `authoring/journeys/golden_triangle/` にあります（[旧配置との対応表](../../../README.md#当時の配置と現在の配置)）。

デリー、アーグラ、ジャイプールの地点間について、地下鉄・鉄道（`rail`）とバス（`bus`）を片道ずつ区別して確認します。同じ地点への移動は対象外です。都市ごとの調査内容と出典は `delhi.md`、`agra.md`、`jaipur.md` を参照してください。

次のコマンドは `content/travel/<都市ID>.json` の実際の経路と `decisions.json` を照合し、登録済み・確認済み不採用・調査したが特定できず・未調査を数えます。`--json` を付けると全地点・全方向・交通手段ごとの状態を出力します。

```sh
npx tsx scripts/inspect-india-transit.ts
npx tsx scripts/inspect-india-transit.ts --json
```

- `available`: 現在のゲームにその方向と交通手段の経路が登録されています。所要時間・運賃は `content/travel/<都市ID>.json` が正本です。ゲーム用推定値であり、実際の運行や時刻を保証しません。運賃は２人分です。
- `not_suitable`: 調査した候補について、今回のゲームでは採用しないと判断しました。根拠と判断理由を `decisions.json` に記録します。現実の路線が存在しない、または将来も利用できないという主張ではありません。
- `inconclusive`: 資料を調べましたが、適切な経路を特定できませんでした。確認した資料と結果を記録します。サービスがないという意味ではありません。
- `unresearched`: その組み合わせはまだ調査結果を記録していません。サービスが存在しない、採用に適さない、という意味ではありません。

実際の経路を追加するときは、既存 `routes` に都市内の `fromPlaceId`、`toPlaceId`、`mode`、時間、２人分の費用、`estimation: "game_model"` と出典を入れます。実在路線などの `documented_fact` と、ゲーム時間・料金についての `hypothesis` を少なくとも１件ずつ指定します。方向ごとに記録し、帰路を自動生成しません。路線の存在だけで各地点へのアクセスが確認できるとは限りません。

確認済みの候補を不採用にする場合、`decisions.json` に `{ cityId, fromPlaceId, toPlaceId, mode, status: "not_suitable", checkedAt, reasonJa, sources }` を追加します。資料を確認したものの経路を特定できない場合は `status: "inconclusive"` とし、確認した内容を理由に記載します。`sources` は既存の観光出典と同じ形式で、HTTPS URL・確認日・日本語の主張を含む資料を指定し、少なくとも１件は `documented_fact` とします。未記入の組み合わせは自動的に `unresearched` として表に現れます。

登録済み経路と不採用の判断が重なった場合、同じ判断を二重に記録した場合、都市外の地点を指定した場合は検証エラーになります。地図上の近さや直線距離のみから徒歩アクセスや路線の存在を断定しないでください。

経路の時間・料金、乗換設定、地点を変更した場合は、その経路を比較対象にした `decisions.json` の判断と各都市の調査メモも再確認してください。理由中の比較値は調査時点の記録であり、検証スクリプトは文章中の数値を自動再計算しません。路線の現行運行や乗降地点も必要に応じて再調査し、根拠と確認日を更新したうえで上記コマンドを実行します。

`not_suitable` はゲームにその手段を追加しないという編集上の決定を示します。調査した具体的候補を比較し、別の現実の便については存在や運行を確認できていない場合もあります。現実の運行が未確認であることは、各判断の理由と出典に残します。したがって未判断の数が０であっても、現実の交通や運賃をすべて確認したという意味ではありません。
