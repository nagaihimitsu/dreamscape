## ゲーム用の設定

- 初期資金：4,000,000 UZS。実旅行の予算見積りではなく、登録した二人分の入場・交通費に余裕を持たせるゲーム用暫定値。
- 宿泊無料、都市クリア4AP。通常観光の報酬は案内・初完了・初好成績・エピソードクリア各1AP。
- ミラノ・インドの記録とは独立した新規ゲーム。準備中でも名前だけを別の保存領域へ記録できる。
- 各都市のクリアとエピローグ読了後、次の公開済み都市へ自動で進む。別都市への地図上の移動、鉄道切符購入、長距離運賃は実装しない。
- 都市間ではAP・保留AP・予算・関係値・思い出・履歴を維持し、都市固有の未使用品は取得履歴を残して利用不能にする。次都市で予算は再支給しない。
- 最終都市または未公開の次都市には進まず、現在都市に滞在する。

## 調査と実装の区別

地点座標は資料の代表点です。徒歩時間は道路・街区・門・歩行接続を踏まえたゲーム用の分数で、直線距離を実測値として扱っていません。タクシー時間・料金、公共交通の待ち時間や徒歩アクセスもゲーム値を含みます。現地の運行時間、通行許可、ゲート、料金の保証ではありません。

公共交通の路線・運賃情報は公式資料と二次資料を確認しました。出典の日付・対象・矛盾・採否は各都市のREADMEと台帳に記録しています。短い旧市街の徒歩区間では、サービスの実在を確認しても候補として採用しない場合があります。

`transit-decisions.json` は各都市110方向×4手段（bus・rail・tram・taxi）の判断を保持します。

- `available`：ゲームの移動候補として採用し、対応する経路あり。
- `not_suitable`：今回の地点間の移動には不適合／徒歩や他手段を優先。都市全域にサービスがないという意味ではない。
- `not_applicable`：対象区間でその交通方式を利用する設定に該当しない。
- `unconfirmed`：根拠や判断が未確定。残っている場合は検査を失敗させる。

各都市の出典と写真の詳細： [タシュケント](tashkent/README.md)、[サマルカンド](samarkand/README.md)、[ブハラ](bukhara/README.md)、[ヒヴァ](khiva/README.md)。画像ファイルの撮影者・ライセンス・加工内容は `content/tourism/catalog.json` にも登録します。

## 正本と今後の編集

実行時の正本は `content/cities/`、`content/travel/` と既存の画像・背景・行き先カタログです。都市単位の編集には [city:bundle](../../../../CITY_BUNDLES.md) を使ってください。調査フォルダの `catalog-fragments.json` や組み立てスクリプトは初回取り込み記録であり、正本を継続的に上書きする同期元ではありません。交通判断台帳と `authoring/drafts/uzbekistan/observation-cards.json` は編集・検証時に参照する現行の資料です。

残る制作物と取り込みコマンドは [共通のシナリオ取り込み手順](../../../../JOURNEY_AUTHORING.md) にまとめています。シナリオ制作には案内・対決・デート・フィナーレ・エピローグのInkと題名・紹介・人物・思い出のメタデータを含み、クイズには和訳も含みます。B/Cは舞台と問いをこの段階で決めます。
