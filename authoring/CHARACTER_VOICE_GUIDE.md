# 人物の声の作り方（ヒロイン以外の人物の配役と依頼書）

ヒロイン以外の人物の台詞に声を付けるときの手順です。人物ごとに声のモデルを選び（配役）、声を作る人に渡す依頼書を作り、届いた声をゲームに入れるまでを書きます。

- 元にしたのは、インド編（`golden_triangle`）の 2026-11-17 の配役です。69人・703行を配役し、依頼書を2つ作りました（[声の記録の「2026-11-17_cast/」](journeys/golden_triangle/voice/README.md#2026-11-17_cast)）。
- ヒロインの声の頼み方・受け取り方と、道具の細かい決まりは [発注マニュアル](ORDERING_MANUAL.md) の3〜4章にあります（ヒロイン以外の人物は [3.6](ORDERING_MANUAL.md#36-ヒロイン以外の人物の声配役と依頼書)）。
- 決まりの元は [AGENTS.md](../AGENTS.md) です。この手引きと食い違うときは、そちらに従います。
- 書き方は発注マニュアルと同じです：`<旅行編>` は `content/journeys/<旅行編ID>/`、`<制作資料>` は `authoring/journeys/<旅行編ID>/`。

## 1. 声を付ける人物

- 地の文と主人公を除く、台詞のある全員です（`npm run voice:script` が抜き出す人物）。主人公には声を付けません。ヒロインは別の手順です（[発注マニュアルの3章](ORDERING_MANUAL.md#3-声を頼む)）。
- 人物は `entries.json` の `voice` で分けます。人物の `characterId`（同じ人の別の人物 ID、例えば名前が分かる前の「男」も同じ声）、バトルの相手、場面の頭の `# person:` から決まります（[発注マニュアルの 3.2](ORDERING_MANUAL.md#32-頼む行)）。
- 1行しか話さない人にも声を付けます。インド編の69人のうち、14人は1行、34人は6行以下です。
- メッセージ（携帯の吹き出し）とメモ・手紙の行は、声を付けません。

## 2. ① 人物の特徴を決める

作者の10の特徴を、人物ごとに決めます。

| 特徴 | 書くこと |
| --- | --- |
| 年齢 | 台詞や地の文から分かる年。分からなければ「推定」と書く |
| 性別 | |
| 体型・身体的特徴 | 立ち絵・地の文から |
| 顔立ち・外見 | 立ち絵・地の文から |
| 性格 | 台詞の中身・話し方から |
| 声の高さ | 高い・中くらい・低い。ヒロイン（インド編は約245Hz）や同じ場面の人とどう違うか |
| 声質・質感 | 乾いた・太い・柔らかい など |
| 話す速度 | ふだんの速さと、速さが変わる場面 |
| 話し方・抑揚 | 語尾・一人称・言い方の癖。場面による変化 |
| 出身地・言語・アクセント | どこの人か、ふだん何語か。ゲームでは日本語の吹き替えとして自然な標準語で読む、外国なまりのまねはしない、などの読み方の決まりもここに |

- **根拠を書きます。** 台本（台詞・地の文）、立ち絵、データ（`progression/story.json` の人物、`battles/catalog.json`）から決めます。根拠がない所は「推定」「未確認」と書きます。作らないことです。
- 配役に使うものも一緒に決めます：目標の高さ（Hz の範囲）、必要なこと（例：「老女らしい年齢感」）、避けること（例：「ヒロインに近い高さ」）、同じ場面に出る人物（聞き分けのため）、作る人への読み方の注意。
- インド編の例：[profiles/](journeys/golden_triangle/voice/casting-2026-11-17/profiles/)（69人の10の特徴・配役に使うもの・根拠）。

## 3. ① モデルを選ぶ

### 3.1 選ぶ先

- **AivisHub のモデル**（AivisSpeech で読む）：作者が示した一覧 https://hub.aivis-project.com/search?sort=download&tiers=Official&tiers=Community&page=1 （ダウンロード順、Official と Community）。
- **VOICEVOX のキャラクター**：https://voicevox.hiroshiba.jp の各キャラクター。
- 2026-11-17 に、両方を一覧にしました（AivisHub 77件、VOICEVOX 44人。説明・スタイル・声の高さ・規約）：[voice-models-2026-11-17/](research/voice-models-2026-11-17/README.md)。次の旅行編でも使えます。古くなったら、その README の「作り直し方」で作り直します。

### 3.2 1つの旅行編の中では、1人に1つのモデル

- 作者の決まり：「モデルは、各編の中では被らないように(編が異なれば被っても良い)」。
- **同じ人の声のモデルは、1つと数えます。** AivisHub には、同じ声優・同じ人の声から作ったモデルが別々に載っていることがあります（例：まお と コハク）。`cast.json` では、そのモデルに同じ `voiceGroup` を書きます。
- **例外（作者の判断 D1）**：「1〜6行の人には重複を認める。ただし、そのストーリー内では重複してはいけない」。
  - ストーリーは、`<旅行編>/stories/` の同じ Ink ファイルです（例：`places/gt_delhi_red_fort.ink` の案内・クイズ・デートは、全部で1つのストーリー）。
  - 7行以上の人物は、旅行編の中で自分だけのモデルにします。そのモデルを、別のストーリーの1〜6行の人物が使うのはかまいません。
  - 行数は、その人物の旅行編の中の台詞の数です（依頼書の「台詞：全部で N行」）。
  - `npm run voice:script` が確かめます（6 は `scripts/voice-cast.ts` の `SHARED_MODEL_MAX_LINES`）。
- 同じモデルを2人に使うときは、設定（話速・音高など）を人物ごとに分けます。2人が別の人に聞こえるかは、届いてから聞いて確かめます（5章）。

### 3.3 権利

**作者の判断 D2「営利にはしない」**（2026-11-17）。このため、営利でなければ使えるモデルも使えます。

- 使えるようになったもの：AivisHub の ACML-NC 1.0 のモデル、kuroike ai のモデル（独自の「ACML-NC 1.1」。本文を読んでから）、VOICEVOX の暁記ミタマ・No.7・Voidoll・ユーレイちゃん・ぞん子（個人・非商用・同人の利用を許すもの）。どれも、使う前にそのモデルの規約の本文を読みます。
- 引き続き使わないもの：
  - 後鬼・もち子さん・里石ユカ（別の人物の声に使えない）
  - ナースロボ＿タイプＴ（AIで作った絵に声を当てられない）
  - AI Maid のモデル（ヒロインの声の合成音声で学習している）
  - 宗周定昌（声の出所が分からない）
  - RakumaYue（楽間勇笑。作った声を、素材として使える形で公開できない）
  - JVNV M1/M2/F1/F2（CC BY-SA）は、ほかに合う声がない時だけ。使うときは印を付けて、作者に知らせます。
- リダは、クレジットと URL を書けば使えます（性的・暴力的な使い方はしない）。
- **営利にするなら**、非営利だけのモデルの声は録り直しになります。問い合わせが要るモデルもあります（インド編の一覧は [casting.md](journeys/golden_triangle/voice/casting-2026-11-17/casting.md) の「決めてほしいこと・確かめてほしいこと」）。

モデルごとに、規約の本文で次を確かめます。

1. 無料の Web ゲームの台詞に使えるか（作った声のファイルだけをゲームに入れる。モデルは入れない）。
2. 別の人物の声に使えるか（キャラクターの規約で禁じていることがある）。
3. クレジットが要るか、どう書くか（例：VOICEVOX は「VOICEVOX:キャラ名」）。
4. ほかの禁止：政治・宗教の主張、性的な内容、実在の人の声のモデルで本人の発言と誤解させること、評判を下げる使い方、など。台詞がそれに当たらないかを、作者が台詞を読んで決めます。
5. 確かめた日。規約は変わることがあるので、読んだ日と、規約の写し（読めた分）を残します。

規約の本文を読めないとき（ページが開かない・メンテナンス中など）は、その人物の `noteJa` に「録音の前に：…」と、確かめることを書きます。依頼書では、作者が確かめるまで録らない人物として出ます。読めないまま録るか、だめだったときにどうするかは、先に作者が決めます。

### 3.4 声の高さを測る

人物どうしの聞き分けと、目標の高さに合うかを、モデルの見本の声で測ります。

```sh
npm run voice:pitch -- 見本1.wav 見本2.mp3
```

- 1ファイル1行の JSON を出します：長さ（`durationS`）、声のある長さ（`voicedS`・`voicedRatio`）、高さの中央値・10%・90%（`f0MedianHz`・`f0P10Hz`・`f0P90Hz`）、高さの幅（`semitoneRangeP10P90`、半音）。
- ffmpeg が要ります（PATH にあること）。音声の形式は ffmpeg が読めれば何でもよい（WAV・MP3 など）。
- 測り方：16kHz・モノラルに直し、40ミリ秒ずつ10ミリ秒おきに、60〜500Hz の間で周期を探します（YIN に似た方法）。静かな所は飛ばし、中央値から1オクターブ以上外れた値は捨てます。`scripts/voice-pitch.ts`。
- 気をつけること：500Hz より高い声は正しく測れません。ささやき声などは「声のある所が見つかりません」になることがあります。見本の文によって高さは揺れます（インド編では、1つのモデルで約121〜171Hz と揺れたものがある）。
- 2人の差は半音で比べます（半音の差＝12×log2(高い方÷低い方)）。インド編では、同じ場面の2人は2.4半音、続けて話す2人は1.5半音より近いと聞き分けにくいかもしれない、を目安にしました（目安で、聞いて決める）。

### 3.5 配役の順番

インド編で使った順番です。

1. **権利**：使えるモデルだけを候補にする（3.3）。
2. **同じ声**：同じ人の声のモデルを1つと数え、旅行編の中でもう使ったモデルを外す（3.2。D1 の例外は最後に使う）。
3. **性別・年齢**：人物と合う声。カタログに合う年代の声がないときは、いちばん近い声にして「弱い」と書く。
4. **高さ**：目標の範囲に入るか。ヒロイン・同じ場面の人と離れているか。
5. **声質**：乾いた・太いなどの特徴。カタログの説明と見本から推定する。
6. **台詞の多い人から**：多い人から順に決める。少ない人に、残った声と D1 の重なりを使う。
7. **聞き分け**：同じ場面で続けて話す人どうしの差を見直す。

設定の目安：AivisSpeech の「音高」は、合成した後で変えるので音質が落ちる。動かさない。VOICEVOX の「音高」は ±0.05 まで。話速は 0.8〜1.2、抑揚は 0.6〜1.4 ほど。

### 3.6 合う声がないとき

- 近い声にして、合い具合を「弱い」と書き、理由（若く聞こえるかもしれない、など）を残す。
- スタイルを変える、音高を少し動かす（VOICEVOX）、話速と抑揚で年齢感を出す、を試す案を `noteJa` に書く。
- 代わりの候補を残す（インド編の配役の記録の `alternatives`）。
- それでも合わなければ、配役しないで残してよい。配役のない人物は依頼書に入らず、`voice:script` が一覧を出します。
- どうするかは作者が決めます。聞いて決めることが多いので、試聴する組を記録に書きます（5章）。

### 3.7 記録を残す

- 配役の記録（なぜそのモデルか、測った高さ、合い具合、権利の印、代わりの候補、試聴する組）を `<制作資料>/voice/casting-<日付>/` に残します。インド編：[casting-2026-11-17/](journeys/golden_triangle/voice/casting-2026-11-17/casting.md)。
- **声の印象・年齢感は、カタログの説明と高さの測定から推した推定です。** 聞いて確かめていないことを、記録と依頼書に書きます。

## 4. ② 依頼書を書く

### 4.1 cast.json

配役を `<制作資料>/voice/cast.json` に書きます（ゲームは読みません）。形は `scripts/voice-cast.ts`、例はインド編の [cast.json](journeys/golden_triangle/voice/cast.json)。

```json
{
  "schemaVersion": 1,
  "journeyId": "golden_triangle",
  "checkedAt": "2026-11-17",
  "voices": [
    {
      "voice": "gt_kamla",
      "nameJa": "カムラ",
      "profile": { "age": "79歳", "gender": "女性", "build": "…", "looks": "…", "personality": "…",
        "pitch": "…", "quality": "…", "speed": "…", "delivery": "…", "origin": "…" },
      "engine": "voicevox",
      "model": { "id": "chubu_tsurugi", "nameJa": "中部つるぎ", "speaker": "中部つるぎ",
        "url": "https://voicevox.hiroshiba.jp/product/chubu_tsurugi/", "termsUrl": "https://zunko.jp/con_ongen_kiyaku.html",
        "license": "VOICEVOX ソフトウェア利用規約 ＋ 中部つるぎ 音声ライブラリ利用規約", "creditJa": "VOICEVOX:中部つるぎ" },
      "styles": { "default": "ノーマル", "ids": { "ノーマル": 94, "ヒソヒソ": 96 } },
      "settings": { "speedScale": 1.08, "intonationScale": 0.9 },
      "reasonJa": "なぜこのモデルか",
      "noteJa": "録音の前に：…（権利で確かめること。なければ書かない）\n同じモデル：…（D1 で同じモデルを使う人物）\n作る人へのメモ"
    }
  ],
  "scenes": { "gt_delhi_arrival": "場面の状況（2〜3文）" },
  "lines": { "gt_delhi_arrival_kamla_001": { "input": "エンジンに入れる文（読みを直したとき）", "noteJa": "この行の注意" } },
  "dictionary": [{ "word": "廟", "reading": "ビョウ", "noteJa": "…" }]
}
```

- `voice`：`entries.json` の `voice`。`profile`：2章の10の特徴。
- `engine`：`aivishub` か `voicevox`。`model.id`：AivisHub はモデルの UUID、VOICEVOX はキャラクターのページの名前。`model.voiceGroup`：同じ人の声のモデルに同じ名前（3.2）。
- `model.creditJa`：規約が求めるクレジットの書き方そのまま。任意なら「不要（任意。載せるなら…）」のように書きます。
- `styles`：ふだんのスタイル（`default`）、表情ごとのスタイル（`byEmotion`。表情の札の言葉 → スタイル）、VOICEVOX のスタイル ID（`ids`）。
- `settings`：エンジンの設定の値（`speedScale` など）。依頼書には、エンジンの画面の名前で出ます（AivisSpeech：話速・感情表現の強さ・テンポの緩急・音高・音量・開始無音・終了無音。VOICEVOX：話速・音高・抑揚・音量・間の長さ・開始無音・終了無音）。AivisSpeech には「間の長さ」がありません。「感情表現の強さ」は、スタイル「ノーマル」には効きません。
- `noteJa`：作る人へのメモ。1行ずつ（改行で区切る）。「録音の前に：」で始まる行は、録る前に作者が確かめること（確かめることがなければ「録音の前に：なし（理由）」）。「同じモデル：」で始まる行は、同じモデルを使うほかの人物と、話すストーリーが別であること。
- `scenes`：knot ごとの場面の状況。`lines`：行ごとの入力する文（`input`）・スタイル（`style`）・注意（`noteJa`）。読みがまだ決まらない語は「読み（仮）：…。作者の確認待ち」と書きます。
- `dictionary`：エンジンのユーザー辞書に登録する語（読みはカタカナ、アクセントは任意）。行によって読みが違う語（例：十分＝じゅっぷん／じゅうぶん）は辞書に入れず、その行の入力する文か注意に書きます。

### 4.2 voice:script を走らせる

```sh
npm run voice:script -- --journey <旅行編ID> --out <フォルダ>
```

- `heroine_lines.txt`・`entries.json` と、`Aibishub.txt`・`voicevox.txt` を書きます。
- 止まるもの：3.2 のモデルの決まりに合わない、エンジンにない設定、入力する文に名前がある、ヒロインを書いた、同じ人物を2回書いた、ほかの旅行編の `journeyId`。注意に出るもの：台詞のない人物、使われない場面や行のメモ、「同じモデル：」の行の過不足。配役のない人物は、人数と行数の一覧が出ます。
- `entries.json` は、頼む行だけ（ヒロインと配役した人物）です。配役のない人物の行は入らず、その ID は仮のままです。

### 4.3 2つの依頼書

依頼先が違うので、エンジンごとに1つのファイルにし、その依頼先の人物を全員まとめます。

- `Aibishub.txt`：AivisSpeech（AivisHub のモデル）で作る人物。
- `voicevox.txt`：VOICEVOX で作る人物。

どちらも同じ形です：この依頼について（同じモデルを使う人物の一覧）→ 録る前に（作者が確かめる権利の一覧、ユーザー辞書〈この依頼の台詞にある語だけ〉、エンジンの設定の注意）→ 箱の見方と読み方 → ファイルのそろえ方 → 名前の入る台詞 → 目次 → 人物ごと（★録音の前に、声〈モデル・話者・スタイル・設定・同じモデル・クレジット・ライセンス・ページ・利用規約〉、人物〈10の特徴〉、選んだ理由、作り方の注意、出る場面）→ その人物の台詞（都市・場面ごと、1行1つの箱）。

箱はヒロインの台本と同じ形です：`[ID]`、前の行、場面の分かれ道、表情、演出、スタイル、注意、台詞、入力する文。読むのは「台詞：」（入力する文があればそれ）だけです。

**依頼書は手で直しません。** 直すときは `cast.json` か台本を直して、`voice:script` を走らせ直します。

### 4.4 名前の入る台詞（作者の判断 D3）

遊ぶ人が決める名前（`{player_name}` など）は、録音した声では言えません。ふつうは、名前を言わない文に直してから頼みます（[発注マニュアルの 3.2](ORDERING_MANUAL.md#32-頼む行)）。

D3「「……」まで録る」：名前の手前まで録って、名前は字幕だけに出す行もあります。

- `cast.json` の `lines` に、その行の入力する文を、名前の手前で止めた文で書きます。例：`"gt_jaipur_hotel_mehndi_morning_jaipur_hotel_front_002": { "input": "あら。ここ、名前が書いてある。ヒンディー語で。……" }`。
- 依頼書では「★名前の手前まで録る。名前は字幕だけ」と出ます。`entries.json` のその行には `spoken`（録る文）が付きます。
- 届いたら、`voice:tag` が `recorded.json` に `spoken` を記録します。`content:build` は、名前の入る行の `# voice:` を、この記録がある声だけ通します。ほかの名前の入る行の `# voice:` は、今までどおり止めます。

### 4.5 渡すフォルダ

- `<制作資料>/voice/<日付>/` に、`voice:script` が書いた `entries.json`・`Aibishub.txt`・`voicevox.txt` をそのまま置きます（同じ日にほかの台本も渡したときは `<日付>_<ラベル>`。インド編は `2026-11-17_cast/`）。`entries.json` を置くと、その ID で決まります。
- 声の記録の README に、渡したもの（ファイルごとの人物と行の数）、作者の判断、同じモデルを使う人物、録る前に確かめる権利、作者の確認待ちの読み、配役が推定であることを書きます。
- 配役の記録（3.7）も、同じ `voice/` の下に残します。

## 5. 届いたら

流れはヒロインの声と同じです（[発注マニュアルの 4.1](ORDERING_MANUAL.md#41-届いたら)）。

1. **届いた物を確かめる。** 本数と、ファイル名が [ID] か。人物ごとに、依頼書の行数と合うか。
2. **MP3 にして置く。** ヒロインの声と同じ形（MP3・48kHz・モノラル・80kbps、ピークを -1 dB にそろえる）にして、`<旅行編>/public/assets/voice/<ID>.mp3` に置きます。例（形だけを変える。音量は別にそろえる）：`ffmpeg -i <ID>.wav -ac 1 -ar 48000 -b:a 80k <ID>.mp3`。
3. **札を付けて記録する。** `npm run voice:tag -- --journey <旅行編ID> --from <届いたファイルだけのフォルダ>`。名前の手前まで録った行は、`recorded.json` に `spoken` も記録されます。
4. **クレジットを足す。** 使ったモデルごとに、`<旅行編>/manifest.json` の `voiceCredits` に1つずつ足します（「出典・権利の一覧」の「声」に出ます）。
   - `useJa`：何の声か（例：「カムラの声」、同じモデルを2人に使ったら「ハミード・老人の声」）。
   - `titleJa`：モデル（例：「VOICEVOX の音声ライブラリ「中部つるぎ」」「AivisHub のモデル「MarkN」（AivisSpeech）」）。
   - `author`（VOICEVOX は音声ライブラリの権利者、AivisHub はモデルを公開した人）・`license`（規約の名前だけ。確かめた時のメモは入れない）・`url`（https のページ）・`checkedAt`（規約を確かめた日）。
   - 人数が多いと「声」の欄が長くなるので、出典・権利の一覧では「声の出典（○件）」を開いて見る形にしてあります。
   - `creditJa`：`cast.json` の `model.creditJa` の、規約が求める書き方。クレジットが任意のモデルも、声の出所として載せます。実在の人の声から作ったモデルは「音声合成モデル『○○』」の形にし、「CV:○○」のように本人が演じたと読める書き方をしません。
5. **聞いて確かめる。**
   - 配役の記録の「作者の耳で確かめてほしい組」を、続けて聞きます（インド編：[casting.md](journeys/golden_triangle/voice/casting-2026-11-17/casting.md) の「2. 作者の耳で確かめてほしい組」）。同じモデルを使う2人が別の人に聞こえるか、年齢感、同じ場面の人と聞き分けられるか。
   - 届いた声の高さを測ります：`npm run voice:pitch -- <旅行編>/public/assets/voice/<ID>.mp3`。配役の目標の範囲に入るか。
   - 数字と漢字の読み、辞書に入れた語、「読み（仮）」の語を聞きます。
   - `npm run content:build` が通るか。ゲームの設定「台詞の声を出す」で、場面の中で聞きます。
6. **コミットする。** MP3・Ink・`recorded.json`・`manifest.json` を一緒に入れ、声の記録の README に届いた本数と、付けなかった声とその理由を書きます。

## 6. 後で変えるとき

- **台詞を直したとき**：`npm run voice:changes -- --journey <旅行編ID>` が、録り直しの行と、まだ録っていない行の変わった・なくなった・新しい台詞を、人物の名前つきで出します。直した行だけを、同じ形の依頼書で頼みます（`voice:script` で作り直すと、録る行だけが依頼書に入ります）。
- **配役を変えるとき**：`cast.json` を直して `voice:script` を走らせ直します。ID は変わりません。もう届いた声のモデルを変えるなら、その人物の行は全部録り直しになるので、作者が決めます。
- **人物が増えたとき**：2章・3章の順で配役し、`cast.json` に足します。D1 の決まりで、そのストーリーにもう出ている人物のモデルは使えません。
- **モデルの規約が変わったとき**：その人物の `noteJa` に「録音の前に：」を書き直し、`checkedAt` を変えます。届いた声を使い続けてよいかは、作者が決めます。
- **営利にするとき（D2 を変えるとき）**：非営利だけのモデルの声は使えなくなります。問い合わせが要るモデルもあります。配役の記録の「営利にするなら」を見て、作者が決めます。
