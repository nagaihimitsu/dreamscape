# 横の点検：1つの指摘から、同じ型を全部探す

1つの指摘を直したら、同じ型の所をほかにも全部探すための手引きです。Dreamscape を直す AI のために書きました。人が同じ役をするときにも使えます。

- 元にしたのは、2026-11 の長い開発の会話（11-13〜11-16）です。ユーザーは「他にもそういうことがないか調べること」「他にもこういうことがないか調べて」「すべてのファイルで変わってるか調べて」のように、11-14〜11-16 に7回、横に探すよう頼みました。
- この手引きは、それを**頼まれなくてもする習慣**にします。
- 例は、その会話の記録、そのときの調べの報告、Git の履歴から引きました。調べの報告は AI の作業用フォルダにあり、いずれ消えます。要る中身は、この手引きに写しました。
- 決まりの元は [AGENTS.md](../AGENTS.md) です。この手引きと食い違うときは、そちらに従います。
- 仲間の手引き：遊ぶ人に見える言葉を変えるときは [決め方の手引き 11章](DECISION_GUIDE.md#11-遊ぶ人に見える言葉を変えるとき)、表記のゆれは [調べものの落とし穴集 4.1](RESEARCH_PITFALLS.md#41-ファイルごとに表記がずれる)、写真と場面の時刻は [同 5.3](RESEARCH_PITFALLS.md#53-場面の時刻と場所に合わない)、名札の探し方は [シナリオ改稿のポイント 2.8](SCENARIO_EDITING_GUIDE.md#28-名札旅の風景のまま人が話していないか) にあります。ここでは繰り返しません。

## 1. なぜ横に探すのか

指摘された1件は、たいてい同じ型の1つ目です。

2026-11-14、ユーザーは、まだ払っていないのに「雨の匂いの小瓶」が持ち物に入ることを指摘しました。同じ型を全部探すと、インド編でさらに10件、ミラノ編と見本の編で12件の気になる所が見つかりました（6.1）。

- **遊ぶ人にとって**：同じ違和感が別の場面でまた出ると、直ったと感じられません。
- **頼む人にとって**：毎回「他にも」と言わなければならないのは手間です。7回言わせたのは、こちらの落ち度です。
- **書く人にとって**：型に名前が付くと、次の都市を書くときの点検表になります（4章）。

決まり：**1件直したら、言われる前に同じ型を探す。報告には、見た数と見つけた数を書く。**

## 2. 五つの手順

### 2.1 型を一文で決める

指摘された1件を、「何と何がずれているか」の一文にします。一文が決まると、何を数えるか（札の名前、言葉、画面の部品）が決まります。

- 「品物の札とお金の動きが、物語で払う・受け取る行とずれている」（2026-11-14、小瓶）
- 「写真の真下に出典の行が出て、画面がごちゃごちゃする」（同日、前回までのあらすじ）
- 「ウインドウごとに閉じ方が違う」（同日、ゲームの設定）

狭すぎると、同じ型を見落とします。「小瓶の札の位置」では1件で終わります。「品物とお金の時点」にしたので、祝儀袋の札・夜のショーの券・入場料まで入りました。広すぎると、数えきれません。「文がおかしい所」では、何を拾えばよいか決まりません。

### 2.2 仕組みが本当にいつ・どう動くかを、コードで確かめる

「合っている」「ずれている」は、仕組みが本当にいつ効くかで決まります。資料の説明ではなく、コードで確かめます。

品物とお金の点検（2026-11-14〜15）で、先に確かめたこと：

- `# item_show:` は、その行のあいだ札を見せて `item_get` の音を鳴らすだけ。品物は増えません。もう持っている品物でも、音は鳴ります（`src/components/ItemShow.tsx`）。
- 「…を手に入れました」は、持ち物が本当に増えたときだけ出ます（`src/app/ItemGainNotice.tsx`）。
- 選択肢の `# money:`・`# give:`・`# use:` は、選んだその場で効きます（`src/domain/scene-effects.ts`）。
- `# on_done:` は、場面の終わりに効きます。案内の `# on_done:` は、最後まで読んだ初回だけです。案内を「飛ばす」と、読んだことにならず、効きません（`src/domain/chapter.ts`、`src/domain/tourism.ts` の `skipTourismGuide`）。
- 入場料（出来事の `admissionCost`）は、その場面が始まるときに二人分払います（`src/domain/travel.ts`）。

**なぜ先に確かめるか。** 最後の2つを知らないと、アンベール城の細密画の代金を、絵を買う案内の頭へ移したくなります。そうすると、案内を飛ばした人は、払わずに絵を手に入れます（6.1）。

書いてある決まりと、画面の動きが違うこともあります。2026-11-15 には、資料の説明と違って、`# leave:` が一部の場面の画面で効いていませんでした（[表現の道具の手引き 1.2](EXPRESSION_TOOLS_GUIDE.md#12-札が本当に何をするかはコードで確かめる)）。見せる札と動かす札を分ける考え方も、同じ手引きの [3章](EXPRESSION_TOOLS_GUIDE.md#3-見せる札と物を動かす札を分ける) にあります。

### 2.3 全部を数え、全部を読む

- **札と言葉で全部を拾い、一つずつ前後を読む。** 機械の検索は、候補を出すだけです。合っているかは、本文を読んで決めます。
- **札だけでなく、本文も数える。** 品物とお金の点検では、効果69件（札45件、データで決まる支払い24件）に加えて、「買う・払う・代金・ルピー・渡す・もらう」などが出る本文216行を読みました。札のない支払いの話は、札を数えても見つかりません。
- **データも見る。** 入場料（`admissionCost`）とデートの AP（`apCost`）は、Ink の札ではなく JSON にあります。
- **旅行編を全部見る。** インド編だけでなく、ミラノ編、見本の編、Ink のない旅行編のデータまで見ました。
- **遊ぶ順に読む。** `npm run journey:readthrough -- --journey <旅行編ID>` で本文の流れを出し、Ink と合わせて読みました。画面で確かめるときは、Debug で場面を開いて1行ずつ進めます（[Debug で確かめる手引き 3章](DEBUG_CHECK_GUIDE.md#3-場面を開く)）。
- **画面の型は、共通の部品の使われ方で探す。** 写真の下の出典は、出典の行を出す部品を使う所を全部見ました。閉じ方は、全部のウインドウのコードを読みました。
- **問題のなかった所も、1行ずつ残す。** インド編の報告は、確かめて問題のなかった効果を都市ごとに1行ずつ並べました。次の人が、どこまで見たかを知れます。
- **大きいときは分けて頼む。** 品物とお金の点検は、インド編と、ミラノ編・見本の編の2人に分けました。物差しは共通の指示書に1回だけ書きます（[AIに仕事を分けて頼む手引き 2章](AI_DELEGATION_GUIDE.md#2-共通の指示書)）。

### 2.4 「直す／理由があって残す／軽い」に分ける

| 分け方 | どんなものか | 例（品物とお金の点検） |
| --- | --- | --- |
| 直す | 遊ぶ人に見えて、物語と食い違う。小さく直せる | 祝儀袋の札が、まだ空で金額も決まっていない封筒に出る → お金を包んだ後の行へ移す |
| 理由があって残す | 直すと別の壊れ方が出る。仕様どおり。決めるのはユーザー | 「お金は一ルピーだけ」を選んでも ₹1 は減らない。減らすと三つの選択肢がどれもお金を使い、所持金が ₹0 の人は、本筋の手前のこの場面で一つも選べなくなるおそれがある |
| 軽い | 遊ぶ人にほとんど見えない。まれな道だけ。改稿のときに決める | 腕輪は、値切れた道も値切れなかった道も同じ ₹500。一度に一つの道しか遊べず、本文に値段もない |

直すときも、越えない線があります。

- ヒロインの台詞の文は変えません。地の文を1行足す、札を動かす、で直します（[シナリオ改稿のポイント 4章](SCENARIO_EDITING_GUIDE.md#4-守ること)）。
- 金額は作りません。夜のショーの券の値段はリポジトリのどこにもなかったので、主人公に払わせる案には、金額はユーザーに決めてもらう、と書いて出しました。
- 大きな直しは、その場でしません。ミラノ編の版画（券を使って刷った版画が持ち物に残らない）は、品物の登録と絵が要るので、改稿のときに決めることにしました。

### 2.5 件数と、残した理由を報告する

- 見た数、見つけた数、分け方ごとの数を書きます。
- 残したものは、1件ずつ理由を書きます。理由があれば、ユーザーは「それでも直す」と言えます。
- **残したものは、伝えないと忘れられます。** 2026-11-14 の名札の点検では、迷う4か所を作者向けに残しましたが、ユーザーに伝えていませんでした。11-16 に、3か所がまだ「旅の風景」のままだと伝えると、答えは「おすすめで」でした（6.6）。残したものは、続けて持つ一覧に入れます（[決め方の手引き 8章](DECISION_GUIDE.md#8-話の糸を落とさない)）。

報告の形は7章です。

## 3. 直した後にも、同じ型を探す

直しは、新しい道を作ります。その道に、同じ型の誤りが出やすいのです。

**例（2026-11-09、場面を1つの Ink で書く仕組みの4段目、PR #35）**：場面の後の行き先を変える札 `then:` を入れたとき、最初の点検で12件が見つかり、全部直しました。ところが、直した差分を確かめるたびに、同じ種類の新しい穴が出ました（1回目の直しの後に4件、2回目の直しの後に5件）。たとえば、エピローグへの運賃が場面で使うお金を数えていない穴を直したら、AP に同じ穴が残っていました。直しをお金だけに当てたからです。直しは4回になりました。回ごとの中身は [表現の道具の手引き 6章](EXPRESSION_TOOLS_GUIDE.md#6-飛ぶ札はお金時間ap保存とぶつかる) にあります。

**例（2026-11-15）**：「ホテルで休みました」を、たたくまで残るようにしました（90cd4a0）。すると、その下の上の帯が、もう翌朝の「2日目 09:00」になっているのが目に入るようになりました（6.8）。

**例（2026-11-14）**：ゴルガッパで、彼女が12個目にはったりをかけるようにしました。すると、先に手を上げたときの彼女の「あと一個で」が、いつも本当とは限らなくなりました。「あと少しで」に直しました（d45bed4、#131）。

だから、直したら次の2つを見ます。

1. 直した所と同じファイル・同じ仕組みに、同じ型がないか。
2. 直したことで新しく起きるようになったこと（新しい道、長く見えるようになった表示、変わったゲームの結果）が、ほかの所とずれていないか。

確かめるのは、直した所とその周りだけです。全部を何度も確かめ直すことはしません（[AIに仕事を分けて頼む手引き 1章](AI_DELEGATION_GUIDE.md#1-分ける理由と変えない決まり)の「確認の組み合わせを増やさない」）。

## 4. 点検表「物語と画面のずれ」

遊ぶ人が知るのは、画面だけです。文と札が別のことを言えば、どちらを信じればよいか分かりません。この会話では、この型の指摘が少なくとも5回ありました。場面を書いたら、または直したら、行ごとに次を照らします。

| その行で起きたこと | 合わせるもの | この会話の例 |
| --- | --- | --- |
| 買った・払った | お金の札（`# money:`・`# on_done: money`）、入場料、品物の札 | 小瓶・夜のショーの券・ハワー・マハルの入場料（6.1） |
| 受け取った・渡した | `# item_show:`・`# give:`・`# use:`・`# on_done: item` | カムラのメモの札が、まだ書いている行に出た。ダルセナで、もう持っているピックに「手に入れた」音が鳴った（6.1） |
| 夜になった・朝になった | 上の帯の時計、`# when: time night`・`cond("time night")`、背景の写真、`# tint:` | 夜の帯（6.8）、夜の場面の昼の写真（6.9） |
| 名前が出た・登場した | 旅の図鑑の札（`# term:`）、名札（`# speaker:`） | ニハーリーの札（6.7）、「旅の風景」のまま話す人（6.6） |
| 写真を撮った | アルバムの札（`# photo:`） | チーニー・カ・ラウザーの札は、構えを作る行にある。その瞬間の写真として読めるので、残した |

向きは二つあります。「払う前に手に入る」だけでなく、「払ったのに何も起きない」もずれです。デリーのフィナーレでは、夜のショーの券を「三枚買う」のに、お金が動きませんでした（6.1）。

### 4.1 ミニゲームを直したら、結果を語る地の文も読み直す

ミニゲームの結果ごとに、続きの文が分かれます。遊びを変えると、その文が本当でなくなることがあります。ゲームの規則（`src/minigames/<名前>/rules.ts`）で、その結果になる道を全部書き出し、どの道でも文が本当かを読みます。遊びの作り方は [ミニゲームの手応えの手引き](MINIGAME_FEEL_GUIDE.md) にあります。

- **クリケット（2026-11-14、8e0623f）**：バウンサー（高く跳ねる球）を振ると、高く上がって塀を越える当たりになる。地の文の「ボールは、思ったよりまっすぐ来た。」は跳ねる球と合わないので消し、「振った板きれに、手ごたえがあった。」だけを残した。ヒロインの声のある台詞「今日いちばんの当たりだったのに！」は大きな当たりにも合うので、そのまま。
- **ナハルガル城のかくれんぼ（2026-11-16、da4a85d）**：11-14 の改良で、彼女が扉からのぞき、空の部屋が彼女の方へなびくようになった。3枚目で見つけることも増えた。地の文「七つ目の扉を開けたとき」を「いくつ目かの扉を開けたとき」に直した。「三回目に呼んだとき、すぐ後ろの扉の陰から、くすくす笑う声がした。」も直した。ゲームでは「くすくす」は2回目で、3回目は彼女が出てくる所だから。
- **ゴルガッパ（2026-11-14、d45bed4）**：3章の例。

### 4.2 状態で分けられない行は、どちらでも本当の言い方にする

一つの行を、いくつもの状態から通ることがあります（何枚目で見つけたか、案内を読んだか飛ばしたか）。分けて書けないなら、どの状態でも本当になる言い方にします。

- 「いくつ目かの扉を開けたとき」「あと少しで」は、どの道でも本当です。
- アンベール城のクイズの場面は、「十分前、{heroine_name}は一枚の絵を買った。」と買ったことを言い直します。案内を飛ばした人にも伝わります。
- 書き分けたいときは、場面の中の `cond(…)` で分けます（[コンテンツ制作ガイド](CONTENT_GUIDE.md#場面の中の分岐)）。

## 5. 資料と今のゲームを照らす

2026-11-14、ユーザーは「このように昔作った資料とかが現在と食い違ってるものがたくさんあると思います　それをどんどん調べましょう」と頼みました。進め方は次のとおりです（例は 6.4）。

1. **資料の地図を作る。** 資料ごとに、誰が読むか、何のためか、どこと重なるか、その話の本家はどこかを書く。
2. **資料の種類ごとに分けて読む。** このときは、仕様の資料（`docs/`）、制作の資料（`authoring/`）、コードのコメントと道具の3人に分けました。
3. **資料の一文ずつを、コードと中身（データ・Ink）で確かめる。ほかの資料では確かめない。** 資料は互いに写し合うので、二つが同じことを言っても、両方とも古いことがあります。
4. **見つけたものを4つに分ける。**

| 見つけたもの | すること |
| --- | --- |
| 古い事実（道・名前・数・なくなった機能） | その場で直す |
| 足りない事実（読む人に要る、今の機能） | 短く足す |
| 日付のある記録（計画・点検・調べの記録・昔の指示） | 書き換えない。頭に1行だけ足す。何の記録か、いつのものか、今の状態はどこに書いてあるか |
| 決まりどうしの食い違い | AI が決めない。両方の行をファイルと行番号つきで引き、おすすめを付けて聞く |

- 頭の1行の例：[docs/05](../docs/05_ROADMAP.md)「最初の計画の記録です。…今の実装の範囲は…、今の受け入れテストは…にあります。」
- **なぜ AI が決めないか。** 決まりは、ユーザーが決めたものだからです。答えをもらったら、その決まりのある資料に日付つきで書きます（[決め方の手引き 4.3](DECISION_GUIDE.md#43-資料が第一原則と食い違うとき)・[7章](DECISION_GUIDE.md#7-決めたことを書き残す)）。
- 資料に件数や時間を書くときは、測った日も書きます。数は、中身を足すと変わるからです。

## 6. 例

### 6.1 品物とお金の時点

- **指摘（2026-11-14）**：「会計が済んでないのに、雨の匂いの小瓶がアイテムに加わるのが違和感」。続けて「他にもそういうことがないか調べること」。
- **先に直した**：小瓶の札を、布袋に入れて手渡す行へ。同じ形の腕輪も、代金を払って包む行へ（1cff100）。
- **数えた**：インド編は効果69件と本文216行。見つけたのは10件（直す5、理由があって残す1、軽い4）と、写真の札の報告2件。ミラノ編と見本の編は別の人が55か所を見た（問題なし43、指摘12）。
- **直した**：インド編は、祝儀袋の札をお金を包んだ後へ、夜のショーの券をアマンが買う文に、ジャイプールのフィナーレの昼はハワー・マハルに上る文に、メヘターブ・バーグの「写真代の使い道を聞く」道で写真を撮る1行を、カムラのメモの札を書き終えた後へ（2596a4f）。ミラノ編は、ダルセナのピックの札を消す、城でピックがティノの指に残る1行、券を受け取る文、券の説明。見本の編は、サドルの直し賃を払う1行（91fbdca）。どちらも #133。
- **残した**：アンベール城の細密画の代金はクイズの場面の終わりのまま（2.2）。₹1 の祝儀（2.4）。ミラノ編の版画（改稿のとき）。

### 6.2 写真の出典の出し方

- **指摘（2026-11-14）**：前回までのあらすじや旅の図鑑で、写真の下に出典が出て「ごちゃごちゃします」。「他にもこういうことがないか調べて」。
- **探した**：出典の行を出す部品を使う所。あらすじ、旅の図鑑、クイズの答えの種明かし、手がかり帳の4か所だった。
- **案と答え**：最初の案は、「写真の出典」を押せるボタンにすることだった。答えは「設定の写真の出典からアクセスするようにしてほしい　ボタンも増やしたくない」（2026-11-15）。
- **直した**：4か所とも、写真の下の出典を外した。≡メニューの「写真の出典」「画像の出典」と「出典・権利の一覧」で見られる。使われなくなった部品も消した（e733cef、#133）。
- **学び**：権利の表示は消さずに、今ある入口へ集める。ボタンを足す案になったら、足さない道を先に探す。

### 6.3 閉じ方

## 7. 報告の型

報告の一般の決まりは [決め方の手引き 10章](DECISION_GUIDE.md#10-報告のしかた) にあります。横の点検では、次の形で返します。長いときは、テキストのファイルにします。

```
横の点検：<型の一文>
- きっかけ：<日付>、<指摘（ユーザーの言葉）>
- 仕組み：<コードで確かめたこと（ファイル）>
- 見た範囲：<旅行編・ファイルの種類・札と言葉>。見ていない所：<と理由>
- 数：見た <n> 件。直す <a>・理由があって残す <b>・軽い <c>
- 直したもの：<1行ずつ。場所 → どう直したか（コミット）>
- 残したもの：<1行ずつ。場所と理由>
- ヒロインの台詞：<変えていない／変えた行と、録り直しの要否>
- 決めてほしいこと：<番号・おすすめ・一行の理由>
- 確かめたこと：<content:build、Debug で開いた場面、voice:changes など>
```

## 8. チェックリスト

探す前：

- □ 指摘を直したら、言われる前に同じ型を探すと決めた
- □ 型を一文で書いた（何と何がずれているか）
- □ 仕組みがいつ・どう動くかを、資料ではなくコードで確かめた

探すとき：

- □ 札・言葉・データ・画面の部品で全部を拾い、一つずつ前後を読んだ
- □ 全部の旅行編を見た。見ていない所は、理由と一緒に書いた
- □ 問題のなかった所も、1行ずつ残した
- □ 資料の文は、ほかの資料ではなく、コードと中身で確かめた

分けて直すとき：

- □ 「直す／理由があって残す／軽い」に分け、残すものに理由を書いた
- □ ヒロインの台詞、話の事実、金額は、自分で変えずに案にした
- □ 日付のある記録は書き換えず、頭に1行だけ足した。決まりどうしの食い違いは、両方を引いて聞いた
- □ 行ごとに、起きたことと品物・お金・時刻・写真・図鑑・名札の札が合うかを見た（4章）
- □ ミニゲームを変えたら、結果を語る地の文を全部の道で読んだ
- □ 状態で分けられない行は、どの状態でも本当になる言い方にした

直した後：

- □ 同じファイル・同じ仕組みに、同じ型がもうないか見た
- □ 直したことで新しく起きるようになったことが、ほかとずれていないか見た
- □ 件数と、残した理由を報告した。残したものを、続けて持つ一覧に入れた
