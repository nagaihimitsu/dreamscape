# SNS（旅の記録の「SNS」の欄）の仕様

2026-11-26 のユーザーとの相談で決めた方針です。**仕組み（ビルド・届く規則・セーブ・条件・画面が使う読み口）と画面を作りました（2026-11-27）。** 作ったものの名前は [作ったもの](#作ったもの2026-11-27) と [作った画面](#作った画面2026-11-27) にあります。数値や文、見本の絵は仮で、作るときに変えてよいものです。決まっていない所は [未決](#未決) に分けました。

## ねらい

- 出会った人のコメントとヒロインの返事、出会った人の暮らしを、**頭をカラッポにして読める**軽いSNSにする。
- 旅の記録の「体験」の欄を、この「SNS」の欄に置き換えた（2026-11-19・11-20 に決めた「体験」の形を改めた）。体験のカードの題と文（`clearTitleJa`・`clearDescriptionJa`）は、前回までのあらすじに残る（夜の「今日の見出し」は、夜の画面を作り直してなくした。下の「夜の画面」）。
- 読まなくても旅は進む。本筋に要る情報はSNSだけに置かない。
- **誰の投稿か**：ヒロインの投稿は彼女のアカウントのもの。写真は主人公が撮り、彼女が自分の旅の投稿に使う（だから「撮ってる人、だれ？」のようなコメントが書ける）。出会った人の投稿は、その人が自分で撮った写真。主人公は投稿もコメントもせず、いいねだけ押す。
- 実在のSNSの見た目（ロゴ・色の輪・アイコンの並び）は借りない。いいねのハートは、どのSNSにもある一般的な印として使う。読み方の型（新しい順・投稿の下にコメント）だけ借り、見た目はゲームの写真の紙と羊皮紙の色でまとめる。

### 旅の記録の欄

- 上の切り替えは「SNS｜写真」。新しいものがあるとき「SNS」に点（今の写真の点と同じく、このタブの間だけ）。
- 投稿を書いていない旅行編（今のミラノ編など）は「SNS」を出さず、「写真」だけにする。
- 「体験」の下にあった「旅の数字」は、ヒロインの人物ページ（彼女のSNSのプロフィール）に小さく出す（2026-11-27 のユーザー判断）。投稿のない旅行編では、「写真」の下に出す（彼女のページがないため。作るときに決めた）。

### トップ：共通のタイムライン

- 新しい順。日ごとに見出し「デリー · 2日目」を置き、見出しの右に**その日に会った人の顔**を重ねて出す。押すと、その日に会った人の一覧 → 人物ページ。
- いちばん上に1行の「出会った人 ›」ボタン（顔を3〜4つ重ねた印）。押すと全員の一覧（都市ごと、会った順に顔と名前、自己紹介の1行目）→ 人物ページ。
- **ヒロインの投稿は1日1枚の札**。その日の彼女の投稿を、写真ごとに横に並べてめくる（1日に何か所も回るので、流れが投稿で埋まらないように）。札が属する日は、投稿した夜の日。
- **出会った人の投稿は1つずつ別の札**で、同じ流れに混ざる。

### 札：写真の紙

- 写真は、場面で大きく出る写真と同じ「写真の紙」（白い縁）。少しだけ傾ける。字は傾けない。札の枠や頭の行は作らず、紙そのものが投稿。
- 写真の**左上**に投稿した人の顔アイコン、その下に小さく名前。写真の**右下**に場所の名前（白い字に影、その角だけ少し暗くする）。
- 紙の下の余白に、その投稿の**一言**を手書き風の字（Klee One。写真の説明と同じ字）で載せる。写真の説明 `# photo_caption:` はSNSでは出さない（場面と「写真」の欄で見られる）。
- 前後の写真が左右に少しのぞく。のぞいている写真の上に「‹」「›」の小さな白い丸（押せる広さは44px）。指で払ってもめくれるが、**めくれるのは写真の帯の上だけ**（コメントの上で横に指が動いてもめくれない）。
- 写真の下に小さな点。投稿ごとにまとめ、まとまりの間をあける。新しいコメントが届いた投稿のまとまりには、横に小さな赤い点。
- めくると、場所・写真・一言・コメントがその投稿のものに替わる。**同じ投稿の写真の間は、一言とコメントは替わらない。**
- 札の高さは、**その日の投稿のうちいちばん高いもの**にそろえる（2026-11-27 のユーザー判断）。めくっても下の札が上下に動かない（コメントの少ない投稿では下に余白が出る）。
- **写真を押すと**、「写真」の欄で写真を押したときと同じ大きな表示をSNSの上に開く（写真の全体・写真の説明・「2日目 14:20 · 場所」。前後は「写真」の欄の並びでめくる）。閉じるとSNSの元の位置に戻る。

### コメント欄

- 写真の下に、少し濃い紙の上でまとめる。1件1行：顔アイコン・名前（太字）・本文。返事は字下げして小さめの顔（左の線は使わない）。
- 新しいコメントは、名前の前の小さな赤い点だけ。**数は出さない**（いいねの数・コメントの件数・フォロワーはない）。
- 顔や名前を押すと、その人の人物ページ。

### いいね

2026-11-26 のユーザー判断。DEATH STRANDING の「見返りのない愛」（数はおまけ、よくないねはない）と、町が反応するだけのSNSを手本にし、関係値が上がる・数を集めるいいねにはしない。

- **主人公が押す。** 投稿（1日の札なら、今めくっている1枚の投稿）ごとに、写真の紙の隅の小さなボタンで押す。もう一度押すと取り消せる。**数は出さない。** 写真を押すとアルバムが開くので、2回たたいていいねにはしない。印は**ハート**（2026-11-26 のユーザー判断。旅のスタンプの判は、ほかの所でも使いがちで見た目が一本調子になるため）。押していないときは線だけ、押すと赤く塗る。
- **仕組みとしての効果は付けない**（関係値・品物・お金・AP は変わらない）。何が起きるかは制作者が書く：条件 `liked <投稿>` で、場面やコメントが読める（例：彼女の投稿にいいねしていると、夜の一言で「いいね、押したでしょ」とからかわれる）。主人公が彼女の投稿に押すことは、それ自体が小さな好意の合図になる。条件は読んだときのいいねを見る。後で取り消しても、もう起きたことは変わらない。
- **出会った人のいいねは、顔で見せる。** 写真の下に、いいねした人の小さな顔を重ねて出す（数は出さない）。いいねする人は、その投稿にコメントした人（届いたコメントだけ）と、札 `# likes:` に書いた人。いいねはコメントと同じく、届いた夜から出る。
- いいねは、押した投稿のIDだけをセーブに記録する。

### 人物ページ

- 左上の「‹ SNS」でトップの元の位置に戻る。旅全体で**1人1ページ**（カムラやアマンのように都市をまたぐ人も1ページ）。
- 上から：
  1. **本人の言葉**：顔アイコン、名前、本人が書いた**自己紹介**（2〜3行、本人の口調）。
  2. **あゆみのメモ**：ヒロイン側の情報。今の紹介（`titleJa`。例「村から来た男の子」）と、会った都市・日・場所（例「デリー · 2日目にインド門で会った」）。彼女の小さな顔と「（ヒロインの名前）のメモ」の見出しを付けた枠に、手書き風の字で。本人の言葉と声が混ざらないよう分ける。
  3. **その人の写真**：その人が撮った日常の写真を3列の格子で。押すとその投稿。写真のない人はこの欄を出さない。
  4. **ヒロインの投稿へのコメント**（どの写真へのコメントか、小さな写真付き）。
  5. **一緒に写っている写真**（5列。下の `# photo_with:` で拾う）。
- 顔アイコンは**人ごとに固定**（SNSのアイコンは本人が選ぶものなので、場面の服で変えない）。基本の服の顔にし、制作者が別の服を選べるようにする。服の違いは写真で見せる。
- ヒロインの顔を押すと、彼女のページ：顔・名前・自己紹介（書く所は作るときに決める。名前はベタ書きせず `{heroine_name}`）、その下に**旅の数字を小さく**（2026-11-27 のユーザー判断）、そして彼女の1日の札。

### 夜の画面と知らせ

- **夜の画面は、SNSに合わせて大きく作り直してよい**（2026-11-27 のユーザー判断）。**「今日の見出し」はなくした。** 並べ方は、作るときに次のように決めた：「夜も更けました。」→ 夜の操作のボタン（ツアー・出発など）と「ホテルで休む」（今までどおりの位置。小さな画面でも操作が見えるように）→ 広くあけて SNSの札 → 彼女の一言 → 今日の道のりの地図 → 今日の一語。SNSの札は、押し間違えないよう操作のボタンから30pxほど離し、形も違う（左に顔の並んだ横長の札）。
- 夜の操作が1つもなく、ゲームが自分で休む夜でも、その夜にSNSに届いたものがあれば夜の画面を出す（「ホテルで休む」とSNSの札だけ）。作るときに決めた：札を見せる場所が夜の画面だけのため。21時より前に「休む」で夜を過ごしたときに届いたものは、夜の札（「ホテルで休みました。」）に出さず、≡メニューと「旅の記録」の点で知らせる。
- SNSの札：届いた人の顔を重ねて、「SNS にコメントが届きました」と、新しいコメントの1件目を2行まで。押すと、その投稿のその1枚を開く（旅の記録の「SNS」を、その投稿の札の所で、その投稿の1枚目にめくって開く）。件数は出さない（顔が重なることで「何件か届いた」とだけ伝える）。コメントがなく投稿だけ届いた夜は「SNS に新しい投稿があります」と投稿の一言（作るときに決めた）。顔は書いた人で、彼女の顔はほかに誰もいないときだけ。
- 昼は札・音を出さない。場面の途中には決して出さない。

### 「写真」の欄

- 格子を5列にする（幅の広い画面は7列くらい）。つまんで列を変える操作は入れない（ブラウザの拡大と取り合うため）。
- 5列だと一度に40枚ほど見えるので、ビルドで縮小版（256px角）を作り、格子はそれを読む（作った。`<絵のID>.thumb.webp`。SNSの人物ページの格子も読む）。

## 届き方と記録

- ゲームの中の時計で届ける（現実の時刻では縛らない）。届くかを調べるのは**夜の画面だけ**。旅を終えたときにも一度だけ調べる（最後の夜の後に届くはずのものを取りこぼさないため）。
- **投稿**は、条件を満たした後の最初の夜に出る。ヒロインの投稿は、載せる写真を1枚以上撮っていること（撮った写真だけが載る。1枚もなければ出ない）。
- **コメント**は、**投稿と同じ夜**にまとめて届き（2026-11-27 のユーザー判断）、そこで閉じる。それより後にも届けたいコメントだけ `# timing: later` を書く（伏線の回収、関係の変化など）。
- 届いた投稿とコメントは記録し（ID・日・時刻）、**後から文が変わらない**。書き分け（`# one_of:`）は最初に届いた1つで決まる。セーブの版は上げず、任意の項目にした（2026-11-27。ない旧セーブは何も届いていないものとして続く。[作ったもの](#作ったもの2026-11-27)）。
- 疲れを避ける決まり：コメントする人は都市ごとに数人の「常連」に絞る。1つの投稿にコメントは2件くらいまで（4件以上で `content:build` が注意）。後から届くコメントが1つの投稿に2件以上あれば注意。
- **夜には成り立たない条件**：届くかは夜にだけ調べるので、`time day`・`not time night` のように夜には成り立たない条件の投稿・コメント・`# likes:` は届かない。`content:build` が注意を出す（`sns-night`。`scripts/sns-posts.ts` の `mayHoldAtNight`）。お金・AP・品物・関係の値の条件は、その夜の値で調べる（昼に満たしても、夜に満たしていなければ届かない）。

## 札（書き方）

投稿は都市ごとのファイル `content/journeys/<旅行編ID>/stories/posts/<都市>.ink` に書く。knot が1つの投稿、stitch が1件のコメント。場面としては流れない。札の名前は案で、作るときに今の札とそろえて決める。

| 札 | 書く所 | 意味 |
|---|---|---|
| `# post: <誰>` | 投稿の頭 | 投稿した人（`heroine` か人物ID） |
| `# images: <絵ID> …` | 投稿の頭 | 載せる絵（1枚以上）。ヒロインはアルバムの絵（撮ったものだけ載る）。出会った人は、アルバムの絵の使い回しか、新しく描いた絵（アルバムとは別のフォルダ） |
| `# where: <場所>` | 投稿の頭 | 出会った人の投稿の場所（任意。書かなければ出さない）。ヒロインの投稿は写真の記録の場所を使う |
| `# when:`・`# until:` | 投稿・コメントの頭 | 出る・届く条件（今の条件と同じ書き方）。`until` の後は届かない |
| `# one_of: <名前>` | コメントの頭 | 書き分け。同じ名前のうち、最初に届いた1つだけ残る |
| `# timing: later` | コメントの頭 | 最初の夜より後にも届く |
| `# speaker:` | 行 | 誰の言葉か（今と同じ）。投稿の頭の後の最初の行が投稿の一言 |
| `# photo_with: <人物ID> …` | 写真の札 `# photo:` の行 | その写真に写っている人（人物ページの「一緒に写っている写真」） |
| `# likes: <人物ID> …` | 投稿の頭 | コメントしていないがいいねする人（コメントした人は書かなくても入る）。投稿のコメントと同じ夜に届く。人ごとに条件を付けたいときの書き方は、作るときに決める |
| `# past: <いつ>` | 投稿の頭 | 出会った人の過去の投稿（2026-11-27）。二人に会う前の投稿で、夜には届かない。書いた人に会うと、人物ページで読める（「去年の冬」「三年前」など、いつの投稿かを日本語で） |
| 条件 `comment <投稿>.<コメント>` | 場面・コメントの条件 | そのコメントが届いたか |
| 条件 `liked <投稿>` | 場面・コメントの条件 | 主人公がその投稿にいいねしているか |

- ビルドが止めるもの（壊れるものだけ）：写真・絵・人物がない、同じ投稿のIDが2つ、投稿の中の選択肢・`cond(…)`・効果の札（品物・お金・AP・関係値・フラグ。届いた後に文が変わらないように、書き分けは `# one_of:` で）、未定義の札。
- 英語の一言やコメントには訳を添える（書き方は作るときに今の対訳の仕組みに合わせる）。

```ink
=== post_gt_india_gate ===
# post: heroine
# images: gt_album_d054 gt_album_d25 gt_album_d060
# when: date gt_delhi_date_india_gate
# speaker: heroine
十二人家族に、一日だけ入りました

= roohi
# speaker: gt_roohi
毎朝通ってるのに、知らなかった
# speaker: heroine
同じ名前、いっぱいあるよ

= monu_post
# timing: later
# when: met gt_monu
# speaker: gt_monu
来年はもっと望遠のきく携帯にする
# speaker: heroine
十三人目、予約しておきます
```

人物のデータ（`progression/story.json` の `people`）に足すもの（名前は案）：

- 自己紹介（本人の口調、2〜3行）。書いていない人は、名前と「あゆみのメモ」だけ出す（語り手の紹介 `titleJa` は声が違うので、自己紹介の代わりにしない）。
- SNSに出さない印。**基本は全員出す**。「電話の声」「入国審査官」のような人は、制作者が人ごとに隠せる。
- アイコンにする服（任意。書かなければ基本の服）。**立ち絵のない人（インド編に11人）はSNSに出さない**（2026-11-27 のユーザー判断）（その人の投稿・コメント・いいねは書けず、ビルドが止める）。

## 文の書き方

- **一言**は1行（スマホで20字くらい）で、さらっと。2行になると紙の高さが変わり、めくったときに下が動く。
- **コメントと返事**は1件1行（顔が付くので15字くらい）。
- 書かないもの：歴史・観光の説明、クイズの話、長い感想（物語は場面で読んでいる）。
- 書くもの：軽い冗談、その後の小さな出来事、人柄が見える一言。二人がしたことへの反応（例：写真屋を呼んだかで、モヌの投稿の写真が十三人か十四人か。`# when: flag …` と `# one_of:`）。
- 関係の変化は、古いコメントを直さず、新しいコメントで書く（例：「前は『旅の相棒』って言ってなかった？」を `# when: couple` と条件 `comment …` で）。
- ヒロインの文は [キャラクターバイブル](../docs/09_HEROINE_CHARACTER_BIBLE.md) を読んでから書く。SNSは半分おおやけの場なので、二人きりのときとは違う顔（人前では甘い言葉を言わない、照れて打ち消す、からかう、返事をしないこともある）が書ける。
- 自己紹介は本人の口調で（例：モヌ「ハリヤーナーの村から。／ダーディーの通訳係（無給）。／携帯の望遠を研究中」）。あゆみのメモはヒロイン側の情報。
- 名前はベタ書きしない（`{heroine_name}`・`{player_name}`）。
- 出会った人の日常の写真は新しく描く絵になる。全員には描かず、よく登場する人やクイズの相手から始める。
- 書く量の目安：1都市に彼女の投稿5〜10、1投稿にコメント1〜2件。まずデリーだけで5投稿ほど書いて、手触りを見てから広げる。

## 作らないもの

| 作らないもの | 理由 |
|---|---|
| いいねの数・コメントの件数・フォロワーの数 | 数値を上げる遊びになり、関係の値を見せない決まりともぶつかる |
| いいねで関係値などが上がる仕組み | 全部押せば得になり、選ぶ楽しさがない（恋と深空・Midnight Suns 型）。効果は制作者が条件 `liked` で書く |
| よくないね、いいね以外の反応（絵文字など） | 軽く読めることを優先。よくないねは DEATH STRANDING と同じく作らない |
| 遊ぶ人が書き込む・返事を選ぶ | 規模が大きくなる。効果をつけると二重受給の守りが要る。「通常会話を無制限に増やさない」決まりとの兼ね合い。今は読むだけ |
| コメントで品物・お金・AP・関係値・フラグが変わる | 場面の役目。要るようになったら足す |
| 全部の写真・全員への自動のコメントや、AIで作った大量の文 | テンプレ台詞の量産禁止、検証していない文を採らない決まり |
| 実在のSNSの名前・ロゴ・見た目 | 権利と没入感 |
| DM・チャット・ストーリー・検索・ハッシュタグ | 今回の芯ではない |
| コメントの声 | 文字で読むもの |
| 届いた後に文が変わること | 過去が書き換わると不気味になる |
| 現実の時刻で届く知らせ | 負担になる（ゲームの中の夜で届ける） |

### 札の名前

上の「札（書き方）」の案のとおりの名前にした。今の札とそろえた所と、作るときに決めた所：

- ファイル：`content/journeys/<旅行編ID>/stories/posts/<都市ID>.ink`。場所のファイルと同じく、1行目に `INCLUDE modules.ink`、2行目に `-> DONE` を書ける（Inky で見るため。隣に置いた `modules.ink` の写しはビルドが読まない）。knot の名前が投稿のID（すべての旅行編で1つだけ）、stitch の名前がコメントの名前。ほかの都市の投稿のファイルは書けない（ファイル名はその旅行編の都市のID）。
- 投稿の頭：`# post:`・`# images:`・`# where:`・`# when:`・`# until:`・`# likes:`・`# past:`（下の「過去の投稿」）。コメントの頭：`# when:`・`# until:`・`# one_of:`・`# timing: later`。行：`# speaker:`・`# translation:`（英語の一言やコメントの訳。今の対訳と同じ札）。
- `# speaker:` は、投稿の一言では省ける（投稿した人の言葉になる。書くなら投稿した人）。コメントの行には毎行書く。書けるのは `heroine` と、立ち絵（`characterId`）があり SNS に出さない印のない人。投稿の一言は1行（2行目からは書けない）。
- `# where:` は、その都市の地点のID（`travel/<都市>.json` の places）か、場所の名前（日本語。例「村の家」）。英小文字の ID の形で地点にないものはビルドが止める。ヒロインの投稿には書けない（写真の記録の場所を出す）。
- `# images:` は、ヒロインならアルバムの絵（撮ったものだけが載る）。出会った人なら、アルバムの絵か、新しく描いた絵（旅行編の `public/assets/sns/<ID>.webp`。アルバムと同じく自作の絵で、登録も出典も要らない。ID はアルバムの絵と重ねない）。
- `# likes:` の人ごとの条件は `# likes: <人物ID> … if <条件>`（例 `# likes: gt_monu if met gt_monu`）。`# likes:` は何度でも書ける。いいねは投稿が届いた夜に決まり、セーブに残る（後で条件が変わっても変わらない）。
- `# photo_with: <人物ID> …` は、場面の写真の札 `# photo:` と**同じ行**に書く（例 `# photo: gt_album_d25 # photo_caption: 十三人目 # photo_with: gt_monu`）。people にいる人なら書ける（立ち絵のない人は人物ページがないので出ない）。
- 条件：`comment <投稿>.<コメント>`（JSON では `snsComment`）、`liked <投稿>`（`snsLiked`）。場面の `cond(…)`・頭の `# when:` など、今の条件の書ける所ならどこでも書ける。
- ビルドが止めるもの：絵・人物・地点がない、立ち絵のない人・SNS に出さない人の投稿・コメント・いいね、同じ投稿のIDが2つ・同じコメントの名前が1つの投稿に2つ、選択肢・分岐・`~`・行き先（`->`）・`cond(…)`・`{…}`（`{heroine_name}`・`{player_name}` は書ける）・効果の札、書けない札（`# emotion:` なども）、条件の書き間違い・参照切れ。注意（止めない）：1つの投稿にコメント4件以上、後から届くコメント2件以上（`content:build` の注意 `sns-reading`）、夜には成り立たない条件（`time day` など）の投稿・コメント・`# likes:`（注意 `sns-night`。2026-11-27 に足した）。
- 生成データ：`src/content/generated/sns.json`（`src/content/sns.ts` の `snsDataSchema`。投稿・SNS の絵・写真に写っている人）。ゲームは `src/content` の `snsData` で読む。ビルドは `scripts/sns-posts.ts`。

### 過去の投稿（`# past:`、2026-11-27）

- 投稿の頭に `# past: <いつ>` を書いた出会った人の投稿は、夜に届かず、タイムラインにも夜の札にも出ない。書いた人に会うと、人物ページの「〜の写真」で、旅の間に届いた投稿の後に、書いた順に並ぶ（1人分は新しいものから書く）。押すと、その投稿のページ（見出しは「モヌ · 去年の冬」）。
- いつも同じ中身：`# when:`・`# until:`、コメントの `# when:`・`# until:`・`# timing:`・`# one_of:`、`# likes:` の条件は書けない。ヒロインはコメントできず（まだ会っていない）、ヒロインの過去の投稿もない。主人公のいいねのハートは出ない。いいねした人の顔は、コメントした人と `# likes:` の人。
- セーブには何も残さない（届いた記録がない）。Debug の「Debug：SNS」は、都市ごとに過去の投稿の数だけ出す。
- 仕組み：ビルドは `scripts/sns-posts.ts` の `checkPast`、届かないのは `src/domain/sns.ts` の `reachablePosts`、画面の読み口は `src/features/journey/sns.ts` の `snsPostView`（過去の投稿は `pastJa` があり `arrived` がない）・`snsPersonPage`・`snsPostPageTitle`。テストは `scripts/sns-posts.test.ts` と `src/features/journey/sns-past.test.ts`。

### 書いて分かった注意

- 条件 `met <人>` は、場面の `# person:`（`# together:`）に名前のある人だけが真になる。クイズやデートでだけ会う人は、`battle <クイズ>`・`date <デート>` で書く。
- 到着の場面は `seen` で読めない。到着の投稿は、写真が撮れたことだけで届く（条件を書かない）。
- 「デートの翌日以降」のような、ある夜より後を表す条件はない。同じ夜に届きすぎるときは、別の場面（次のクイズなど）や `day >= N` で散らす。
- フィナーレの後すぐエピローグが始まる都市では、フィナーレの夜の投稿は、都市を出るときか旅の終わりにまとめて届くことがある。フィナーレの直後の差し込みを読む書き分け（`seen …`）は、どちらの順でも読める文にする。
