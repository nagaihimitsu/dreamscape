# 書いた場面をDebugで確かめる

書いた場面（Ink）や直した場面を、遊ぶ人と同じ画面ですぐに見たい人のための手引きです。シナリオを書く人・直す人（編集者）向けで、コードを読まなくても使えるように書きました。

- 「◯◯を見たい → こうする」の形で並べています。URLの項目の全部と細かい決まりは、開発者向けの [開発時の確認の「Debug起動URL」](../docs/10_DEVELOPMENT_CHECKS.md#debug起動url) にあります。この手引きと食い違うときは、そちらに従います。
- 例のURLは、どれも [docs/10 のURLの例](../docs/10_DEVELOPMENT_CHECKS.md#urlの例)、単体テスト、E2E（`tests/e2e/debug-tools.spec.ts`・`debug-scenes.spec.ts`）から取りました。印（✓）のURLは、2026-11-16 に開発サーバーで開き、書いたとおりの画面か断りの文が出ることを確かめました。
- URLの形は開発用で、予告なく変わることがあります。開けなくなったら、まず docs/10 を見ます。
- 作る順番の中では、[新しい都市を1つ足す手引き](NEW_CITY_GUIDE.md) の、シナリオを書いた後の確認にあたります。直す人の読み方は [シナリオ改稿のポイント](SCENARIO_EDITING_GUIDE.md#52-読み物を用意する) にあります。

## 1. Debugを開く

Debug は、場面を一つずつ直接開くための確認用の入口です。ふつうに遊ぶと長く進めないと届かない場面へ、URL一つで入れます。

### 1.1 開発サーバーで

1. `npm run dev` を起動します（先に生成も行います）。
2. 表示されたアドレス（ふつうは `http://localhost:5173`）の後ろに `/?debug` を付けて開くと、「場面の確認」（場面を選ぶ画面）が出ます。
3. `/?debug&city=…&scene=…` のように項目を足すと、場面の確認を通らずに、その場面を直接開きます。

**書き直したら、生成し直してから開き直します。** ゲームは Ink を直接読まず、`npm run content:build` が作った生成物を読むからです。

- 起動したままなら、別のターミナルで `npm run content:build` を実行します。
- 保存のたびに自動で生成し直すなら、`npm run dev` の代わりに `npm run dev:watch` で起動します（保存から約5秒。失敗したときは理由を出し、前の生成物のまま待ちます。[12 開発の手引き](../docs/12_DEVELOPMENT.md#生成と編集の流れ)）。
- 生成できたら、ページを再読み込みします。Debug のURLは、再読み込みすると**その場面を最初から**開き直します（Debug で進めた所は残りません）。

スマートフォンで見るときは、同じネットワークから `http://<PCのIPアドレス>:<表示されたポート>/?debug&…` で開きます。

### 1.2 公開版（本番ビルド）で

公開版では、Debug モードをオンにした端末だけが Debug を開けます。

1. 旅を始めた後、上の帯の ≡メニュー →「ゲームの設定」→ いちばん下の「制作者向け」（たたんである）→「Debugモード」。
2. パスワード `adminmode` を入れて、オンにします。**このパスワードは秘密ではありません**（ユーザーの判断。誤ってオンにしないための確認です）。
3. ゲームの設定の「場面の確認を開く」を押すか、公開版のアドレスに `?debug&…` を付けて開きます。

オフの間は、`?debug` を付けても通常のタイトル画面が開きます。オンの間は、ふつうに遊んでいても、Debug の印の付いた表示（関係の値の変化、場面の条件、鍵のかかった札。6章）が出ます。

- 公開版には、見本の編（7.2）は入っていません。準備中の旅行編の写真なども入らないので、準備中の都市を写真まで見るなら開発サーバーで見ます（[技術設計](../docs/02_TECH_ARCHITECTURE.md) の「準備中の旅行編のファイルは本番ビルドに入れない」）。
- 手元で本番の形を試すなら、`npm run build` の後に `npm run preview` です。

### 1.3 Debug で遊んだことは、どこにも残らない

Debug の進行は、そのタブのメモリの中だけにあります。通常のセーブ・英語ノート・設定には触れません。「場面の選択へ戻る」・再読み込み・終了で捨てられます。通常のゲームに戻るには「通常プレイに戻る」を押します。

Debug は、遊びではそうは届かない状態（フラグだけ立てた、時刻を戻した、など）も作ります。だから通常の保存とは分けてあり（AGENTS.md）、**Debug で確かめるのは、場面の見た目と流れまで**です。保存して再開できるかは、ふつうに遊んで確かめます（[docs/10](../docs/10_DEVELOPMENT_CHECKS.md#人が画面を確かめるときの使い方)）。

## 2. 場面の確認の使い方

`/?debug` だけで開く画面です。上から選んで「この場面を開く」を押します。

| 欄 | 選ぶもの |
| --- | --- |
| 確認データ | 「都市データ」（ふつうはこれ）か「仮の場面」（7.1） |
| 都市 | 都市の名前。制作中の都市には「（制作中）」が付く |
| 場面 | 観光・場所、クイズ、人物との交流、デート、エピローグ、観光地の時点、ツアー、街歩き（地図）。その都市にない場面には「（この都市にはありません）」が付く |
| 対象（街歩きでは「地点」） | 開く場面。**括弧の中が、URLの `target=` に書くID** |
| 旅の進行 | 「都市クリア後」か「旅の開始時」 |
| AP・親しさ・信頼・恋愛の意識 | 場面を始める前の値 |
| 恋の段階 | 「旅の進行のまま」か 1〜4 |
| デートの反応 | 「成功寄り（抽選値 0）」か「失敗寄り（抽選値 9999）」 |
| フラグを得たことにする | たたんだ欄。チェックしたフラグを得た状態で始める |

場面を「街歩き（地図）」にすると、「街歩きの日時」の欄も出ます（4.3）。

- 下の「この場面のURL」に、選んでいる設定のURLが出ます。「この場面のURLをコピー」で写せます。作業の報告やPRにこのURLを書くと、読む人が同じ場面をすぐ開けます。
- 場面を開くと、上に Debug の帯が出ます。「Debug · 通常セーブとは別」、開始地点、「フラグ・時刻・段階」（5章）、「場面の選択へ戻る」です。

**場面は、本物のゲームの規則で、その都市まで遊んだ状態から始まります。** 「都市クリア後」は、その都市までをクリアした後の街歩き（インド編では、すぐエピローグになる。9.1）、「旅の開始時」は、その都市に着いて到着の会話を読んだ直後です。ただし、Debug は途中のデート・差し込みの場面・観光案内・道中交流を流さないので、そこでしかもらえない品物は持っていないことがあります（[docs/10](../docs/10_DEVELOPMENT_CHECKS.md#debug起動url)）。

## 3. 場面を開く

開発サーバーのアドレスの後ろに付けます。

| 見たいもの | URL | メモ |
| --- | --- | --- |
| 観光案内 | `/?debug&city=milano&scene=tourism&target=duomo_milano` ✓ | `target` は観光地のID |
| クイズ | `/?debug&city=milano&scene=battle&target=milano_duomo_01` | |
| 推理クイズB（矛盾追及） | `/?debug&city=milano&scene=battle&target=milano_la_scala_b01` | |
| 推理クイズC（証拠連結） | `/?debug&city=milano&scene=battle&target=milano_brera_c01` | |
| 都市フィナーレ | `/?debug&city=milano&scene=battle&target=milano_city_boss_01` | |
| 旅の開始時のクイズ | `/?debug&city=delhi&scene=battle&target=gt_delhi_main_red_fort_battle&progress=initial` | 都市の最初の状態から |
| デート | `/?debug&city=milano&scene=date&target=milano_brera_date_01&roll=positive` | `roll=negative` で失敗寄りの反応 |
| 道中交流 | `/?debug&city=milano&scene=encounter&target=galleria_fortune` | 遊びと同じ時点で始まり、終わると次の画面へ進む |
| エピローグ | `/?debug&city=milano&scene=epilogue&target=milano_finale` | `target` は都市フィナーレのID |
| 次の都市の到着 | `/?debug&city=delhi&scene=epilogue&target=gt_delhi_finale` | デリーのエピローグを読み進めると、アーグラの到着へ続く |
| ツアー（予約した所） | `/?debug&city=agra&scene=tour&target=gt_agra_tour_fatehpur_sikri` | 都市クリア前に予約するので、進行は「旅の開始時」 |
| ツアー（見学の途中） | `/?debug&city=agra&scene=tour&target=gt_agra_tour_fatehpur_sikri&step=visit` | `step` は見学の行程のID |
| 街歩き | `/?debug&city=delhi&scene=free&progress=initial` ✓ | `target` を省くと宿から |

- **旅の最初の都市の到着**は、Debug では開けません（「旅の開始時」は到着を読んだ後から始まるため）。タイトル画面から新しい旅を始めて読みます。
- ツアーでしか行けない場所（インド編のファテープル・シークリー）の場面は、一覧で灰色になり「ツアーの場面（scene=tour）から開けます」と出ます。ツアーから開きます。
- **観光地の時点（`scene=occasion`）**は、観光地の訪問を本物の規則で進め、`from=` の場面が始まる所で止めます。`prep=` には、先に流しておく同じ都市の場面を書きます（その場面がくれる品物を持たせるため）。例（`npm run dev:sample` で。見本の編のテスト `tests/journeys/sample_trip/occasion.test.ts` が確かめている設定をURLにしたもの）：`/?debug&city=mihon&scene=occasion&target=mihon_clock_tower&progress=initial&from=smp_mihon_clock_gears`

## 4. 旅の途中の状態から始める

### 4.1 進行・AP・関係の値・反応

| 項目 | 値 | 省いたとき |
| --- | --- | --- |
| `progress` | `completed`（都市クリア後）、`initial`（旅の開始時） | `completed`（ツアーは `initial`） |
| `ap` | 0〜12 | 12 |
| `affection`・`trust`・`spark` | -20〜20（親しさ・信頼・恋愛の意識） | 0 |
| `roll` | `positive`（成功寄り）、`negative`（失敗寄り） | `positive` |

例：AP 2 で失敗寄りのデート `/?debug&city=milano&scene=date&target=milano_brera_date_01&ap=2&roll=negative`

デートの分かれ道の、もう片方を見る項目もあります（デートだけ）。

- `without=<品物ID>`：持っている品物を持たずに始める（`cond("item … held")` の持っていない側）。例：`/?debug&city=agra&scene=date&target=gt_agra_date_akbar_tomb&without=gt_delhi_rain_attar`
- `before=<エピソードID>`：そのエピソードを終える前に始める（`cond("episode …")` のまだの側）。例：`/?debug&city=delhi&scene=date&target=gt_delhi_date_lodhi_garden&before=gt_delhi_main_humayun_tomb`

### 4.2 フラグ（`flags=`）

`flags=` に、フラグのIDを `,` で区切って書きます。その場面を始める前に、そのフラグを得たことになります。旅の進行で得ているフラグは残ります。

- 例：ゴルガッパでお腹を壊した状態のデリーの街歩き `/?debug&city=delhi&scene=free&progress=initial&flags=gt_delhi_golgappa_sick` ✓。宿で休むと、翌朝の宿の場面が出ます（E2E が確かめている）。
- IDと説明は、旅行編の `progression/story.json` の `flags`（`noteJa`）です。場面の確認の「フラグを得たことにする」にも、都市ごとに説明つきで並びます（どの場面も使っていないフラグは最後の「どの場面も使っていないフラグ」）。
- ほかの旅行編のフラグや、登録のないIDは断られます。

### 4.3 街歩きの日時（`scene=free`、`time=`、`day=`）

`scene=free` は街歩き（地図）を開きます。`target=` は始める地点のID（省くと宿）。

- `time=19:00` のように時刻を書きます。**使えるのは 09:00〜21:00 だけ**です（9.2）。夜は 18:00 から。`21:00` は一日の終わりで、遊びと同じく夜の画面か、宿で休むに進みます。
- `day=` は、その都市の滞在の何日目か（1〜30）。曜日も一緒に動きます。
- 場面の確認では、「朝 9:00」「昼 12:00」「夕方 17:00」「夜 19:00」のボタンか、時刻と日を入れます（空欄は旅の進行のまま。多くは1日目 9:00）。
- 例：ミラノの夜の街歩き（夜だけのデートが始められる）`/?debug&city=milano&scene=free&time=19:00`。フラグと一緒に：`/?debug&city=milano&scene=free&time=19:00&flags=milano_tino_needs_pick` ✓

### 4.4 恋の段階（`stage=`）

`stage=1`〜`4` で、場面を始める前の恋の段階を決めます（地図・交通の確認 `scene=map` 以外のどの場面でも）。関係の値は変えません。Debug から始めた状態は、ふつう段階1です。

- 例：段階2でデリーのレッド・フォートのクイズから `/?debug&city=delhi&scene=battle&target=gt_delhi_main_red_fort_battle&progress=initial&stage=2` ✓
- 下げた段階は、また上がることがあります（9.4）。

## 5. 遊びながら変える

場面を開いた後、上の帯の「フラグ・時刻・段階」で、今の Debug のゲームを変えられます。変えるとすぐに効き、次の操作からその状態で進みます（通常のセーブは変わりません）。

- **街歩きの日時**：「朝」「昼」「夕方」「夜」を押すか、日と時刻を入れて「この日時にする」。前の時刻にも戻せます。
- **恋の段階**：1〜4 のボタン。
- **フラグ**：チェックで得たことにし、外すと消えます。

**変えられるのは、場面が開いていない間（街歩きと、一日の終わり）だけ**です（9.3）。会話・クイズ・デート・宿の場面・ツアーの間は、欄が押せなくなり、「場面の途中なので変えられません。場面を終えるか、≡メニューの「移動画面に戻る（Debug）」で街歩きに戻ってから変えてください。」と出ます（今のフラグと段階は見えます）。✓

- 「移動画面に戻る（Debug）」は、≡メニューの一覧の最後に出ます。Debug モードがオンの間に、街歩きの画面を一度開いた後だけです。最後に街歩きにいた時の状態へ、お金・AP・時刻・品物・フラグごと戻ります。
- 時刻を変えると、今いる所からその時刻に宿へ帰れる一番安い帰り方を、帰りの交通費としてとっておき直します。間に合う帰り方がない・予算が足りないときは、理由を出して断ります（宿では断りません）。
- ツアーを予約している間は、日を変えられません（翌朝に出発するため。時刻は変えられます）。

例（E2E と同じ流れ）：`/?debug&city=delhi&scene=free&progress=initial` を開き、「フラグ・時刻・段階」で `gt_delhi_golgappa_sick` にチェックして閉じ、宿で休む。翌朝、宿の場面（お腹を壊した朝）が始まります。その場面の間に開くと、欄は押せません。

## 6. 出ない理由を読む

ゲームの画面は、場面の条件（`when`・`cond(…)`）がかなっているかを、遊ぶ人に見せません（関係の値などを隠す決まりのため）。Debug だけが理由を出します。

### 6.1 開けなかったときの理由

URLで開けないときは「場面を開けませんでした」の画面に、理由と「場面の確認へ」のリンクが出ます。条件が足りないときは、満たしていない部品も並びます。

- 例：`/?debug&city=milano&scene=date&target=milano_brera_date_01&progress=initial` ✓ →「この進行状態ではデートを始められません。APや解放条件を確認してください。デートの条件を満たしていません：エピソード「五本の指で話す人」を終えた」
- 例：ミラノにないクイズを指したとき →「「gt_delhi_main_red_fort_battle」はミラノの「クイズ」にありません。」
- 場面の確認の「対象」で灰色の対象は、括弧に理由が出ます（「（品物「…」が必要なため開けません）」「（ツアーの場面（scene=tour）から開けます）」）。

### 6.2 場面の中の `cond(…)`：「Debug：場面の条件」

画面の場面が `cond("…")` を使っている間、場面の上に「Debug」の印つきで、文字ごとに「条件「…」：真（満たす）」か「偽（満たさない）」が出ます。どちらの道を通っているかが分かります。

選択肢で関係の値が変わったときは、同じ所に、各軸の増減と前後の値（デートでは反応と噛み合う確率も）が出ます。どちらも会話ログとセーブには入りません。

### 6.3 「Debug：この時点の候補」

Debug のページには、たたんだ欄「Debug：この時点の候補（…）」があります（遊ぶ人の画面には出ません）。開くと：

- 今の時点（観光地の訪問・宿・エピローグなど）の場面の並びと、それぞれの状態（済み・実行中・次の候補・とばす・未到達）と理由、条件の部品ごとの真偽。
- 今の選択肢の所で、隠れている選択肢と、その偽の部品。
- 街歩きでは、その都市のエピソード・クイズ・デートの「地図に出る条件」の部品ごとの真偽。

差し込みの場面が出ないとき、選択肢が出ないときは、まずここを見ます。

### 6.4 鍵のかかった札（`# hint:`）

デートの頭に `# hint: <一言>` を書くと、Debug モードがオンの間だけ、そのデートの開く条件（`# when:`）がかなうまで、街歩きの札の列の後ろに、鍵のかかった灰色の札として、その一言が出ます。押しても出発しません。**遊ぶ人には出ません**（まだ行けない行き先は、列に並びません）。

- 例：`/?debug&city=delhi&scene=free&progress=initial` ✓ で、インド門などデリーの6つのデートが「デリーの観光を一つ終えてから」の札で並ぶ（`gt_delhi_india_gate.ink` の頭の `# hint: デリーの観光を一つ終えてから`）。
- 出るのは書いた一言だけです。いつ・なぜ開くかをゲームは足しません。
- 開く条件のないデート・関係修復のデートの札は出ません。関係の値でも開くデートの札は、開かずに消えることがあります。どちらも `content:build` が注意で知らせます（[コンテンツ制作ガイド](CONTENT_GUIDE.md#条件の書き方) と、その「次の目標の札」）。

## 7. 仮の場面と見本の編

### 7.1 仮の場面（`data=fixture`）

準備中の旅行編の都市に、まだ場面がないとき、実在する1都市の場面を役割ごとに写した試験データで、画面と流れを確かめます。**自分が書いた場面ではなく、元の都市の写し**です。

- 元の都市は、`npm run dev` ではミラノ、`npm run dev:sample` では見本の街（データから自動で選ぶ）。
- 例：`/?debug&data=fixture&city=tashkent&scene=battle&target=tashkent_special_b` ✓（タシケントで、ミラノのスカラ座の推理クイズの写しが開く）
- 元の都市にない場面は作られず、一覧に「（この都市にはありません）」と出ます。
- 制作中の都市（物語・クイズがまだない）は、地図と交通だけを見られます：`/?debug&city=samarkand&scene=map`

### 7.2 見本の編（`npm run dev:sample`）

見本の編は、開発・テスト専用の架空の旅行編「見本の旅」（都市 `mihon`「見本の街」）です（[README](templates/sample_trip/README.md)、[技術設計の「見本の編」](../docs/02_TECH_ARCHITECTURE.md#見本の編)）。`npm run dev:sample` で起動すると、見本を含めて生成し、タイトル画面に「見本の旅」が並びます。

- 例：`/?debug&city=mihon&scene=battle&target=smp_mihon_special_b_market`（推理クイズB）、`/?debug&city=mihon&scene=battle&target=smp_mihon_special_c_library`（C）、`/?debug&city=mihon&scene=encounter&target=smp_mihon_bookmark_stall&progress=initial`（道中交流）
- 札の書き方の見本を、動く形で見たいときに使います（例：鍵の札 `# hint: 時計塔の番人と話したあとで`）。
- `npm run dev` では開けません（9.5）。

## 8. 声と音と演出を確かめる

場面の確認の下に、遊ばずに確かめる部屋があります。

- **「音と演出の見本を開く」**：登録された効果音・BGM・環境音・声を一つずつ鳴らし、天気・揺れ・時刻の色・品物の札・上の帯の手応え・「完」の判・写真の札・移動の演出・振動を見られます。声は場面ごとに並び、「IDで絞り込む」で探せます。音の設定はこの部屋の中だけのものです（iPhone は Web から振動しません）。
- **台詞の声の速さ**：Debug モードの間、≡メニュー →「ゲームの設定」と、この部屋の「声」で、0.75〜1.5倍（0.05刻み、「1.00倍に戻す」）にできます。高さは変わらず、鳴っている声にもすぐ効きます。値はこの端末に残り（セーブとは別）、Debug モードがオフの間は 1.00倍で鳴ります。
- **「ミニゲームの見本を開く」**：登録のミニゲームの結果・札の引数・絵・使っている場面を一覧し、物語なしで遊べます。「Debugで開く」で、使っている場面を開きます（[13 ミニゲームの仕組み](../docs/13_MINIGAMES.md)）。
- **「背景・人物・表情を確認」**（`?character-preview`）：衣装・ポーズ・表情、明るい背景と暗い背景、台詞の枠を切り替えて見ます（[コンテンツ制作ガイドの「プレビュー」](CONTENT_GUIDE.md#プレビュー)）。

## 9. はまりやすい所

### 9.1 クリアした都市は、開くとすぐエピローグになる（インド編）

インド編は、エピローグを読むと次の都市へ進む旅行編です。そのため、クリアした都市でエピローグを読んでいないと、ゲームは読み込んだときにすぐエピローグを開きます。Debug の「都市クリア後」はこの状態なので、`/?debug&city=delhi&scene=free` ✓ は街歩きではなく、デリーのエピローグ（見出し「六十年目の返事」）を開きます。ミラノ編はこうなりません。

クリアの前の夜の場面を見たいときは、「旅の開始時」から本筋を遊んで進めます。例：デリーの宿の屋上の告白「屋上の、言いたいこと」（`# when: episodes delhi >= 1`・`not couple`・`time night`、段階2から）。2026-11-16 の E2E は次のように開いています。

1. `/?debug&city=delhi&scene=battle&target=gt_delhi_main_red_fort_battle&progress=initial&stage=2` ✓ を開く。
2. レッド・フォートのクイズを結果まで遊び、「街歩きへ進む」。
3. 上の帯の「フラグ・時刻・段階」で「夜 19:00」を押して閉じる。
4. 宿の札に告白のデートが出て、「行く」が押せる。

### 9.2 時計は 9:00〜21:00 だけ

`time=` と帯の時刻は 9:00〜21:00 です。`time=22:00` ✓ は「「time=22:00」は使えません。time には 09:00〜21:00 の時刻を 19:00 のように書きます。」で断られます。21:00 は一日の終わりです。

### 9.3 変えられるのは、街歩きか一日の終わりだけ

場面の途中でフラグや時刻を変えると、保存している場面の位置・条件・時間枠と食い違い、遊びでは起きない場面になるからです。場面を終えるか、「移動画面に戻る（Debug）」で街歩きに戻ってから変えます（5章）。

### 9.4 下げた段階は、また上がる

Debug は段階だけを入れ、ゲームの規則は変えません。関係の値と終えたデートの数がもっと上の段階に届いていると、次に関係の値が動いたとき（選択や場面の終わりの関係の札）か、デートを終えたときに、遊びと同じくその段階まで上がります。一度地図に出たデート（告白など）の記録は残りますが、始められるかは今の段階で決まります。

### 9.5 見本の編のURLは、見本を入れて生成したときだけ開く

docs/10 のURLの例には見本の編（`city=mihon`）も入っていて、単体テストはどれも開けることを確かめています。それは、テストの前の生成が見本を含める（`content:build -- --with-sample`）からです。`npm run dev` で開くと「都市「mihon」は登録されていません。仮の場面の都市なら data=fixture を付けます。」✓ と断られます。`npm run dev:sample` で起動し直します。

生成物は開発サーバーとテストで共通の一つです。`npm test` を実行すると見本入りの生成物になり、次の `npm run dev`（や監視の生成）で見本なしに戻ります（[12 開発の手引き](../docs/12_DEVELOPMENT.md#生成と編集の流れ)）。

### 9.6 品物を持っていないことがある

Debug は、場面の前のデート・差し込みの場面・観光案内・道中交流を流しません。そこでしかもらえない品物は持っていません（2章）。それでも品物が足りずに始められない観察の後の交流は、一覧で選べず理由が出ます。同じ都市の場面がくれる品物なら、観光地の時点（`scene=occasion`）の `prep=` で先に流せます。

### 9.7 書き直したのに変わらない

生成し直していないか、ページを再読み込みしていないかです（1.1）。`npx vite` を直接起動したときは、先に `npm run content:build` を実行します。
