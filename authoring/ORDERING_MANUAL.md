# 発注マニュアル（声・絵）

ヒロインの声と、絵（立ち絵・アルバムの絵・ミニゲームの絵・描いた背景）を、作る人（人のことも、AI のこともあります）に頼み、届いたらゲームに入れるまでの手引きです。ヒロイン以外の人物の声は、3.6 と [人物の声の作り方](CHARACTER_VOICE_GUIDE.md)（配役のしかた・モデルの権利・依頼書・受け取り方）にあります。

- 元にしたのは、インド編（ゴールデントライアングル編）の発注です。声は 2026-11-12・13・15 の3回、絵は 2026-11-13 の依頼書（ミニゲームと会話の背景。リポジトリにはない）と 2026-11-16 の依頼書です。
- 決まりの元は [AGENTS.md](../AGENTS.md) です。札の正確な書き方は [コンテンツ制作ガイド](CONTENT_GUIDE.md)、作る順番は [新しい都市を1つ足す手引き](NEW_CITY_GUIDE.md)（手順13〜15・18・19）にあります。この手引きと食い違うときは、そちらに従います。
- 書き方は新しい都市の手引きと同じです：`<旅行編>` は `content/journeys/<旅行編ID>/`（ゲームが読む）、`<制作資料>` は `authoring/journeys/<旅行編ID>/`（ゲームは読まない）。

## 1. 頼むもの・頼まないもの

| 頼むもの | 使う所 | 頼む時期 | 新しい都市の手引き |
| --- | --- | --- | --- |
| ヒロインの声 | 台詞の行の `# voice:` | 台詞が確定してから（関門D） | [手順18](NEW_CITY_GUIDE.md#手順18-台詞の声) |
| 立ち絵 | 会話の舞台に立つ全身の絵（クイズの相手・出会う人・ヒロインの表情や衣装） | 人物の設計の後。台本の完成は待たない | [手順14](NEW_CITY_GUIDE.md#手順14-立ち絵と大きさ) |
| アルバムの絵 | 行の `# photo:`（アルバム・前回までのあらすじ・エンドロール） | 撮る行が決まってから（初稿の後） | [手順15](NEW_CITY_GUIDE.md#手順15-アルバムの絵) |
| ミニゲームの絵 | `# minigame:` の行の `art.<枠>` | 場面とゲームの絵の枠が決まってから | [手順19](NEW_CITY_GUIDE.md#手順19-ミニゲーム) |
| 描いた背景 | 会話の背景・街歩きの背景・タイトルの絵 | 舞台が決まってから（関門A） | [手順13](NEW_CITY_GUIDE.md#手順13-背景移動画面タイトルの絵) |

`voice:script` は、地の文と主人公を除く全員の台詞を抜き出します（2026-11-17。主人公には声を付けない）。ヒロイン以外の人物の声は、配役を決めてから頼みます（3.6）。

頼まないもの：

- **BGM・環境音・効果音**は頼まず、作者とライセンスを確かめたフリー素材（CC0・CC BY など）から選びます。選び方と出典の書き方は、新しい都市の手引きの[手順17](NEW_CITY_GUIDE.md#手順17-bgm環境音効果音)と、制作ガイドの「音楽（BGM）」「環境音」の節にあります。
- **観光地の写真**も頼みません。出典と権利を確かめた写真を使います（[手順5](NEW_CITY_GUIDE.md#手順5-観光写真を選び権利を確かめる)）。ミニゲームの背景にも使えます（[13 ミニゲームの仕組みの 2.12](../docs/13_MINIGAMES.md#212-絵と置き場所)）。

## 2. 旅行編ごとのフォルダ

渡した物は、渡したときのまま、旅行編の制作資料に日付で残します。後で台詞や絵を直したとき、何を頼んだかと照らし合わせるためです。

```text
authoring/journeys/<旅行編ID>/
  voice/
    README.md        … このフォルダの記録（渡した台本ごとの中身、届いた本数、付けなかった声）
    <日付>/          … 渡した声の台本（渡したときのまま）
    recorded.json    … 届いた声が言っている文（voice:tag が書く。手で書かない）
    cast.json        … ヒロイン以外の人物の配役（任意。3.6）
  art-requests/
    README.md        … 依頼ごとの開発の記録（絵がどこに入るか、届いたらどうつなぐか）
    <日付>.md        … 渡した絵の依頼書（渡したときのまま）
  characters/<人物ID>/<名前>.png  … 立ち絵の元の絵（可逆の PNG。配信しない）
  backdrops/         … 街歩きの背景の元の絵（配信しない）
```

- 日付は渡した日を `YYYY-MM-DD` で書きます（例 `voice/2026-11-15/`、`art-requests/2026-11-16.md`）。
- 声のフォルダの名前は `YYYY-MM-DD` か、同じ日に別の台本を渡すときは `YYYY-MM-DD_<英小文字・数字>`（例 `2026-11-17_cast`）です。この形の名前で `entries.json` のあるものだけを、`voice:script`・`voice:changes`・`voice:tag` が「渡した台本」として読みます。名前の順でいちばん後ろが「最新の台本」です（`2026-11-17_cast` は `2026-11-17` より新しい）。`2026-11-15b` のような名前は読まれません。
- 渡したら、そのフォルダかファイルをコミットします。渡した後は書き換えません。直したくなったら、次の発注に入れます。
- ゲームと `content:build` は `art-requests/` を読みません。`voice/` は声のツールが読み、`content:build` も `recorded.json` を読みます（4.2）。
- 例：[インド編の声の記録](journeys/golden_triangle/voice/README.md)、[インド編の絵の依頼の記録](journeys/golden_triangle/art-requests/README.md)。

## 3. 声を頼む

### 3.1 いつ頼むか

台詞が確定してから頼みます。編集者の改稿（手順10b）と台本の点検が済み、演出の札（手順16）やバランス（手順21）で文を変える予定もない時です（新しい都市の手引きの関門D）。

なぜ待つのか：声は1行＝1回の収録＝1ファイルです。文を一字でも変えると、その行は録り直しか、新しい行の発注になります。インド編では、改稿（#132・#136、2026-11-14・15）の前の 2026-11-12 の台本で声を作り始めました。そのため1回目の改稿で直した録音済みの1行（`gt_delhi_jama_masjid_guide_003`）を、2026-11-15 の発注で録り直しました。

### 3.2 頼む行

1. `npm run voice:script -- --journey <旅行編ID>` が、今の Ink から台詞を全部抜き出し、`artifacts/voice/<旅行編ID>/` に `heroine_lines.txt`（ヒロインの台詞だけの台本）と `entries.json`（全員の台詞のデータ）を書きます。`content:build` は要りません。メッセージと手紙・メモの行（`# phone:`・`# letter:`）は、誰の行でも入りません。
   - `entries.json` の行には、`speaker`（`# speaker:` の値）・`voice`（誰の声か。ヒロインは `heroine`、ほかの人は人物の `characterId`）・`speakerJa`（名札の名前）が付きます（2026-11-17）。同じ人の別の人物 ID（例：名前が分かる前の「男」）も、同じ `voice` になります。
   - `# speaker: enemy` の声は、ゲームと同じ決め方です。バトルでは相手（`presentation/characters.json` の `battleCharacters`。ないときはバトルの ID）、ほかの場面では頭の `# person:` の人物です。どちらもない場面の `enemy` の行は、`voice:script` が止まって、ファイルと行を出します。
2. 最初の発注は全部の行です（インド編 2026-11-12：877行）。
3. 2回目からは、`npm run voice:changes -- --journey <旅行編ID>` が出す行だけを頼みます。
   - 台本にない新しい台詞。
   - まだ録音していない行で、文が変わった行。新しい ID になり、前の ID は「録らなくてよくなった行」として台本の頭に書きます。
   - 録り直し：録音した行で、文が変わった行。同じ ID で録り直します。
4. 名前の入る行（`{player_name}`・`{player_address}`・`{heroine_name}`）は頼めません。遊ぶ人が決める名前は、録音した声では言えないからです。台本では【主人公の呼び名】のように出て、「★名前を含む」の印が付きます。先に、名前を言わない文に直します。例（2026-11-15）：マリアム廟の「ねえ。わたし、{player_address}って呼んでるでしょ。…」を「ねえ。わたし、いつもの呼び方で呼んでるでしょ。…」に直し、新しい ID `gt_agra_date_mariam_tomb_023` で頼みました。
   - ただ一つの例外（2026-11-17 の作者の判断「「……」まで録る」）：名前の手前まで録って、名前は字幕だけに出す行です。ヒロイン以外の人物の行で、`cast.json` の `lines` にその行の「入力する文」（`input`）を、名前の手前で止めた文で書いたときだけ頼めます（3.6）。例：ジャイプールのフロントの女性の「あら。ここ、名前が書いてある。ヒンディー語で。……『{player_name}』」は、「……」までを録ります。

**録り直しは、変わった行だけです。** 全部を新しく録り直すことはしません（2026-11-15 のユーザーの判断）。台詞を変えてよいときと、そのときのユーザーの言葉は、[シナリオ改稿のポイントの4章](SCENARIO_EDITING_GUIDE.md#4-守ること)にあります。

ID は `voice:script` が付けます。手で付けません。

- 形は「knot の名前_番号」です（例 `gt_delhi_date_lodhi_garden_001`）。ヒロイン以外の人物の行は「knot の名前_声の名前_番号」です（声の名前は `voice` の最初の `gt_` などを除いた部分。例 `gt_delhi_arrival_kamla_001`）。番号は knot と声ごとに数えます。
- 前に渡した台本の ID は、同じ声の行にだけ引き継ぎます（別の人が同じ文を言っても、その ID は使いません。2026-11-17 より前の台本の行はヒロインの行です）。
- 前に渡した台本と同じ文の行は、その文を最後に渡したときの ID のままです。
- 新しい行と文を直した行は、まだ使っていない番号になります。
- まだ渡していない行の ID は仮です。ほかの行が先にその番号を使うと、送られることがあります（2026-11-15 に、ナハルガル城の2行の仮の ID が `_028`・`_029` から `_031`・`_032` に送られた）。渡した `entries.json` に入った時に決まります。

### 3.3 一行は60字ほどまで

スマートフォンの画面では、一行60字ほどまでが目安です（理由と分け方は[シナリオ改稿のポイントの 2.9](SCENARIO_EDITING_GUIDE.md#29-一行の長さ)）。

- 頼む前に、まだ録音していない長い行を、文の切れ目で2行に分けます。分けた2行は、新しい ID の2つのファイルになります。
- 録音済みの行は、長さだけを理由に分けません。分けると録り直しになるからです（シナリオ改稿のポイントの4章：「少し長い」は台詞を変える理由にならない）。
- 字数を数える道具は、リポジトリにありません。`voice:script` の後に、まだ録音していない60字を超える行を次で出せます。

  ```sh
  node -e 'const lines = require("./artifacts/voice/<旅行編ID>/entries.json"), rec = require("./authoring/journeys/<旅行編ID>/voice/recorded.json").clips; for (const l of lines) if (!rec[l.id] && [...l.text].length > 60) console.log([...l.text].length, l.id, l.text)'
  ```

- 例（2026-11-15）：前の台本でまだ録音していない、60字を超える15行を、「。」の所で2行ずつに分けて30行として頼みました。言葉は同じです。台本には「前の台本の1行を録るつもりで、2つのファイルに分けて録ってください」と書きました。

### 3.4 発注のファイル

渡すファイルを `voice/<日付>/` に置きます。インド編の名前には `india_` が付いています。

| ファイル | 中身 | 作り方 |
| --- | --- | --- |
| `heroine_lines.txt` | その時点の全部の台詞。[ID] ごとに前の行・場面の分かれ道・表情・演出と台詞 | `voice:script` の出力のまま |
| `entries.json` | 同じ台詞のデータ（`id`・`text`・`file`・`knot`・`title` など） | `voice:script` の出力のまま |
| `voice_batch.txt` | 今回録る行だけの台本 | 手で作る（ツールはない）。`voice:changes` の一覧と、各場面の Ink から |
| `voice_guide.txt` | 声を作る人への説明書 | 最初の発注で作る。次からは「読み方は前の説明書と同じ」と書く |
| `Aibishub.txt`・`voicevox.txt` | ヒロイン以外の人物の依頼書（依頼先ごと。3.6） | `cast.json` があるとき `voice:script` が書く。手で直さない |

今回録る行の台本（[2026-11-15 の例](journeys/golden_triangle/voice/2026-11-15/india_voice_batch.txt)）の形：

- 頭に、作った日、録る行の数と内訳（新しい行・文を直した行・分けた行・録り直し）、部ごとの中身と、なぜ足したか。
- 読むのは「台詞：」の後ろだけ、ということ。ほかの欄は声の調子の手がかりで、読まない。
- 同じ所の別の分かれ道は、遊ぶ人にはどちらか1つしか聞こえないので、別々に録る、ということ。
- 録らなくてよくなった前の ID の一覧（「→ 新しい ID」つき）。
- 都市ごと・場面ごとに、場面の状況を2〜3行。その下に1行ずつ、次の箱を並べます。

```text
[gt_agra_tour_back_leg_004]　新しい行
  前の行（地の文）：帰りの車の中は、行きより静かだった。日差しが真上から照りつけ、エアコンの風が、やっと追いついてくる。
  場面の分かれ道：なし（帰りの車で、いつも流れる）
  表情：ふつう
  状況：後ろの席から、運転席のヴィノードへ。ふと気になって聞く、素直な好奇心。ていねいに、でも堅くならずに。このあとヴィノードが「一度だけ。学校の遠足で。あとは、ずっと外です」と答える。
  台詞：ヴィノードさんは、中に入ったこと、ありますか？
```

直した行には「前の文」の欄も足します。演出の札がある行には「演出」の欄が付きます。

説明書（[2026-11-12 の例](journeys/golden_triangle/voice/2026-11-12/india_voice_guide.txt)）には、次を書きました。

- 収録する AI にそのまま貼れる、人物と声の指示文。
- 台本の見方、場面の分かれ道の読み方、演出の札と表情の札の意味。
- 気をつけること：名前は声で言えない、叫び声・笑い声、読み間違えやすい語、外国語、同じ文の台詞、声を付けない行。
- ファイルのそろえ方：1行1ファイル、ファイル名は [ID]、WAV（48kHz か 44.1kHz、モノラル）、頭と終わりの無音は0.1〜0.2秒ほど、音量をそろえる、同じ声の設定で録る。

**`entries.json` に入れた行は、ツールが「渡した」と数えます。** `voice:changes` は、まだ録音していない行を最新の `entries.json` と比べます。そのため、頼んでいない行が入っていると、その行は変更の一覧から消えます。新しい行と直した行は全部、今回の台本に入れます。一部だけ頼むときは、`entries.json` を「前の台本の行＋今回頼む行」だけにします（2026-11-15 の最初の案はこの形。後で残りの40行も一緒に頼むことになり、全部の出力にした）。

### 3.5 声の札と出典

- `# voice:` は、声のファイルが届いた行にだけ付きます。書くのは `voice:tag` です。手では書きません。
- 新しく足した台詞には、声が届くまで `# voice:` を書きません。`# voice:` があるのに MP3 がないと、`content:build` が止まります（「声のファイルがありません」）。名前の入る行の `# voice:` も止まります（名前の手前まで録った声だけは通ります。3.6）。
- 録音した行の文を変えても、その行の `# voice:` は消さず、変えません。`content:build` の注意と `voice:changes` が、録り直しを知らせ続けます（4.2）。
- 声の作り方は、`<旅行編>/manifest.json` の `voiceCredits`（何の声か・作品・作者・ライセンス・確認日・ページ・作者が求める引用）に書きます。「出典・権利の一覧」の「声」に出ます。声のファイルのない旅行編に書くと止まります。インド編は音声合成 Irodori-TTS v4.1-Small（MIT License）です。
- 音声合成のモデルや素材のライセンスを確かめます。実在の人の声を参考にするとき（声の見本や、音声合成の参照音声）は、その人の同意を得て記録を残します。同意の記録を置く決まった場所は、まだありません（`<制作資料>/research/` などにメモを置く）。

### 3.6 ヒロイン以外の人物の声（配役と依頼書）

2026-11-17 のユーザーの依頼で、ヒロイン以外の人物の台詞にも声を付けられるようにしました。人物ごとに、AivisHub のモデル（AivisSpeech で使う）か VOICEVOX のキャラクターを選びます。選び方（10の特徴・モデルの探し方・権利・声の高さの測り方・配役の順番）と、届いた後の流れは [人物の声の作り方](CHARACTER_VOICE_GUIDE.md) にまとめました。ここには、道具の決まりを書きます。

- 配役は `<制作資料>/voice/cast.json` に書きます（任意。ゲームは読まない）。人物（`voice`。`entries.json` の `voice` と同じ）ごとに、10の特徴（年齢・性別・体型・身体的特徴・顔立ち・外見・性格・声の高さ・声質・質感・話す速度・話し方・抑揚・出身地・言語・アクセント）、エンジン（`aivishub` か `voicevox`）、モデル（ID・名前・話者・ページ・利用規約・ライセンス・クレジット表記。同じ人の声のモデルには同じ `voiceGroup`）、スタイル（ふだんのもの、表情ごとのもの、VOICEVOX のスタイル ID）、設定（エンジンの画面の名前で出す）、選んだ理由、作る人へのメモ（`noteJa`。1行ずつ）を書きます。場面の状況（knot ごと）、行ごとの入力する文・スタイル・注意、ユーザー辞書の語も書けます。形は `scripts/voice-cast.ts` にあります。
- `noteJa` の行のうち、「録音の前に：」で始まる行は、録る前に作者が確かめること（権利）です。依頼書では人物の欄のいちばん上と、頭の一覧に出ます。確かめることがない時は「録音の前に：なし（理由）」と書き、一覧には出ません。「同じモデル：」で始まる行は、同じモデルを使うほかの人物で、モデルの欄に出ます。
- 1つの旅行編の中では、1人の人物に1つのモデルを使います（旅行編が違えば同じでもよい）。例外は作者の判断（2026-11-17）「1〜6行の人には重複を認める。ただし、そのストーリー内では重複してはいけない」です。同じモデル（同じ `voiceGroup` の組は1つと数える）を使う人物のうち、7行以上の人物は1人まで。2人が同じ Ink ファイル（ストーリー）で話すことはできません。行数は、その人物の旅行編の中の台詞の数（依頼書の「台詞：全部で N行」）です。6 という数は `scripts/voice-cast.ts` の `SHARED_MODEL_MAX_LINES` にあります。
- 名前の入る行（3.2 の4）は、`lines` にその行の「入力する文」を、名前の手前で止めた文で書くと頼めます（作者の判断「「……」まで録る」）。依頼書では「★名前の手前まで録る。名前は字幕だけ」と出ます。入力する文に名前があると止まります。
- `cast.json` があると、`voice:script` は `heroine_lines.txt`・`entries.json` と同じフォルダに、`Aibishub.txt`（`aivishub` の人物）と `voicevox.txt`（`voicevox` の人物）を書きます。依頼先が違うので、ファイルを分けます。1つのファイルに、その依頼先の人物を全員まとめます。
  - このとき `entries.json` は、頼む行だけ（ヒロインの行と、配役した人物の行）です。配役のない人物の行は入らず、その ID は仮のままです（数は `voice:script` が出します）。名前の手前まで録る行には `spoken`（録る文）が付きます。
- 依頼書の形：頭に、この依頼について（同じモデルを使う人物の一覧）、録る前に（作者が確かめる権利の一覧・ユーザー辞書〈この依頼の台詞にある語だけ〉・エンジンの設定の注意）、箱の見方と読み方、ファイルのそろえ方、名前の入る台詞。次に目次（人物・モデル・行数）。人物ごとに、録音の前に確かめること、声（エンジン・モデル・話者・スタイル・設定・同じモデル・クレジット・ライセンス・ページ・利用規約）、人物（10の特徴）、選んだ理由、作り方の注意、出る場面。その後に、録る台詞（`# voice:` のない行と、録音した文が変わった「録り直し」の行）を都市・場面ごとに1行1つの箱で並べます。
- `voice:script` が止まるもの：ヒロインを書いた、同じ人物を2回書いた、上のモデルの決まりに合わない（7行以上の人物どうし、同じストーリーの2人）、そのエンジンにない設定を書いた（AivisSpeech には「間の長さ」がない）、入力する文に名前がある、ほかの旅行編の `journeyId`。注意に出るもの：台詞のない人物、配役した人物の台詞がない場面や ID のメモ、同じモデルなのに「同じモデル：」の行がない（またはその逆）。配役のない人物は、どちらの依頼書にも入らず、一覧が出ます。
- 渡したら、ヒロインのときと同じく `voice/<日付>/` に置きます（同じ日に別の台本を渡すときは `<日付>_<ラベル>`。インド編は `2026-11-17_cast/`）。`voice:script` が書いたまま置き、手で直しません。

## 4. 声を受け取る・録り直す

### 4.1 届いたら

1. **届いた物を確かめる。** 本数が台本の行数と合うか、ファイル名が [ID] か（`<ID>.wav` か `<ID>.mp3`）を見ます。インド編では、届いた zip が途中で切れていて、1本（`gt_agra_date_confession_011`）を取り出せなかったことがあります。数字と漢字の読みは、聞いて確かめます。
2. **MP3 にして置く。** 変換の道具はありません（手作業）。インド編は MP3・48kHz・モノラル・80kbps、-1 dB にそろえました。置き場所は `<旅行編>/public/assets/voice/<ID>.mp3` です（登録は要らない）。
3. **札を付けて記録する。**

   ```sh
   npm run voice:tag -- --journey <旅行編ID> --from <届いたファイルだけのフォルダ>
   ```

   届いた声ごとに、その行の前に `# voice: <ID>` を書き、`recorded.json` にその声が言っている文（その ID を最後に渡した台本の文と日付）を記録します。ヒロイン以外の人物の声も同じです（付けた行の数を、話す人ごとに出します）。名前の手前まで録った行（3.6）は、渡した `entries.json` の `spoken` も `recorded.json` に記録します。`content:build` は、この記録がある声だけ、名前の入る行の `# voice:` を通します。`--from` には、今回届いたファイルだけのフォルダを指します（前からある声まで記録し直さないため）。

   次の声は付けずに、理由を出します（ほかの声は付けます。1本でも付けないと終了コード1）：ファイル名が ID でない、渡した台本にない ID、今の文が台本の文と違う、`public/assets/voice/` に MP3 がまだない、今の台詞にその ID の行がない。
4. **確かめる。**
   - `npm run content:build` が通るか。どの行も使わない声のファイルは注意に出ます。
   - `npm run voice:changes -- --journey <旅行編ID>` で、録り直しの行が減ったか。
   - ゲームの設定「台詞の声を出す」をオンにして、場面で聞く。Debug の「音と演出の見本」の「声」でも、一つずつ鳴らせます。読み終えた場面の声は、旅の音楽室（旅を終えた後、「旅の記録」から）にも並びます。
5. **コミットする。** MP3・Ink・`recorded.json` を一緒に入れ、`voice/README.md` に届いた本数と、付けなかった声とその理由を書きます（インド編のコミットの例：「Voices: India heroine clips 0322-0409 (86: …)」と、付けなかった2本の理由）。ヒロイン以外の人物の声を初めて入れるときは、`manifest.json` の `voiceCredits` に、使ったモデルごとのクレジット（`cast.json` の `creditJa`）を足します（[人物の声の作り方](CHARACTER_VOICE_GUIDE.md#5-届いたら)）。

### 4.2 台詞を直したとき

- `npm run voice:changes -- --journey <旅行編ID>` が、録音した行は `recorded.json` の文と、まだ録音していない行は最新の台本と比べます。録り直しが要る行が先に出て、次に使われなくなった声、まだ録音していない行の変わった・なくなった・新しい台詞が出ます。ヒロイン以外の人物の行も比べ（同じ声の行どうしだけ）、どの行にも話す人の名前が付きます。ファイルは変えません。
- `content:build` も、録音した行の文が変わると、注意「録音した台詞が変わりました：<ID>（録り直しが必要）」を出します（一覧は `-- --verbose`）。この注意は、新しい台本を渡しただけでは消えません。作り直した声を `voice:tag` で記録すると消えます。
- 録り直しの流れ：`voice:script` で台本を作り直す → 変わった行だけの台本を作って渡す（3.4）→ 届いたら `voice:tag`（4.1）。
- 一覧に、意図していない変更が出たら、それは誰かが間違えて変えた台詞です。直した人に聞きます（[シナリオ改稿のポイントの4章](SCENARIO_EDITING_GUIDE.md#4-守ること)）。

## 5. 絵の依頼書

### 5.1 絵に要ることだけを書く

ユーザーの言葉（2026-11-13）：

> 絵の依頼書、絵に必要な情報以外の情報が多くてまじでダメです。絵の構図を考えて、その絵に必要な情報『だけ』を徹底的に指示してもらいたい

前の依頼書には、ファイルのパスやコード、Ink の札とその置き場所、自作の絵の登録、`content:build` の確かめ方、ゲームが絵をどう置くか、台本の食い違いが混ざっていました。描く人には、どれも要りません。

- **日本語で、短い文で書きます。**
- **1枚につき1項目にし、その項目だけで描けるようにします。** 1項目だけを写して、人にも画像を作る AI にも渡せるようにするためです。画風の言葉は項目ごとにくり返し、「共通を見る」のような参照はしません。
- **構図は自分で決めます。** アートディレクターのつもりで、視点とカメラの高さ、手前・中・奥に何があるか、それぞれが絵のどこか（左上からの横％・上から％）、どこを空けるか、なぜこの絵が効くかを決めます。描く人に選ばせません（昼か夜か、どの版の部屋か、など）。台本が食い違っていたら、その絵の場面に合う方を選び、食い違いのことは依頼書に書きません（開発の記録に書く。5.3）。
- **ゲームが上に重ねる所**（文章の窓、上の帯、ゲームが自分で描く物）は、構図の言葉だけで書きます。例：「下から25%は文章の窓に隠れるので、大事な物を置かない」「この縦の帯（横45〜55%）は模様を控えて無地に近く」。仕組みの説明はしません。
- **描かないもの**を絵ごとに書きます：別の絵で重ねる人物（ヒロインや名前のある人）、文字（看板の字が絵の一部なら、その字をそのまま書く）、ロゴ、実在の会社の名前。
- **頭は3行まで**：何の絵のまとまりか、何枚か、納品の形。終わりのまとめ（確かめ方・置き場所）は書きません。
- **書かないもの**：パス、コード、札の名前、登録、ビルドの手順、ゲームの仕組み（構図を決める所を除く）、「絵が無い間は…」、調べた日、出典。
- **納品の形**は、各項目の「大きさ」の行に書きます：PNG、透明かどうか、ピクセルの大きさ。WebP にするのはこちらの仕事なので、WebP のことは書きません。

### 5.2 1枚の項目の形

```text
## <番号>. <絵の名前>（ファイル名: <ID>.png）
- 大きさ：<幅>×<高さ>px（<縦横比>）／<背景あり・不透明 か 背景は透明>。PNG
- 何の絵か：<1〜2行。場面の空気と、この絵が伝えること>
- 画風：<その絵に合う4〜5語ほど>
- 参考にする絵：<添える絵を、何の絵かで書く>
- 視点：<目の高さ・向き・距離>
- 構図（位置は絵の左上からの横％・上から％）：
  - <上から下へ、または手前から奥へ>
- 描くもの：<欠かせない物を具体的に。形・素材・色・数>
- 描かないもの：<…>
- 時間・光・色：<…>
- 空けておく所：<画面で隠れる所や、ゲームが上に描く所。％で。なければ「なし」>
- 絵の中の決まった位置：<透明な絵だけ。足の裏が下の端、など>
```

- 対になる2枚（同じ部屋の昼と夜、同じ子の後ろ姿と振り返り）は、2枚目に、何が同じで何が変わるかをはっきり書きます。それでも2枚目だけで描けるように、部屋や人の説明もくり返します。例：2026-11-16 のラージューの2枚目「大きさ・位置・足・腰から下の向き・地図は1と同じにし、肩から上だけを変える」。
- 書いたら、描く人の目で1項目ずつ読み直します。要らない文を消し、描く人が聞き返しそうなことを足します。
- 例：[2026-11-16 の依頼書](journeys/golden_triangle/art-requests/2026-11-16.md)（6枚）。

### 5.3 開発の記録は別に書く

絵がどこに入るか、届いたらどうつなぐかは、依頼書に書かず、`art-requests/README.md` に依頼ごとの節として書きます。

- 表：番号・ファイル名・使う所・つなぐのにコードの変更が要るか。
- 絵ごとに：使う場面（ファイルと行、札）、届いたら置く所と足す札、要るコードの作業、気づいた食い違い。行番号は依頼書を作った日のものです。
- 頼む前に、その絵がその場面に出せるかを確かめます。例（2026-11-16）：ラージューの後ろ姿は、ミニゲームでは絵の枠を足すコードの作業が要り、デートの場面では、そのままでは2枚目の絵が出ません（向かいの人はいつも1枚目の絵）。コードを変えずに出す道と、コードで直す道を、記録に書きました。

## 6. 絵の大きさと参考の絵

**参考の絵を添えます。** 依頼書には何の絵かで書き（「今のラージューの立ち絵（正面で、地図を両手で差し出す姿）」）、ファイルは別に渡します。2026-11-16 に添えたのは、今の立ち絵の元の PNG（`<制作資料>/characters/<人物ID>/neutral.png`）と、アルバムの絵を JPEG にしたものでした。どれもリポジトリにある絵の写しなので、写しはリポジトリに入れません。

- 同じ人の新しい姿：その人の今の立ち絵。同じ子・同じ服・同じ背の高さで、と書く。
- 別の服の人：顔・髪・体つきは今の立ち絵、服はその服の出てくるアルバムの絵（例：踊るカムラは、桃色のサリーのアルバムの絵）。
- ヒロインの出るアルバムの絵：同じ日・同じ町のアルバムの絵に、服と持ち物を合わせる（例：昼のジャイプールの灰色の帽子・白いワンピース・黒いウエストバッグ）。表情は、その行の顔の札と[キャラクターバイブル](../docs/09_HEROINE_CHARACTER_BIBLE.md)から決める。
- その瞬間に、その絵を見る人の誰にでもある物だけを描きます。例：メヘンディ（手の模様）は、ジャル・マハルのデートを遊んだときだけなので、返事の場面の絵には描かない。アルバムの絵にする行も、その絵を見せたい道の人が皆読む行を選びます（例：返事の「はい」の道で、3つの選択の前の行）。

## 7. 絵を受け取る

1. **届いた物を確かめる。** 大きさ、透明かどうか、ファイル名が依頼書の ID か、描かないもの（文字・ロゴ・ほかの人）がないか、決まった位置（足の裏・頭の高さ）が依頼書のとおりかを見ます。
2. **WebP にする。** `npm run images:optimize` が扱うのは観光写真と立ち絵だけです。立ち絵は、元の PNG を置いてから `npm run images:optimize -- --journey <旅行編ID> --write` で、配信用の軽い版（非可逆の WebP 品質85、透明度は元のまま）を作ります（手順は[制作ガイドの「基本の衣装・表情の画像を足す」](CONTENT_GUIDE.md#基本の衣装表情の画像を足す)）。ほかの絵は手で変換します（インド編の街歩きの背景は品質70）。例：

   ```sh
   node -e 'require("sharp")(process.argv[1]).webp({ quality: 80 }).toFile(process.argv[2])' 届いた絵.png 配信する絵.webp
   ```

   品質は、スマートフォンの大きさで目で見て決めます。透明な絵は、透明のまま WebP になります。
3. **置いて、登録して、つなぐ。**

| 絵 | 置く所（配信する絵） | 自作の絵の一覧 | つなぐ所 |
| --- | --- | --- | --- |
| 立ち絵 | `<旅行編>/public/assets/characters/<人物ID>/<名前>.webp`（元の PNG は `<制作資料>/characters/<人物ID>/<名前>.png`） | 載せる | `presentation/characters.json`（人物の `imagePath`・`placement`、対決の `battleCharacters`）。名前で話す人は `progression/story.json` の `people` の `characterId`。大きく見える人は `figureScale`（0.5〜1.2） |
| アルバムの絵 | `<旅行編>/public/assets/album/<ID>.webp`（ID は英小文字・数字・`_`。すべての旅行編で1つだけ） | 載せない（置き場所で自作の絵とみなす。`tourism/catalog.json` に載せると止まる） | 行の `# photo: <ID>`（任意で `# photo_caption:`・小さく見せるだけの `# photo_show: small`）、思い出の呼び戻しは `# recall: <ID>` |
| ミニゲームの絵 | `<旅行編>/public/assets/minigames/<絵のID>.webp`（人物・物の枠は webp か png） | 載せる | `# minigame:` の行に `art.<枠> <絵のID>`。枠を足すときはコードの作業 |
| 会話の背景 | `<旅行編>/public/assets/…`（決まったフォルダはまだない。png・webp・svg） | 載せる | `romance/presentation.json` の背景の `imagePath`（写真なら `imageAssetId`） |
| 街歩きの背景 | `<旅行編>/public/assets/backdrops/<名前>.webp`（元の絵は `<制作資料>/backdrops/`） | 載せる | 都市ファイルの `backdropImagePath`（写真なら `backdropAssetId`。どちらか一方） |
| タイトルの絵 | `<旅行編>/public/assets/…`（例 `assets/title/<旅行編ID>.webp`） | 載せる | `manifest.json` の `titleArt` |

ヒロインの絵だけは、旅行編ではなく共通の層に入れます：登録は `content/presentation/characters.json`、元の絵は `authoring/characters/heroine/…`、一覧は `content/presentation/own-artwork.json`（[制作ガイドの「基本の衣装・表情の画像を足す」](CONTENT_GUIDE.md#基本の衣装表情の画像を足す)）。

札と欄は、絵を置いてから書きます。ない絵を指すと `content:build` が止まるからです（声の `# voice:` と同じ）。それまでは、札の案を開発の記録に書いておきます（2026-11-16 のアルバムの絵の `# photo: gt_album_j59` は案のまま）。

**自作の絵の一覧**は、絵を配信する層の `presentation/own-artwork.json` です。旅行編の `public/` の絵は `<旅行編>/presentation/own-artwork.json`（例：[インド編](../content/journeys/golden_triangle/presentation/own-artwork.json)）、リポジトリ直下の `public/` の絵は `content/presentation/own-artwork.json` に、配信時のパスを1行ずつ書きます。

```json
{ "noteJa": "Dreamscape のために作者が描いた、カムラの立ち絵（自作の絵）", "paths": ["assets/characters/gt_kamla/neutral.webp"] }
```

配信する絵は、出典つきの観光写真か、この一覧の絵のどちらか一方です（決まりは[技術設計の「画像の出典と自作の絵」](../docs/02_TECH_ARCHITECTURE.md#画像の出典と自作の絵)）。自作の絵は出典の一覧に出ません。別の人のイラストを流用しません。ほかの旅行編の `public/` の絵も使えません。旅行編の人物を、共通の `content/presentation/characters.json` に登録しません。

4. **確かめる。**
   - `npm run content:build`：どちらでもない絵（「出典のない画像」）、両方に載った絵、一覧にあるのに置いていない絵、ない絵を指す札や欄で止まります。立ち絵は形式・寸法・透過も見て、可逆のまま配信している絵は注意に出ます。アルバムは、ID にならないファイル名、同じ ID の絵が2つ、どの札も使わない絵（注意）を見ます。
   - 立ち絵は `npm run dev` の URL に `?character-preview` を付けて、大きさ（`figureScale`）と透過の縁を目で見ます。ミニゲームの絵は Debug の「ミニゲームの見本」の「Debugで開く」で見ます。
   - スマートフォンの幅で、その場面を見ます。
5. **コミットする。** `art-requests/README.md` の、その依頼の節に、届いた絵とつないだ所を書き足します。
