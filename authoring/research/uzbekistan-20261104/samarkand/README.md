## 交通判断

11地点の異なる地点間110方向を、バス・鉄道・トラム・タクシーの4モードで確認した。`transit-decisions.json` は440件の採否と理由・出典を持つ。徒歩は同一点0分を含む121経路、タクシー110経路、バス47経路を登録した。

| モード | 採用 | 今回の地点間では不採用 | 対象外 | 未確認 |
| --- | ---: | ---: | ---: | ---: |
| バス | 47 | 63 | 0 | 0 |
| 鉄道 | 0 | 0 | 110 | 0 |
| トラム | 0 | 110 | 0 | 0 |
| タクシー | 110 | 0 | 0 | 0 |

不採用は「路線が存在しない」という意味ではない。停留所への徒歩、待ち時間、経路の向きまで含む今回のゲーム用モデルで、有利な接続を採用できなかったという編集判断である。モデル上の比較を現地での最速経路の保証としない。鉄道は都市間列車を市内移動へ流用しない。

バス31番は大学大通り側とシヨブ方面、17番はシャーヒ・ズィンダ側とウルグベク天文台方面の往復停留所を確認した。31番の往路・復路の停留所差を別に扱う。31番から17番への接続も登録対象とする。45番は旧ガイドの案内と現在の利用者編集台帳の運休表示が一致しないため採用しない。トラム2番は実在するが、シヨブから北西の鉄道駅方面へ向かう路線であり、今回の中心部・東側の地点間移動には採用しない。

公共交通は各人がカードを持つ前提で1乗車2,000スム×2人=4,000スム。乗り換え時は割引を当て込まず2乗車8,000スムとする。2026年5月の公式案内はATTOの時間制乗り換え割引を掲載しているが、ゲーム内ではカード別の利用履歴や実際の改札時刻を再現しない。旧記事の現金3,000スムを現行運賃として使わない。

徒歩・タクシー・バスの所要時間はいずれも `game_model`。徒歩はタシュケント通り、レギスタン通り、ルハバードと大学大通り、シャーヒ・ズィンダからアフラシャブ方面などの接続を手動で構成し、その街路グラフの最短経路を使った。座標の直線距離から実測距離を生成していない。タクシーは歩行者区間を避ける車道グラフに配車8分と車止めからの徒歩4分を加算。料金は1台2人で `15,000 + 車内分数 × 2,000` スムのゲーム用設定で、現地会社の公定・実測運賃ではない。`route-model.json` に全方向の通過地点・選択経路・モデル値を保存した。

## 写真と観察資料

10地点すべてにWikimedia Commonsの実写真を保存した。原作者・原寸・配信サイズ・ライセンスの取得記録は `selected-images.json`、不採用を含む検索結果は `*-image-candidates.json`。APIの縮小画像サイズと実際の配信サイズに相違があったため、保存済みJPEGの寸法を再確認して台帳へ反映した。画像への描き足し・AI生成・色変更は行っていない。初回採用8枚はCommonsの縮小配信画像をそのまま保存。後述の差替2枚は原本からEXIF方向を適用し、長辺1920px・JPEG品質89で縮小保存した。CC BY-SAの作品は縮小版も同じライセンスで提供する。ライセンスURLは同一ライセンスのHTTPS URLに正規化した。

独立レビューにより、博物館正面の現代レリーフと天文台の現代エントランスが主題の写真は公開対象から外した。写真のライセンスとは別に、現代の建築・装飾の利用許諾を確認できなかったためである。博物館は館内の7世紀壁画（Khusen Rustamov / Koshkinhome、CC BY-SA 4.0）、天文台は15世紀の観測遺構（Alaexis、CC BY-SA 2.5）を主題とする写真へ変更済み。旧写真はpublicに残さず同名を置換し、旧metadataのみ `replaced-modern-subject-images.json` に保存。採用候補の新metadataは `replacement-image-candidates.json` に保存した。4メインの観察画像・ホットスポット・ハッシュには変更がない。

全10写真を目視確認済み。4メインのホットスポットはそれぞれ、レギスタンの3正面、シャーヒ・ズィンダの青い壁面、グーリ・アミールの畝のある青いドーム、ビビハニムの大アーチに配置した。写真から読み取れる形と、資料から知る歴史を区別している。クサムにまつわる話は伝承と明記。グーリ・アミール内部の翡翠の墓石は資料であり、外観写真に写っているとは扱わない。

観察資料の主な出典はウズベキスタン観光サイトの[レギスタン](https://uzbekistan.travel/en/o/registan/)、[シャーヒ・ズィンダ](https://uzbekistan.travel/en/o/the-memorial-ensemble-shahi-zinda/)、[グーリ・アミール](https://uzbekistan.travel/en/o/gur-emir/)、[ビビハニム](https://uzbekistan.travel/en/o/bibi-khanym/)。文章は短い日本語の独自要約とし、観察事実と解釈を分離した。

## ファイルの扱い

- `content/cities/samarkand.json`、`content/travel/samarkand.json`、`content/travel/samarkand-settings.json` が実行時データ。
- `catalog-fragments.json` は共通の画像・背景・デート先・観察・画像ハッシュ・出典台帳へ取り込むための初回インポート断片。統合後の編集は共通台帳または都市バンドルで行う。
- `assemble-city.py` は今回の初回組み立て手順の記録。ネットワークを使わないが、後日の台帳編集を上書きするため、通常のビルドから呼ばない。
- `fetch-images.py` と `download-selected.py` は今回の画像取得手順の記録。実行時・通常ビルドには不要。

検証：都市・旅行・設定・画像・背景・観察資料・デート先の既存Zodスキーマを通過。全110方向×4モードの重複・欠落・出典参照、採用経路の存在、4観察画像のSHA-256、10画像の実寸も確認する。統合後の全体検証は親作業の `content:check`・型検査・テスト・ビルドに含める。
