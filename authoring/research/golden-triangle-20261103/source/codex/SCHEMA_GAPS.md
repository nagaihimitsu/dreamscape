# 既存のスキーマ/実装との残差

現行 `travelPlaceSchema` と `travelRouteSchema` は書き込み可能だが、曜日や通貨の独立フィールドがなく、料金は数値だけ。 `travelCatalogSchema` は場所/経路/Event IDのみチェックし、`scripts/travel-validation.ts` がイベント実体とすべての徒歩経路を別途強制する。

今回の26+資料は以下を変更しない：元の `src/content/*`、ミラノ脚本、セーブ形式、UI、観光カタログ。これはGitHubリポジトリ変更ではなく調査データの更新。24件の未確認橋跨ぎ徒歩を捏造しないため、全地点対全地点徒歩必須をCodex側で再設計し、タクシー到達を代替として認める必要がある。
イベントIDとゲーム本体のInk/クイズ/敵/デート定義の照合は未完了。
