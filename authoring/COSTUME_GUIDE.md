# ヒロインの着替えの作り方

ヒロインの衣装を足して、場面に合わせて着替えさせる手順です。読む人は、制作者と、作業をする AI の会話です。衣装の絵を**1枚**用意すれば、12表情の静止画と動く立ち絵まで、1つのコマンドで作れます（2026-11-20。最初の例はサリー `saree_01`）。

動く立ち絵の仕組みや、手で1つずつ行う手順は [動く立ち絵の作り方](LIVE_PORTRAIT_GUIDE.md)、なぜこの形になったかは [動く立ち絵の試作](LIVE_PORTRAIT_TRIAL.md) にあります。

## 1. 流れ

1. 衣装ID と、いつ着るかを決める（[2.](#2-決めること)）。
2. 作者に、服だけを変えた全身の絵を1枚、背景を透明にして描いてもらう（[3.](#3-衣装の絵を頼む)）。
3. `add-costume.py` を1回実行する（[5.](#5-1つのコマンドで作る)）。
4. できた12表情を並べた画像と、ゲームの確認画面で見る（[6.](#6-見て確かめる)）。
5. 着る場面を `wardrobe` に書く（[7.](#7-着る場面を書く)）。
6. 確かめて、PR で取り込む（[8.](#8-ゲームに入れる)）。

## 2. 決めること

- **衣装ID**：小文字・数字・`_` で、`<衣装の名前>_01` の形（例 `saree_01`、`kurta_01`）。`characters.json` の衣装の ID と、絵のフォルダの名前になります。
- **いつ着るか**：場面・都市・国・地域で決められます（[7.](#7-着る場面を書く)）。物語の途中で着替える・遊ぶ人が選ぶ、という決め方は、今の仕組みにはありません（足すなら、条件で衣装を選ぶ仕組みと、着ている服の保存が要る）。
- **実在の場所に合うか**：モスクや寺院のように、肌を覆う決まりや貸し出しの服がある所があります。その場面の服がその場所に合っているかを確かめます。現地の服を着る場面は、その土地の服への敬意を持って描写します。

## 3. 衣装の絵を頼む

基本の衣装の元の絵 [`default_01/standing_01/neutral.png`](characters/heroine/default_01/standing_01/neutral.png) を見本に渡し、次を頼みます。

- **同じポーズ・同じ位置・同じ大きさで、服だけを変えた全身の絵**（1024×1536 が望ましい。数画素ずれても、顔に合わせて直せます）。
- **顔（目・鼻・口・輪郭）の位置と大きさは変えない。** 表情・まばたき・口は基本の衣装の顔から作るので、顔は描き直されても基本の衣装の顔に置き換わります。
- **背景は透明に。** 白い背景の絵だと、透ける布（サリーの肩から垂れる布など）を私たちの側ではきれいに抜けません。透明にした絵を作者に用意してもらいます。
- 帽子・髪型・耳飾りは、変えても構いません。
  - 帽子と髪が基本の衣装と同じ絵：基本の衣装の頭をそのまま重ねます（「同じ頭」）。
  - 帽子なし・髪型が違う・耳飾りがある絵：その絵の髪と耳飾りを残し、顔だけをそろえます（「髪を残す」。サリー）。
- 顔の向きや大きさが違う絵（横向き・アップなど）は、この手順では作れません（[動く立ち絵の作り方の 4.](LIVE_PORTRAIT_GUIDE.md#4-新しい人物顔の違う衣装に作るとき)）。

## 4. 道具を準備する

1回だけ行います。

- [uv](https://docs.astral.sh/uv/)（Python を動かす）と Node.js 22.17 以上。
- Mesh Avatar Studio（層を作る道具）：

  ```sh
  git clone https://github.com/shinshin86/mesh-avatar-studio
  cd mesh-avatar-studio
  git checkout 406714b
  npm install
  npm run doctor
  ```

  ゲームが使う部品（動く立ち絵を描く部分）は Dreamscape 用に直してありますが（[動く立ち絵の作り方の 6.](LIVE_PORTRAIT_GUIDE.md#6-動かす部品を作り直すとき)）、ここで使うのは層を作る道具だけなので、直す前のままで構いません。

## 5. 1つのコマンドで作る

衣装の絵を受け取ったら、リポジトリの直下で次を実行します。

```sh
uv run --with pillow --with numpy --with opencv-python-headless python \
  authoring/characters/heroine/default_01/mesh_avatar/add-costume.py <衣装の絵.png> \
  --id <衣装ID> --studio <mesh-avatar-studio のフォルダ>
```

[`add-costume.py`](characters/heroine/default_01/mesh_avatar/add-costume.py) がすること：

1. 衣装の絵を `authoring/characters/heroine/<衣装ID>/mesh_avatar/outfit.png` に残す。
2. 絵の顔を基本の衣装の顔に合わせ、1024×1536 にする（大きさ・回転・ずれを表示）。
3. 帽子と髪が基本の衣装と同じかを調べて、「同じ頭」か「髪を残す」かを決める（違いを表示。`--head same` / `--head keep-hair` で指定もできる）。
4. 12表情の元の絵（可逆の PNG）を `authoring/characters/heroine/<衣装ID>/standing_01/` に作る。
5. 動く立ち絵を `public/assets/characters/heroine/<衣装ID>/standing_01/avatar/` に作る。
   - 同じ頭：骨組みと層だけ。顔は全衣装で共通のフォルダ（`avatarFace`）を使う。
   - 髪を残す：骨組みと層に加えて、衣装の髪と耳飾りを切り抜いた顔の差分の写し（`built/sprites/`）。
6. `characters.json` に衣装を登録し（12表情の WebP、`avatar`、同じ頭なら `avatarFace`）、`own-artwork.json` に絵を1枚ずつ書き、`npm run images:optimize -- --write` で配信用の WebP を作る。
7. 12表情の顔を並べた画像 `<mesh-avatar-studio>/work/costume_<衣装ID>/check.png` を作る。

着る場面（`wardrobe`）は書かず、コミットもしません。作り直すときは `--replace` を付けます（前の絵と登録を置き換えます）。

## 6. 見て確かめる

1. **`check.png`**：12表情の顔を並べた画像。前髪・眉・耳飾りのまわりに継ぎ目がないか、目から別の目がのぞいていないか、口が残っていないかを見ます。
2. **`npm run content:build`**：ファイルと登録がそろっているか。
3. **ゲームの確認画面**：`npm run dev` で `?character-preview` を開き、衣装を `<衣装ID>` にして、表情を切り替えます。動く立ち絵が静止画と同じ位置・大きさで動くか、表情の顔に変わるか、まばたきで頬の赤みが消えないかを見ます。
4. **大きさ**：柄の細かい服ほど大きくなります（サリーは動く立ち絵が約2.7MB、静止画12枚で約1.8MB）。ヒロインの絵は共通の層に入るので、「オフラインで遊ぶ」の共通のファイルが増えます。

## 7. 着る場面を書く

`characters.json` の `wardrobe` に書きます。優先の順は、**場面 → 都市 → 国 → 地域の標準の衣装 → 基本の衣装**です。旅行編の場面・都市は、その旅行編の `content/journeys/<旅行編ID>/presentation/characters.json` に書けます（ミラノ編はここに `wardrobe.cities` がある）。

```json
"wardrobe": {
  "scenes": { "gt_delhi_date_india_gate": { "costume": "saree_01" } },
  "cities": { "jaipur": { "country": "IN", "costume": "saree_01" } }
}
```

- `scenes` のキー：デートID・バトルID・観光地ID・都市エピローグのエピソードID。その場面の間だけ着ます。
- `cities` のキー：都市ID。`country` に国のコード（インド編は `IN`）を書きます。
- 国ごと・地域ごとの標準は、共通の `content/presentation/characters.json` の `countries`・`regions` に書きます。
- 衣装の絵が届いていない（`neutral` がない）衣装を書くと、基本の衣装が出ます。

## 8. ゲームに入れる

1. 変更の範囲に合わせて確かめます：`npm run content:build`、型の確認（`npm run typecheck`）、文書を変えたら `npx vitest run scripts/docs-links.test.ts`。
2. 作業用の枝からコミットし、PR を出し、GitHub の自動の確認が通ったら squash で取り込みます（[AGENTS.md](../AGENTS.md)）。
3. 取り込むと公開されます。スマートフォンで、その場面を開いて見ます。

## 9. うまくいかないとき

| 起きたこと | 原因 | 直し方 |
|---|---|---|
| `could not line the face up with default_01` | 顔の向き・大きさ・絵柄が違う | 同じポーズ・同じ顔の位置で描き直してもらう。顔が違う衣装は [動く立ち絵の作り方の 4.](LIVE_PORTRAIT_GUIDE.md#4-新しい人物顔の違う衣装に作るとき) |
| 表示の大きさが 0.97〜1.03 を外れる、回転が1度・ずれが10px を超える | ポーズや顔の位置が違う | 同上 |
| 帽子と髪が同じなのに「髪を残す」になった（またはその逆） | 髪の描き直しが大きい | `--head same` か `--head keep-hair` で指定する |
| 髪を残した衣装で、閉じた目から瞳がのぞく | 瞳の色を耳飾りと取り違えた | `new-costume.py` は目のまわりを耳飾りと見なさない（2026-11-20 に直した）。別の場所で起きたら、耳飾りの見分け方（`gold`）を直す |
| 透ける布のふちが白く汚い | 白い背景の絵から抜いた | 背景を透明にした絵をもらう |
| 前髪や耳飾りの一部が、表情によって消える | 衣装の髪の範囲（hairmask）に入っていない | 作業フォルダの `hairmask-aligned.png` を見る。毛先が抜けているなら、骨組みの下書きの毛束を足して作り直す（[動く立ち絵の作り方の 4.](LIVE_PORTRAIT_GUIDE.md#4-新しい人物顔の違う衣装に作るとき)） |

## 10. 表情を足したとき

表情は基本の衣装の絵で描いてもらい、共通の顔に足します（[動く立ち絵の作り方の 2.](LIVE_PORTRAIT_GUIDE.md#2-表情を足すとき)）。そのあと、**ほかの衣装ごとに `add-costume.py` を `--replace` で実行し直します**（その衣装の静止画に新しい表情を作り、髪を残す衣装は顔の差分の写しも作り直します）。元の衣装の絵は `authoring/characters/heroine/<衣装ID>/mesh_avatar/outfit.png` にあります。
