- 例は、この2回の実際の直しから引きました。「前」「後」の文は、その回の差分のままです（その後の直しで、今の本文と少し違う所があります）。
- 決まりの元は [AGENTS.md](../AGENTS.md) です。札の正確な書き方は [コンテンツ制作ガイド](CONTENT_GUIDE.md)、文章の規格は [06 文章の規格](../docs/06_WRITING_STANDARDS.md) にあります。この手引きと食い違うときは、そちらに従います。

## 1. なぜ、書く人と直す人を分けるのか

ユーザーの言葉（2026-11-16）：

> シナリオを作る時に考えるAI(シナリオ担当)は、面白いシナリオを考えることに集中し(リソースを割き)
> それを編集者が添削して整えて行った方が もっと面白いものを作れると思うから

面白い話を考える仕事と、初めて読む人の目で一行ずつ確かめる仕事は、頭の使い方が違います。一人で両方をすると、どちらかが薄くなります。それに、書いた人は自分の意図を知っているので、画面に書いていないことも「伝わっている」と感じてしまいます（2.1 の「知識の呪い」）。だから、書く人は面白さに力を使い、意図を知らない別の人（編集者）が読んで整えます。

### 書く人（シナリオ担当）が気にしなくてよいこと

- 説明が足りているか、その説明をどの行に置くか。
- 地の文の量の加減。顔の札・`# leave:`・効果音を付ける行など、札の細かい付け方。
- 一行の長さ、呼び名や表記のそろい方、名札が正しく出るか。

書く人が力を使うのは、人物・出来事・意外な展開・結末と、場面の面白さです。初稿は、多少くどくても、足りなくてもかまいません。ただし、ゲームや保存が壊れるもの（`content:build` が止めるもの）、AGENTS.md の決まり（名前の差し込み、事実と出典、クイズの呼び方）、その編の設計の決まり（インド編なら「主人公は話さない」）は、書く人も守ります。編集者は、それをもう一度確かめます。

書く人がしておくと助かること：場面の意図（この人はなぜここにいるか、どこで驚かせたいか、何を謎として残すか）を、Ink のコメント（`//`）か設計の資料に残すこと。編集者は、その意図と画面の差を探します。

### 編集者が受け持つこと

- 初めて遊ぶ人の目で、すべての道（選択肢・クイズの正解と不正解・`cond(...)` の両側）を読み、分からない所・迷う所・くどい所を見つける。
- 語り方を直す：地の文、ほかの人物の台詞、札、物、行の分け方、呼び名。
- 4章の決まり（声の録音、名前、事実など）が守られているか確かめる。
- 自分で決めてはいけないことを、書く人かユーザーに聞く。

### 編集者がしてはいけないこと

- **話の向きを変える。** 出来事・結末・選択肢と効果・条件・場面の順・登場人物は変えない。変えるのは語り方だけです。1回目のユーザーの注文も「ストーリーの内容を変えずに細かい部分のリライトで」でした。
- **謎を説明してしまう。** 読む人を先へ引っぱる謎を、先回りして解かない（2.2）。
- **人物の声を平らにする。** 分かりやすくするために、皆を丁寧な説明口調にしない。ぶっきらぼうな人はぶっきらぼうなまま、皮肉な人は皮肉なままにする。
- **良い場面を直す。** 「直す所なし」も診断の結果です。2回目の改稿のときは、インド編はもうかなり良く、「直しすぎ」がいちばんの危険でした。
- **話の事実を自分で決める。** 人の関係・過去・誰が何をしたかを変えたくなったら、案を並べて、書く人かユーザーに聞く。

なぜここまで線を引くのか：編集者が筋に手を入れ始めると、書く人が面白さに集中できなくなり、分けた意味がなくなるからです。

インド編の1回目では、次の3つを「ユーザーに決めてもらうこと」として、案をつけて出しました（今の本文は、勧めた案になっています）。

| 迷った所 | 今の文 |
| --- | --- |
| カムラが移る「ジャイプールの息子の家」は、孫アマンの父の家か、叔父の家か（式では花婿側の親戚が「デリーから来た」） | アマンの知らせ「祖母も、もうジャイプールの叔父の家に移っています」 |
| アーグラでサミールが「新婚では、なかったんですね」と謝ったのに、ジャイプールの選択肢が「サミールさんは、まだ新婚だと思ってる」 | 選択肢「サミールさんの帳面には、また何か書いてある」 |
| フィナーレの冒頭で、城門の係員がクイズ4の答え（夜のショー）を先に言っていた | 係員「暗くなってから？　昼の券で入れるのは、日没までですよ」 |

## 2. 直す所と直し方

11の点を、読む順に並べました。どの点も「何が起きているか」「なぜ困るか」「どう直すか」の順です。

### 2.1 知識の呪い：画面に出たことだけで読む

遊ぶ人が知っているのは、画面に出たことだけです。行の字、名札、背景の絵、立ち絵と表情、選択肢、カード（品物・紙・携帯・図鑑の小窓）、クイズの画面。Ink のコメント、設計の資料、ID、通らなかった分かれ道、まだ遊んでいない場面は、遊ぶ人に届きません。書いた人は、自分が知っていることを読む人も知っていると思い込みます（Pinker のいう「知識の呪い」）。

- 一度目は、意図の資料を閉じて、画面に出る行だけで読む。
- 二度目に、意図（コメント・設計の資料）と比べる。**意図にあって画面にないもの**が、直す所の候補です。
- 1回目の診断では、場面ごとに「初見の人に伝わること」「作者の意図」「伝わっていないこと」の3つを書いてから、指摘に進みました。

例（タージ・マハル。1回目）：タージが「皇帝が亡き妃のために建てた墓」だということが、観光案内にも本筋にも一度も書かれていなかった。書いた人には当たり前でも、遊ぶ人には当たり前ではない。

- 前：「ニキルが、練習どおりの台詞を始める。」
- 後：「ニキルが、練習どおりの台詞を始める。皇帝が亡き妃のために建てた、この白い墓の話からだ。」

### 2.2 謎と混乱

読む人が「何が分からないか」を言えるなら謎です。謎は、先を読む力になるので残します。何が分からないのかも分からないなら混乱です。混乱は直します（Dean Hale の「Confusion vs. mystery」による。混乱は読む人を怒らせ、謎は引きつける）。

- 例（デリー到着。1回目）：カムラが書いた見どころの一覧の妙な注釈と、彼女の「説明したら、つまらない。」は謎なので、先回りして解かなかった。
- 例（レッド・フォートのフィナーレ。1回目）：ユーザーは「録音の声」が何の声か分からず、光と音のショーが始まったことにも気づかなかった。これは混乱なので直した。
  - 前：「ラホール門で、次の回の券を三枚買う。暗い城壁に光が走り、録音の声が、皇帝たちの時代を語り始めた。」
  - 後：「ラホール門で、次の回の券を三枚買う。中へ入ると、暗い城壁に光が走った。」／「語り手の姿はどこにもない。どこからか、録音の語りが流れ出した。この城の皇帝たちの時代の話だ。」

**クイズの答えを先に言わない。** クイズも謎の一つです。クイズの前の前振りは、問いの形にします。1回目の最初の直しでは、城門の係員が「夜のショーの券がある人だけ」と言ってしまい、クイズ4の答えが場面の最初の数タップで出ていました。見直しで「昼の券で入れるのは、日没までですよ」に弱めました（別の入り方がありそうだとは分かるが、何かは言わない）。答えは、クイズの後に、正解と不正解の両方の道で言います。

台詞の裏（言葉と違う気持ち）は、画面のどこか（仕草・物・前の行）に手がかりが一つあるかを見ます。手がかりのない裏は、読む人に届かない秘密です。

### 2.3 置き場所

足すより、置き場所です。正しい事実を一つ、効く行の近くに置きます。まとめて場面の最初に並べません。

1. **直前（1〜3行前）**：何かが始まる、誰に話しているか、知らない言葉、反応（笑い・涙・怒り）の原因。
2. **場面の頭（最初の数行）**：誰が・どこで・いつ・何のために（2.4）。
3. **前の場面**：名前・関係・約束などの前振り。ただし、**必ず通る場面**に置く。
4. **直後（1〜2タップ以内）**：驚かせたい一行の後に、それを読み解く一行（聞き手の反応など）。わざと遅らせる所だけ。

会話がはずんでいる最中に、説明を挟みません。移動・沈黙・仕草の合間の静かな行に置きます。

**順不同の場面と分かれ道。** 観光地の場面は、どの順にも遊べます。前振りが、遊ぶ人のまだ通っていない場面や、選ばなかった枝にだけあると、ないのと同じです。

- 前振りは、必ず通る場面（到着、その観光地の案内、フィナーレの前の本筋）に置く。どれが必ず通るかは、`when:` の札と [場面の並び](#52-読み物を用意する) で確かめる。
- 回収の側は、前振りを見ていない人にも通じる言い方にする（「宿の娘」のような役割の名詞）。見た人には確認、見ていない人には紹介になる長さにする。
- 説明を、クイズの正解か不正解の片方、選択肢の一つ、`cond(...)` の片側にだけ置かない。全部の道に置くか、合流した後に置く。

**山場から逆にたどる。** 山場の一行が効くには、その前に決め手の事実が要ります。山場から逆にたどって、その事実が画面のどこにあるかを指させるか確かめます。

例（レッド・フォートのフィナーレ。1回目）：カムラの「……わたしも。わたしも、です。遅くなったけど」が六十年前の告白への返事だと分かるには、①プラカーシュは亡くなった夫、②その夜に言われたのは「好きだ」、③彼女は返事をしなかった、の3つが要る。③はあったが、②は「ずるい言い方で」何かを言われた、までで、①はどこにもなかった。①は必ず通る到着の名乗りに、②は山場の直前のカムラの台詞に置いた。

- 前（到着）：「カムラ、七十九歳。この家に六十年住んで、数日のうちに、ジャイプールの息子の家へ移る。」
- 後（到着）：「カムラ、七十九歳。この家に六十年。夫のプラカーシュは先に逝った。数日のうちに、ジャイプールの息子の家へ移る。」
- 後（山場の直前）：「プラカーシュ。あの冬の夜、ここのショーの暗がりで、言ったでしょう。好きだ、って」

### 2.4 誰が・どこで・いつ・誰に

場面の頭の数行で、四つを言えるか確かめます：**誰が**（名前と、二人との関係）、**どこで**（背景の絵がなくても分かるように）、**いつ**（時刻か、前の場面からどれくらい後か）、**何のために**（二人がここに来た理由、相手の目的）。

- 背景の絵だけでは、どこか分からない人がいます。背景が変わった直後の行で、着いた所と時を言います。時間の経過は「しばらくして」より、時刻・明るさ・人の様子の変化で見せます。
- 観光地の写真で見せる場面（観光案内など）では、`# background:` を書いても絵が替わらないことがあります（2回目の点検で確かめた）。場所を移るなら、地の文で言います。

例（メヘターブ・バーグ。1回目）：昼のタージから夕方の対岸の庭へ、黙って移っていた。

- 前：「川を渡ったメヘターブ・バーグの岸辺。夕日に染まるタージが、川向こうに正面から見えた。」
- 後：「夕方、一行は川を渡った。メヘターブ・バーグの岸辺。夕日に染まるタージが、川向こうに正面から見えた。」（その前に、二人が付いていく理由の一行「杖の先が、二人を指した。新婚のお二人も、ぜひ、と。客たちの笑い声に押されて、断りそびれた。」も足した）

**誰に話しているか。** 舞台に立つのはヒロインと向かいの一人だけです。その場にいない相手・空いた席・写真に話す場面は、地の文がどちらを向いているかを見せます。

例（レッド・フォートのフィナーレ。1回目）：カムラは亡き夫に話していたが、画面には誰もいない所へ話していることが出ていなかった。

- 前：「…膝の上に、香辛料の袋。唇が動いている。」
- 後：「すぐ隣は、空いている。カムラはそちらへ顔を向け、誰かと話すように唇を動かしていた。」（前の場面のアマンの台詞にも「誰もいない椅子に、『プラカーシュ』って」と前振りを置いた。結びの「孫が隣に座るのを」は「空いていた隣に孫が座るのを」にして、空いた席の意味を変えた）

### 2.5 登場と退場

**人の紹介。** 初めて出る人は「役割＋名前」を一度言います（「孫のアマン」「宿の娘」）。名前より役割の方が覚えやすいので、役割を先に言ってもかまいません。別の場面をはさんだ後や、長く出番がなかった後は、役割をもう一度だけ添えます。

例（アーグラのフィナーレ。1回目）：語り手が、なぜこの老人を知っているのかが分からなかった。

- 前：「アンワル。この町で一番泣かせるガイド、とホテルの支配人が言っていた。支配人の叔父なのだそうだ。」
- 後：「アンワルだ、とツアーの客らしい男が連れにささやいた。この町で一番泣かせるガイドだよ、と。」／「名刺にあった名前だ。宿の支配人のサミールが薦めていた、あの叔父。」（到着の名刺にも「叔父アンワルは、アーグラ一のガイドです。」と名前を入れた）

**舞台に立つ人。** 絵のある人は、その人の最初の台詞の行から立ちます（クイズの相手は場面の最初から）。登場の札はありません。去った人は、札を書かないと立ったままです。

- 去る行に `# leave: <人物ID>` を書く。例（ジャイプールのエピローグ。2回目）：「…笑い声と一緒に、桃色の町の角へ消えていった。」の行に `# leave: enemy`（この場面の `enemy` は `# person:` のカムラ）。前は、去ったはずのカムラが、場面の終わりまで9行立ったままで、その中には二人だけの結びもあった。
- 画面の外の声は、その人の台詞の行に `# leave:` を書くと、舞台の外から話す。例（2回目）：電話の宿の主人、暗いショーの中のカムラ（光が当たる行の後で、初めて絵が立つ）。
- ヒロインが去る所は、`# stand: apart` で代えずに `# leave: heroine`。例（ロータス寺院。2回目）：「…こちらを振り返らずに出口へ歩きだした。」
- 二人が交互に話す場面（父と息子など）は、`# together:` で向かいに二人並べられる（例：グル・カ・タールの父と息子）。三人まで並べられる（例：ハワー・マハルの都市フィナーレのカムラ・プージャー・花嫁の祖母）。
- 三人目・群衆の反応は絵に出ない。後の台詞が前提にしている反応（拍手、ざわめき）は、地の文に書く。

### 2.6 ト書き（地の文）の過不足

ユーザーの注文（2026-11-15）は「過小ト書」「過剰ト書」にならないこと、「不足も過剰もダメ」でした。過小ト書は、ドラマに必要な人物・関係・小道具・リアクションを書き忘れること（新井一『シナリオの基礎技術』。本そのものではなく、シナリオ・センターの記事の引用で確かめた）、過剰ト書は書きすぎです。

地の文の一行ごとに、三つ問います。

1. 絵（背景・立ち絵の表情・立ち位置）、声、品物や紙の札、図鑑の小窓が、もう伝えていないか → 伝えていれば削る（過剰）。
2. この行がないと、初めての人は何かを取り違えるか、思い描けないか（誰がいる・何を持つ・どこへ動いた・誰が反応した・時間が経った）→ なら残す・足す（過小）。
3. 抽象語（くつろぐ・悲しむ・驚く・落ち着かない・しばらくして・やがて）だけか → 見える動作一つか、時刻・明るさ・人の様子の変化一つに替える。

この作品ならではの決まり：

- **札は外れても筋が通るように。** 効果音は設定でオフにしたときと高速送りで鳴らず、揺れは動きを減らす設定で揺れず、`# pause:` は一括表示と高速送りで消えます。だから、音と同じことを地の文が言うのは「保険」で、重複ではありません（削らず、短くするだけ）。本当の過剰は、必ず見えるもの（立ち絵の表情、品物・紙の札、図鑑の小窓）と同じことを地の文が言うときです。
- **今、表情を変えられるのはヒロインだけ。** ほかの人物の絵は、インド編ではどれも一枚です。ほかの人の顔・身ぶりは地の文にしか書けません。ここを削ると過小になります。
- **地の文が彼女の顔を書く行には、顔の札を付ける。** 札がないと、その行の立ち絵はふつうの顔に戻ります。例（ロータス寺院。2回目）：「…彼女は真っ赤になってうつむき、それきり、こちらを見なかった。」の行に `# emotion: shy_deep`。
- **効果音は、行の字が出始めるときに鳴る。** 音の出来事が行の二文目にあると、音が先に鳴ります。音の出来事を別の行に分けて、そこに `# se:` を付けます。例（レッド・フォート。2回目）：「ソーヌーはそう叫んで、城壁に向かって演説の真似を始めた。手振りが大きすぎて、土産物屋の棚の鈴が一斉に鳴った。」を二行に分け、鈴の行に `# se: shop_bells`。
- **漫符は、声と台詞が言っていない気持ちにだけ。** 明るい台詞の♪、照れた台詞の赤面のように、顔と同じことを言う漫符は、`# reaction: heroine,<顔>,<漫符>` を `# emotion: <同じ顔>` に替えます（顔は同じで、漫符だけ消える。録り直しは要らない）。例（インド門。2回目）：`# reaction: heroine,happy,music` → `# emotion: happy`。

過剰の例（どれも2回目）：

- 写真が見せる物を数えるだけ（ロータス寺院）：「芝生の向こうに、白い花びらを重ねた建物が浮かんでいた。大理石の花びらは二十七枚。三枚ずつ組になって、九つの面をつくっている。」→「芝生の向こうに、白い大理石の花びらを重ねた建物が浮かんでいた。」
- 心の解説（シティ・パレス）：「本当の理由は、同僚の目ではなかった。{heroine_name}は少し考えてから、口を開いた。」→「{heroine_name}は少し考えてから、口を開いた。」（次の台詞が見せる）
- 「〜という顔だった」（シティ・パレス）：「息子が、遠くへ行ってしまうことを、今さら思い知った顔だった。」→「それから、隣に立つ息子を、黙って見上げた。」
- 図鑑の小窓と同じ定義（イティマード廟。`# term: gt_term_jali` の行）：「窓には、石を透かし彫りにした格子がはまっていた。」→「窓には、石の格子がはまっていた。」

**削る前に、その行が運んでいる事実を一つ書き出します。** 削った後も、その事実が画面のどこか（絵・声・台詞・物・札）に残っているか確かめ、なければ削りません。前の改稿で分かりやすさのために足した行を「説明だから」と消すと、前の直しが元に戻ります。消すなら、同じ事実を別の運び方で残します。

### 2.7 説明を行動・物・台詞で運ぶ

ユーザーの言葉（2026-11-15）：

> 理想的な小説の表現は、巧みな「描写」をしているうちに、必要な「情報」も読者に伝えていること。これはシナリオも同じですね。
> つまらないシナリオの典型は、シーンで男女が向かい合ったまま長い会話をしている。もっとひどいのではナレーションでだらだらと述べる。

この言葉の元は、柏田道夫『シナリオ技術（スキル）で小説を書こう！』です（シナリオ・センターの記事が紹介している）。同じ記事は「説明はしなくてはいけない」とも書いています。教えは「説明するな」ではなく、**描写しているうちに説明も済んでいるようにせよ**、です。

運び方は、上から順に試します。

1. **用のある人に言わせる。** 売り子の口上、案内人の自慢、係員の注意。その人の目的・商売・心配の中で事実が出ると、説明に聞こえません。知っている者どうしで説明し合う「ご存じのとおり」型にはしない。旅の新顔の二人に町の人が教えるのは自然です。
2. **画面の物で読ませる。** 書かれた文は `# letter:`、品物の紙は `# item_out:`、メッセージは `# phone:`。見せたら、地の文で読み直さない。
3. **ヒロインの問いにする。** 彼女は旅の新顔なので、問う側に立つのが自然です。答えは町の人か紙が出す（新しい台詞は録音が要るので、今ある問いの台詞を生かす）。
4. それでも地の文に残すなら、主人公の目に入った物から、一行に一つの事実。

例（どれも2回目）：

- ロータス寺院：「…いちばん大事な決まりは一つ。話さないこと。」→「最後に彼は、唇の前に人さし指を一本立てた。」（録音済みの「しゃべっちゃだめなんだ」が、その仕草に答える形になった）
- レッド・フォートのフィナーレ：「混乱した老人ではなく、自分の足で出かけた人。そう思い直すまでに、少し時間がかかった。」→「アマンは携帯を、ゆっくりポケットに戻した。」
- シティ・パレス：「…青年の手には、荷物の重さを測る小さな秤。女性の手提げからは、ガラス瓶がのぞいている。」→「青年が女性の手提げを荷物用の秤に吊るすと、中の瓶が鳴り、針が大きく振れた。」
- ジャイプール到着：地の文の要約「…封筒に入れた現金がふつうで、金額の最後に一ルピーを足す。割り切れない数は、縁起がいいから。」→ フロントの女性の台詞「お祝いはね、封筒に入れた現金。金額の最後に、一ルピー足すの。割り切れない数は、縁起がいいから」
- イティマード廟：「{heroine_name}は新しい紙に、短く書いた。この墓は、娘が両親のために建てた。タージ・マハルより先に。その下に、自分の名前と国名を。」→ 地の文「{heroine_name}は新しい紙に短く書き、下に自分の名前と国名を添えた。」と、`# letter: card`「この墓は、娘が両親のために建てた。タージ・マハルより先に。」

**会話を動かす。** 向かい合ったまま台詞が8行ほど続き、動き・物・人の出入りがない所には、一か所に一つだけ、動かす物を入れます：用事（手の仕事）、物（渡す・見せる・紙・携帯）、距離（`# stand:`・`# leave:`）、第三者の割り込み、場所の移動、周りの出来事。新しい出来事を作るより、場面にもうある物を動かします（例：シティ・パレスの秤、宿題のノートと鉛筆、チャイのカップ）。

**過去は、今の物・今の場所・人の今の目的の中で。** 遊ぶ人が見た場面を地の文で語り直すのは、文章で書いた「安易な回想」です。一行の呼び返しで足ります。例（2回目）：品物の札 `# item_out: gt_delhi_kamla_memo` がもう出ている行で、「デリーに着いた日に、カムラが書いてくれた見どころの一覧。五行の場所と、一行ずつの妙な注釈。…」→「アマンは切れ端を受け取り、祖母の字を読み進めるほど、顔をこわばらせた。」。同じメモを品物の札と `# letter:` の二枚で続けて見せていた所も、品物の札一枚にまとめました。

**やりすぎない。** 動きの行が埋め草になっていないか、タップが増えすぎないかを見ます。2回目の診断の点検では「到着のノートの三行を紙の札にする」案を採りませんでした。今の一行で取り違えは起きず、紙にすると1タップが3タップになるからです。

### 2.8 名札：「旅の風景」のまま人が話していないか

地の文と、名前のない声には、名札「旅の風景」が出ます。人の言葉を地の文の中に入れたり、地の文が言い換えたりすると、その人が話しているのに名札は「旅の風景」になります。誰の言葉かが一瞬ずれ、人物の声も弱くなります。

- 例（アーグラ到着。2026-11-14）：「皆さん、最初はそうおっしゃいます。三回説明して、三回とも笑顔で流された。…」（旅の風景）→ `# speaker: gt_samir`「皆さん、最初はそうおっしゃいます」と、地の文「三回説明して、三回とも笑顔で流された。…」に分けた。
- 例（シティ・パレス。2026-11-16）：「ヴィシャールが小声で言う。向こうで新しい同僚に、漬物の匂いのする部屋だと思われたくない。最初くらい、身軽に始めたいのだと。」→「ヴィシャールが小声で言った。」と、`# speaker: gt_vishal`「向こうの新しい同僚に、漬物の匂いのする部屋だと思われたくないんです。最初くらい、身軽に始めたくて」。
- 探し方：地の文の行のうち、「」を含む行、言い換え（「〜と。」「〜のだと。」）の行、「あなた」「あんた」を含む行を見る（2026-11-14 の点検で使った見方）。
- 地の文が短く伝える言葉（係員の「暗くなってから、ね」のような短い引用）は、地の文のままでかまいません（[CONTENT_GUIDE](CONTENT_GUIDE.md#inkで会話と演出を作る)）。
- 名前のない役（店主・運転手・フロントの女性）も、役名を名札にして話させられます（3章）。絵のない人は、名札だけ出て舞台に立ちません（「電話の声」）。
- その場にいない人の言葉が頭の中で聞こえる行は、回想の台詞の札で書きます（[CONTENT_GUIDE](CONTENT_GUIDE.md) を参照）。インド編では、タージ・マハルで思い出すカムラの「アーグラでも、言いたいことは言いなさい。」が「旅の風景」のままで、2026-11-16 に絵のない人物「カムラの声」の名札にしました。
- 地の文を台詞に移すと、絵のある人はその行から立ちます。その後で舞台から下ろす行が要るか見ます（例：フロントの女性に話させた後、「帳場を離れて、」の行に `# leave: gt_jaipur_hotel_front`）。

### 2.9 一行の長さ

会話の窓は、名札と3段分の大きさに固定です（2026-11-27のユーザー判断。台詞の量で窓の大きさは変わらず、4段目からは窓の中でスクロールします）。スマートフォンの縦の画面（幅390px）では1段がおよそ20字なので、一行は2段（40字ほど）を目安に、3段（60字ほど）を超えないように書きます。それより長い行は、文の切れ目で2段ずつほどに分けます（ユーザー判断：「長文を読ませるゲームじゃない」。2026-11-27に、4段以上になっていた294行を分けた）。一行に新しい事実は一つにします。

- 分けたら、札は出来事のある側に残す（効果音は鳴る側、`# term:` はその語のある側、`# pause:` は間を置く側）。新しい行には、自分の `# speaker:` を書く（札はすぐ下の行のもの。次の行の札を奪わない）。
- 例（デリー到着。1回目）：カムラの一覧を読み上げる一行（92字）「わたしのデリー。赤い城、暗くなってから。クトゥブ・ミナール、鉄の柱、もう抱けない、腹立たしい。フマユーン廟、東の門から三本目の木陰。ジャーマー・マスジド、朝のニハーリー、階段の下の店。」を、二つの台詞に分けた。
- **分けると意味が変わることがある。** 引用や主張を独り立ちの行にすると、語り手の言い切りに読めることがある（2.11 のイティマード廟の例）。
- ヒロインの長い台詞を分けると、分けた行は新しい録音になります（4章）。2026-11-15 に渡した追加の台本には、長い台詞を分けた行が30行入りました。2026-11-27 に分けた行で外した声は [voice/SPLIT_LINES_2026-11-27.md](journeys/golden_triangle/voice/SPLIT_LINES_2026-11-27.md) に一覧があります。

### 2.10 呼び名と表記のゆれ

同じ物・人・場所は、同じ呼び名で書きます。呼び名が変わると、読む人は別の物だと思います。新しい名前が出たら、前に見た物とつなぐ一言を添えます。

- 例（レッド・フォート。1回目）：「録音の声」を「録音の語り」と言い直した後は、その場面の終わりまで「録音の語り」で通した（「録音の語りが途切れた。」）。
- 例（同じ場面）：「内謁の間」は、本筋では「白い大理石の広間」としか出ていなかった。「光が、内謁の間の白いアーチを照らし出した。遠足の子が指さした『楽園』の広間だ。」と、前に見た広間につないだ。
- 例（アーグラ。1回目）：「帰りぎわ、アンワルは甥の支配人に電話をかけ」→「甥のサミールに電話をかけ」。役割の呼び方（支配人・甥・宿の主人）が名前とつながるようにした。
- 地名は、Ink だけでなく、地図・背景の名前（`romance/presentation.json`）・観光の画像の説明（`tourism/catalog.json` の `altJa`）にも出ます。1回目では「ラム・バーグ」「チーニー・カ・ラウザ」を「ラーム・バーグ」「チーニー・カ・ラウザー」に、Ink・地図・背景の名前でそろえ、見直しで残りが見つかった観光の画像の説明もそろえました。
- 大事な言葉を別の場面で呼び返すときは、字までそろえる（デリーの別れの「アーグラでも、言いたいことは言いなさい」を、アーグラのフィナーレで同じ文で思い出す）。
- 都市をまたぐ食い違いも見る（1章のサミールの誤解の例）。

### 2.11 事実・伝説・解釈の区別

AGENTS.md の「観光と学習」のとおり、確かめた史実と、解釈・伝説を分け、出典を作りません。

- 足す事実は、リポジトリにあるもの（シナリオ、クイズの出典、用語集、観光データ、調査の記録）から取る。何から取ったかを報告に書く。見つからないものは、作らずに「未確認」と書く（例：1回目の見直しでは、ショーの語りが録音であることはクイズの出典に書いていない、と記録した）。
- 伝説は、伝説の言い方で書く。例（アーグラのフィナーレ）：「切られたと語られてきた手は、切られずに、次の都を建てに行ったと伝わる。」
- **地の文は語り手の声なので、地の文に置いた文は事実に読める。** 例（イティマード廟）：請願書の三つ目の主張「この墓を建てた皇妃ヌール・ジャハーンは、タージ・マハルの設計にも関わった」は、クイズで「史実で支えられない」とされる、盛った主張です。1回目に長い行を分けたとき、この文が名札「旅の風景」の一タップとして独り立ちし、語り手の言い切りに読めると、見直しで分かりました。まず『』で請願書の文にし、2回目に `# letter: note` で紙の文として見せました。
- 細かな言い方も事実に合わせる。例（1回目）：カムラが見たのは前の公演で、今の公演とは別なので、「このショー」ではなく「ここのショー」と書いた。
- 主人公の目と耳に届かないこと（ほかの人の来歴や胸の内）を、地の文で言い切らない。人物の言葉や仕草から推す形にする。

## 4. 守ること

どれも理由のある決まりです。迷ったら、理由に照らして判断します。

### ヒロインの台詞と声

ヒロインの台詞は、声を録音済みか、発注済みです（記録は `authoring/journeys/<旅行編ID>/voice/` の日付のフォルダと `recorded.json`）。文を一字でも変えると、録り直しか追加の発注になります。

- **必要なら変えてよい。ただし、全面的な録り直しにはしない**（2026-11-15 のユーザーの判断：「もちろん必要ならやるべきです。ただし全面的に新規録音する方向性はNGということ」）。1回目にもユーザーは「そういうときは、絶対に変えた方がいいです！」と言っています。
- 変える順番：まず地の文・ほかの人物の台詞・札・物で直す。それでも、次のどれかに当たるときだけ、彼女の台詞を変える。
  - 彼女の台詞そのものが混乱の元（見ていない物・人・約束を指す、直した後の場面と食い違う）。
  - その事実は彼女しか言えない（彼女の気持ち、彼女が決めたこと、彼女だけが気づいたこと）。
  - ほかの道具だと場面が壊れる（二つの台詞の間に行を挟むと間が切れる、ほかの人に言わせると「ご存じのとおり」になる）。
- 言い回しが好みでない、少し長い、もっと良く書ける、は理由になりません。
- 例（ジャーマー・マスジド。1回目に変えた、録音済みの1行）：「……今、お昼過ぎ。完全に出遅れた」→「……朝ごはんの時間、もう過ぎちゃった。完全に出遅れた」。9時から入れるので、朝に来た人には上の帯の時計と食い違う。時刻を言っているのが彼女の台詞なので、地の文では打ち消せない。表情の札も同じで、同じ演技で録り直せる。
- 例（変えずに済ませた）：デリー到着の彼女の「地図というより暗号だね」はそのまま、カムラの台詞を「わたしのデリーの地図だよ」にして受けた。
- 変えるときは最小に：語を一つ替える、指す物を言い直す。長さと表情の札は、なるべく元のまま。
- 変えた台詞は、全部一覧にする：ファイルと行、声の ID、録音済みか発注済みか、前 → 後、ほかの道具で足りない理由。
- `npm run voice:changes -- --journey <旅行編ID>` で、録り直しの要る行と、台本から変わった行を確かめる。一覧にない変更が出たら、それは意図しない変更です。
- `# voice:` は手で書き換えない。録音済みの行の文を変えても、`# voice:` はそのままにします（`content:build` の注意と `voice:changes` が録り直しを知らせる。作り直した声が届いたら `voice:tag` で記録する。流れは [CONTENT_GUIDE の「台詞の声の台本」](CONTENT_GUIDE.md#台詞の声の台本と台詞が変わったときの確認2026-11-13)）。**新しく足した台詞には、声が届くまで `# voice:` を書かない**（届いたら `voice:tag` が書く）。
- 顔の札：`# reaction:` を同じ表情の `# emotion:` に替える（漫符だけ消す）のは録り直し不要。表情そのものを別の表情に替えない（声の演技と食い違う）。
- 彼女の台詞の前の行を変えたら、録音済みの演技（驚き・笑い）が、変えた前の行にまだ合うか見る。台詞の並びと演技の指示は、渡した台本（`voice/<日付>/` の `*_heroine_lines.txt`）にあります。
- 彼女の台詞に触れる前に、[キャラクターバイブル](../docs/09_HEROINE_CHARACTER_BIBLE.md) を読む（AGENTS.md）。一人称は「わたし」、問う側に立つ、大切な話では短く率直に、「……」を毎回の頭に付けない、主人公を褒める係・操作を促す係にしない。

### 文と表記

- 一行は2段（40字ほど）を目安に、3段（60字ほど）まで。長い行は分ける（2.9）。
- 名前は `{player_name}`・`{heroine_name}`・`{player_address}` のまま。名前をベタ書きしない（遊ぶ人が決める名前だから）。名前の入る行には声を付けられません。
- 主人公は台詞を話しません（インド編の設計の決まり。[SCENARIO_REWRITE](journeys/golden_triangle/drafts/SCENARIO_REWRITE.md) の「面白さの条件」の6）。全部の旅行編の決まり（AGENTS.md）にはしません。主人公に台詞を言わせるかどうかは、旅行編ごとに書く人が決めます（2026-11-16のユーザー判断）。主人公の言葉は、遊ぶ人が選ぶ選択肢（言う言葉は「」で囲む）で、地の文では「こちら」と書きます。2回目の後には、主人公が日本語で話していた一行（ファテープル・シークリーのツアーの帰り）を、ユーザーの了解を得てヒロインの台詞に移しました。ほかの編で主人公の台詞（`# speaker: player`）を見つけたら（まだ改稿していないミラノ編にはある）、直す前に書く人に聞きます。
- クイズは「クイズ」（矛盾追及・証拠連結は「推理クイズ」）、クイズの人は「相手」と呼び、勝ち・負け・勝利・敗北の言葉を使わない（2026-11-11 のユーザー判断）。クイズの場面では「負けじと」のような言い回しも避けます（1回目の見直しで見つかった）。
- 台詞は「」で囲まない（名札が話し手を示す）。

### 事実

- 事実は確かめたものだけ。出典・確認日を作らない（AGENTS.md の「観光と学習」、2.11）。
- クイズの答えを先に言わない（2.2）。

### 触らない札と行

次は、話の骨組みと保存にかかわるので、編集者は変えません。変えたいときは、書く人かユーザーに聞きます。

- アルバムの `# photo:`（と `# photo_caption:`・`# photo_show:`）。絵はその行の瞬間のために描かれ、アルバムに入る時もその行で決まる。行を分けるときは、その瞬間の側に残す。
- `# voice:`（上の決まり）、`# on_done:`、頭の `when:`・`then:`、選択肢の効果の札（`# option:`・`# set:`・`# rel:` など）、`cond(...)`、knot の名前、`# minigame:` の行。
- 今ある `# recall:` の絵（選んだのは書く人）。
- 選択肢の文を直すなら、札と行き先はそのまま。何を選ぶのかが変わるなら、書く人に聞く。

## 5. 進め方とチェックリスト

### 5.1 流れ

```text
書く人（初稿。content:build が通る）
  → 編集者：診断 → 診断の点検 → 直し → 二人目の読み
  → 検査（5.3）
  → 決めてほしいことを、書く人・ユーザーに出す
```

1. **診断**：場面ごとに「初見の人に伝わること」「作者の意図」「伝わっていないこと」を書き、指摘を並べる。指摘には、ファイルと行、2章のどの点か、読む人の心の声（「この人、誰？」）、直す案（Ink の形で）、どれくらい迷うか（大・中・小）を書く。「直す所なし」の場面も書く。
2. **診断の点検**：別の人が、指摘ごとに「採用」「直し方を変えて採用」「不採用」を決める。直しすぎ（事実が消える、声が平らになる、埋め草の動き、良い場面への手入れ、好みのための録り直し）と、見落としを探す。
3. **直し**：採用した指摘だけを直す。報告に、変えた所（ファイルと行、前 → 後、理由）、ヒロインの台詞の一覧、足した事実の元、決めてほしいことを書く。
4. **二人目の読み**：直しに関わっていない人が、変えた場面を最初の行から、すべての道で読む。直した人の報告は、自分の判断を固めてから読む（結論を借りないため）。変えた所ごとに「良くなった」「同じ」「悪くなった」を付け、まだ弱い所を挙げる。

なぜ二人目が要るのか：直した人も、診断のメモを読んだ後は意図を知っています。知識の呪いは編集者にもかかります。

AI が編集者を務めるときは、都市や場面のまとまりごとに分けて診断し、診断の点検と二人目の読みは、別の会話（別のエージェント）に任せます。インド編の2回は、どちらもこの形で行いました。

### 5.2 読み物を用意する

- **場面の並び**：`npm run content:build` の後に、`npm run journey:readthrough -- --journey <旅行編ID>` を実行します（何も検査しない読み物）。ファイルに書き出すと読みやすくなります（例：`mkdir -p artifacts && npm run --silent journey:readthrough -- --journey <旅行編ID> > artifacts/readthrough-<旅行編ID>.txt`。`artifacts/` は Git に入りません）。インド編の2回の改稿で使った `gt_readthrough.txt` は、この出力です（`--journey golden_triangle`）。
  - 入っているもの：観光地の訪問ごと・時点ごと（デート・フィナーレ・エピローグ・宿・出発・ツアーなど）の場面の並び（`when:`・`then:` つき）と、`# at:` で置いた場面（道中交流・差し込みの場面・ツアーの語りなど）の行を、選択肢と `cond(...)` の道ごとに。話し手は ID で出ます（地の文は印なし。名札の名前ではありません）。1場面の道の数は `--max-paths N`（ふだんは12）。
  - 入っていないもの：観光案内・クイズの会話・デート・フィナーレ・到着・エピローグの行は、並びに名前が出るだけです。これらは場所のファイル（`content/journeys/<旅行編ID>/stories/places/*.ink`）を読むか、Debug で開いて読みます。
- **ヒロインの台詞を前後の行と一緒に**：`npm run voice:script -- --journey <旅行編ID>` が、台詞ごとに前の行・分かれ道・表情・演出を付けた `artifacts/voice/<旅行編ID>/heroine_lines.txt` を書きます。
- **一行の字数や札の数**を数える道具は、リポジトリにありません。インド編の2回は、使い捨てのスクリプトで数えました（リポジトリには入れていません）。要るときは、その都度作ります。
- **遊ぶ人と同じ画面で**：Debug 起動URL で場面を直接開きます（例 `/?debug&city=<都市ID>&scene=battle&target=<バトルID>&progress=initial`。[Debug起動URL](../docs/10_DEVELOPMENT_CHECKS.md#debug起動url)）。スマートフォンの幅（390×844 など）で、効果音をオフにしても、高速送りでも、字だけで筋が分かるか読みます。

### 5.3 検査

- `npm run content:build`：直す前と後に実行し、注意（警告）の数と中身を比べる。新しい注意には理由を言えるようにする。全部の道を歩く検査（scene walk）は、その行で舞台にいない人を下ろす `# leave:` などを注意に出します。
- `npm run voice:changes -- --journey <旅行編ID>`：出てくるのが、一覧にした台詞の変更だけか。
- 触らない札が変わっていないか、差分で確かめる。次のコマンドが出す行が、意図して変えた行だけなら合格です（何も出なければ、触っていない。コミットした後なら `git diff -U0 <直す前のコミット> -- …` で同じように見る）：

  ```sh
  git diff -U0 -- content/journeys/<旅行編ID>/stories \
    | grep -E '^[-+]([^-+]|$)' \
    | grep -E '# *(voice|photo|photo_caption|photo_show|recall|on_done|when|then):|cond\(|^[-+] *[*+] |^[-+]==='
  ```

- 台本の点検を助けるコマンドが3つあります。どれも必要なときに走らせるもので、`content:build` には入っていません。注意を出すだけで、ファイルは変えません。直すかどうかは書く人が決めます。`npm run text:check -- --journey <旅行編ID>` は、「旅の風景」の名札のまま人が話していそうな行（2.8）、名札の出ない声、用語の台帳（`authoring/journeys/<旅行編ID>/terms.json`。決めた言葉だけを、決めた資料の名前と一緒に書く）で避ける言い方を出します（勝ち負けの言葉は見ません。問題になった所は直してあり、今の使い方は使ってよいものだという、2026-11-16 のユーザー判断です）。`npm run content:unused` は、どこからも届かない knot と、場面に届かないデータを出します。`npm run sources:check` は、同じ URL に違う題が付いた出典などを出します（`-- --fetch` で、ページの題とも比べます）。
- その旅行編の単体テストがあれば実行する（インド編は、`content:build` の後に `npx vitest run tests/journeys/golden_triangle`。選択肢・フラグ・場面のつながり・予算を確かめる）。選択肢や条件を書く人と決めて変えたときは、`npm run test:walk` も。
- 最後に、変えた場面を、遊ぶ人と同じ画面で、すべての道で読む（5.2）。

### 5.4 チェックリスト

場面ごとに、上から順に確かめます。

- [ ] 意図の資料を閉じて、画面に出る行だけで読んだ（2.1）
- [ ] 分からない所を、謎（残す）と混乱（直す）に分けた。クイズの答えを先に言っていない（2.2）
- [ ] 前振りは必ず通る場面にある。説明が、分かれ道の片方だけにない（2.3）
- [ ] 場面の頭と、背景が変わった直後で、誰が・どこで・いつ・何のためにが分かる。誰に話しているかが分かる（2.4）
- [ ] 初めての人は役割＋名前で出る。去った人は舞台から下りる。画面の外の声は舞台の外から話す（2.5）
- [ ] 地の文の一行ごとに三つの問いをした。彼女の顔を書く地の文に顔の札がある。音は出来事の行で鳴る（2.6）
- [ ] 削った行の事実が、画面のどこかに残っている（2.6）
- [ ] 説明は、用のある人・物・彼女の問いで運んでいる。向かい合ったままの長い会話がない（2.7）
- [ ] 人の言葉が「旅の風景」の名札で出ていない（2.8）
- [ ] 一行は60字ほどまで。分けた行の札は出来事の側にある（2.9）
- [ ] 同じ物・人・場所は同じ呼び名。地名は Ink の外のデータともそろっている（2.10）
- [ ] 足した事実の元を書いた。伝説は伝説の言い方。地の文が主張を言い切っていない（2.11）
- [ ] ヒロインの台詞の変更は一覧と一致し、`voice:changes` に一覧にない変更がない（4章）
- [ ] 触らない札が変わっていない。`content:build` が通り、新しい注意に理由がある（5.3）
- [ ] 話の事実を変えたくなった所は、案をつけて書く人かユーザーに出した（1章）
- [ ] 良い場面には手を入れていない
